    Extensions¶

    An extension adds a research feature to any agent whose loop folds the phases it uses. The user guide shows how to use them and Writing an extension how to add one.

    ajax.extensions.base ¶

    The Extension framework — composable research features for any agent.

    An :class:Extension is a research feature (expert guidance, observation augmentation, online behavioural cloning, target modifiers, exploration schemes, instrumentation, …) that attaches to any agent without bloating the agent's own file. It implements only the lifecycle phases it touches; an agent's training loop folds every extension through each phase, in list order.

    Design contract¶

    • Static. Extensions are plain Python objects passed as static arguments to the jitted training step, so the fold unrolls at trace time (a Python for over a fixed tuple — no dynamic dispatch). Every extension must therefore be hashable: the default id-based hash is fine for a one-off instance; a @dataclass(frozen=True) is preferred for instances carrying config, so the JIT cache is reused across equivalent runs.
    • State lives in the pytree. An extension never stores mutable state on self — only frozen config. Anything that changes during training is a pytree returned by :meth:Extension.init_state and carried in BaseAgentState.ext_state (one entry per extension; the default () means stateless, zero overhead).
    • No-op by default. Every phase method has a default that is the identity / 0.0 / {} / unchanged-state, so an extension is exactly as invasive as the phases it overrides, and an empty :class:ExtensionStack is genuinely zero-cost.

    Phases¶

    init_state build the extension's pytree state (once, on fresh init) pretrain one-shot, before the training loop (MC/BC pre-training) on_target transform the TD / value target critic_loss extra additive critic-loss term (summed over extensions) actor_loss extra additive actor-loss term (summed over extensions) action override the collection-time action (None = defer; the last non-None proposal in the stack wins) eval_action override the evaluation-time action (same rule) transform_action make the executed action a function of the policy's and the expert's (residual RL), in collection, the losses and evaluation post_update hook after the update step (φ-refresh, schedules, …) eval_metrics extra metrics, merged into the eval log

    on_target, critic_loss and actor_loss may return (value, metrics) instead of their value: metrics, a dict of scalars named <extension>/<metric>, is logged with the update's own metrics (the last update's, or the mean over the update's epochs and minibatches, as the agent logs its own). Two extensions logging one name raise.

    Phase batches¶

    The batch dict of a phase holds the keys :data:PHASE_BATCH_KEYS lists on every agent that folds it; an agent may add its own (read its fold call), and an extension raises on a key it needs and does not find, rather than return a no-op. gamma is None for an average-reward agent, dones is where the target cut the bootstrap and targets the target, held constant; the critic (DQN's and PQN's q_state) and the actor come at the differentiated parameters. The replay agents' raw_observations is None in a run without an expert, whose replay does not keep them. a_expert is the agent's expert_policy's action at each row, stored at collection from the expert's state along the trajectory; None without one.

    ExtensionContext ¶

    Shared context handed to every extension phase.

    step and rng are traced; total_steps is static so it can drive Python-level decisions (e.g. schedule lengths) at trace time. The pretrain phase of a run on ajax.agents.loop.TrainLoop also gets its static env_args and, off-policy, its update(agent_state, experience) -> (agent_state, aux) and replay buffer, so an extension can run the agent's own update; each is None where the run has none.

    Extension ¶

    Base class for a composable research feature.

    Subclass and override only the phases the feature touches. Keep subclasses hashable (@dataclass(frozen=True) is the recommended form) and stateless on self — see the module docstring.

    ajax.extensions.expert ¶

    Expert-guidance research features as composable :class:Extensions.

    • :class:OnlineBC — value-weighted decaying BC loss term.
    • :class:ImitationLoss — plain BC loss term towards the expert.
    • :class:ResidualPolicy — execute clip(a_expert + scale·a_pi).
    • :class:JSRLCurriculum — per-episode expert→learner handoff.
    • :class:ExpertValueMetrics — the critic at the expert's actions, logged.

    Each extension carries only frozen config on self; the maths are the functions below. The expert is SAC's expert_policy: OnlineBC, ResidualPolicy and JSRLCurriculum read the expert action SAC computes. ImitationLoss holds its own expert, and reads the actions the agent stored when that expert is the agent's.

    OnlineBC dataclass ¶

    OnlineBC(
    bc_coef=1.0, critic_warmup_frac=0.15, name="online_bc"
)

    Bases: Extension

    Online, value-weighted, warmup-decaying behavioural-cloning term.

    A bc_coef · w(s) · ||μ_θ(s) - a_expert||² penalty (:func:compute_online_bc_loss) that decays to zero once the training fraction exceeds critic_warmup_frac. It reads the actor's mean action (pi_mean), the expert's action (a_expert, which SAC puts in its actor-loss batch) and the observations from the batch, and the frozen expert critic phi with its value range (expert_critic_params, expert_v_min, expert_v_max) and the critic phi is applied with from the agent's state, which :class:MCPretrain fits (refused without it). The expert's action is the agent's expert_policy's, so an agent without one refuses it (requires agent_expert); it raises on a batch without a_expert (an agent other than SAC). Until phi* exists the term is 0.

    ImitationLoss dataclass ¶

    ImitationLoss(
    expert_policy,
    coef=1.0,
    q_filter=False,
    anneal_frac=None,
    target="expert",
    alpha=None,
    reads_stored_expert=False,
    buffer=None,
    action_scale=None,
    augment_obs_with_expert_action=False,
    name="imitation_loss",
)

    Bases: Extension

    Behavioural-cloning regulariser: coef · mean((μ(s) - a_E(s))²) / 4.

    Same form as the actor-side BC term of TD3+BC (Fujimoto & Gu, 2021), with a frozen expert's action as the target: μ(s) is the actor's mean action (pi.mean(), which is TD3's deterministic action), a_E(s) the expert's action, held constant: its call on the raw observation, or, when it is the agent's expert_policy, the action collection stored from its tracked state (which a stateful expert, a PID with its integral, needs). The mean runs over batch and action dims; / 4 maps the squared distance of two actions in [-1, 1] to [0, 1]. Unlike :class:OnlineBC the term is unweighted and needs no pre-trained expert critic.

    q_filter=True counts only the rows where the critic rates the expert's action above the policy's (:func:q_filter_weight, at μ(s)) and still divides by every row, as the paper's fixed λ2 = 1/N_D does: the Q-filtered BC of Nair, McGrew, Andrychowicz, Zaremba and Abbeel (ICRA 2018, Sec. IV-C, eq. 8). Deviations: replay rows labelled with the expert's action, not a demonstration buffer (the replay's expert flags would restore it); coef on the BC term, not the paper's λ1 = 1e-3 on the RL term and λ2; the policy's mean action and the minimum over the agent's critics (TD3's actor reads its first, REDQ's the mean of its ensemble), not DDPG's one critic. The filter needs a Q critic, which SAC, TD3, REDQ, ASAC and AVG put in their actor-loss batch (critic_state); a state-value critic (PPO, APO) cannot rate an action. It refuses :class:ResidualPolicy, whose critic reads the executed action. imitation/q_filter_frac logs, at each evaluation, the share of a replay batch the filter keeps (every agent but AVG, which keeps no replay).

    With anneal_frac the term is multiplied by a weight falling linearly from 1 to 0 at that fraction of training (:func:anneal_weight), as in kickstarting (Schmitt et al., 2018, Kickstarting Deep Reinforcement Learning, arXiv:1803.03835, eqs. 2-3), whose distillation weight on the teacher decays so the student ends on its own RL loss. Deviations from kickstarting: a squared error on the mean action instead of the cross-entropy between the teacher's and the student's policies (the expert is deterministic: it gives an action, not a distribution); a linear schedule set by anneal_frac instead of the weights population-based training tunes. None keeps the weight at 1.

    target="replay" clones the replayed rows' own actions (actions, which SAC, TD3, REDQ and ASAC put in their actor-loss batch) instead of an expert's: logged data needs no expert, and expert_policy may be None. alpha makes the actor loss TD3+BC's (Fujimoto and Gu, 2021), λ · (the agent's own) + coef · mean((μ(s) - a)²) with λ = alpha / mean|Q_1(s, μ(s))| (:func:td3bc_lambda), the actions compared in the env's units and without the / 4: the term adds (λ - 1) times the agent's own loss (agent_loss in its actor batch), already counted. On TD3, whose own loss is -mean Q_1, that is the paper's -λ mean Q + mean((π(s) - a)²); anneal_frac and the filter act on the cloning part only. With both, on TD3, a transition dataset trained offline (train_offline) and normalize_observations=True (the dataset's statistics, sqrt(var + 1e-8) in place of the reference's std + 1e-3), it is TD3+BC.

    TD3, REDQ, ASAC, APO, SAC and PPO put pi_mean and raw_observations in their actor-loss batch, and all but PPO (which takes no expert) the stored a_expert; an agent whose batch has no pi_mean (a discrete-action policy) raises at trace time.

    ResidualPolicy dataclass ¶

    ResidualPolicy(scale=1.0, name='residual_policy')

    Bases: Extension

    Residual RL (Johannink et al. 2019).

    The executed action is clip(a_expert + scale·a_pi, -1, 1): SAC's action pipeline applies :meth:transform_action at collection (its warmup samples uniformly), and the actor's policy gradient, the TD-target bootstrap and evaluation flow through the same transform. Its presence alone turns residual RL on, with SAC's expert policy; transform_action is a phase only SAC runs, so the other agents refuse it.

    over the critics and the batch, with a the row's action and the a_j n_actions uniform actions in [-1, 1]^A and n_actions of the policy at s and at s', all scored at s. It pushes the critic down on actions away from the data's and up on the data's. The reference sums each critic's Bellman loss and term; Ajax's critics share one mean squared error, so the term is the mean over them, at the same ratio. It needs a policy with a density: a deterministic one (TD3's) is a point mass, whose samples are copies of one action and whose density is undefined. Deviations from the reference's SAC: its target keeps SAC's entropy term (the reference's deterministic_backup drops it). Logs cql/term and cql/gap, the logsumexp minus the data's value.

    ajax.extensions.exploration ¶

    Exploration research features as composable :class:Extensions.

    EDGE (Expert Decayed Guided Exploration) substitutes the expert action for the policy action during collection, gated by a value comparison that decays over training. :class:EDGEExploration selects one of six gates with gate: "fixed" / "argmax" / "boltzmann" (value-gap gates) or "lcb" / "argmax_lcb" / "thompson" (quality-aware gates); the gate maths are the functions below.

    The SAC action pipeline pre-computes the per-step quantities every gate needs (policy_action, expert_action, observations, ...) and passes them through the obs argument as a dict, as the batch dict of the on_target / actor_loss phases. The extension picks an action (or returns None to defer); the pipeline owns the bookkeeping (is_expert_flag, buffer_action, expert-state threading). Gate randomness is threaded through obs["gate_rng"] (read and overwritten in place), the pipeline's own stream, not the framework's per-extension rng split (stack._keys).

    edge_lcb_gate ¶

    edge_lcb_gate(score_expert, score_policy, rng, temperature)

    Stochastic Boltzmann gate over LCB scores.

    p(use_expert) = sigmoid((score_e - score_p) / temperature).

    Hard threshold (argmax) creates a self-fulfilling expert preference: expert always wins → buffer all expert → critic never learns Q for policy actions → expert keeps winning. The stochastic version ensures policy occasionally gets sampled, breaking the inertia.

    Temperature → 0 recovers argmax; → ∞ recovers uniform mixing.

    edge_thompson_gate ¶

    edge_thompson_gate(
    mu_e,
    sigma_e,
    mu_p,
    sigma_p,
    rng,
    temperature=1.0,
    epsilon_floor=0.0,
)

    Thompson-sampling gate, with optional epsilon floor on policy picks.

    Treat each candidate's Q as Gaussian(mu, (temperature * sigma)^2), draw one sample per side, pick whichever is larger. Equivalent to p(use_expert) = Phi((mu_e - mu_p) / (T * sqrt(sigma_e^2 + sigma_p^2))) in expectation, but stochastic per-step (which is what we want for exploration: the gate itself injects noise rather than deferring to a fixed rule).

    Symmetric: high uncertainty on either side widens the gate, never biasing it. Confident estimates dominate. With both sigmas → 0 we recover deterministic argmax.

    epsilon_floor: with this probability, force the policy regardless of the Thompson outcome. Required when the expert dominates by many sigmas (Phi -> 1 -> Thompson never picks the policy -> the critic never sees policy actions in its updates -> Q for policy actions stays stale -> the gate can never flip even if the policy improves). Set carefully on brittle envs: too high crashes the agent, too low starves the policy of evaluation data. ~0.001-0.05 is a sane range.

    Ports the math from EVAREST loss.py / mechanism.make_evarest_decomposition_metrics. The residual is reconstructed from the agent's current critic on a measurement batch sampled the same way :class:ConditioningMetrics samples (replay buffer for off-policy, last_rollout for on-policy).

    EVarEst critic objective as a critic_loss extension.

    Ports the additive form of EVAREST's :func:make_evarest_loss / :func:make_evarest_ppo_loss / :func:make_evarest_td_loss. The agent's vanilla critic loss already contains MSE = bias^2 + Var(residual); this extension adds the eq. (6) extra penalty term:

    penalty(alpha) = ((1 - 2 alpha) / alpha) * Var(q_preds - target_q)

    so the total objective becomes MSE + ((1-2 alpha)/alpha) * Var(residual). alpha=0.5 ⇒ coeff 0 ⇒ identical to vanilla; alpha->0 is the AVEC limit (use a small alpha rather than zero). coeff_override lets callers fix the coefficient directly (e.g. to disable the extra penalty entirely without recomputing alpha).
