    DreamerV3¶

    DreamerV3 learns a model of the environment and trains its policy inside that model. A recurrent world model learns, from replayed sequences, to predict the next latent state, the reward and whether the episode continues. An actor and a critic then learn mostly from trajectories imagined by the model. All three are trained together, one gradient step per update, with the LaProp optimizer and adaptive gradient clipping.

    Paper: Hafner, Pasukonis, Ba and Lillicrap, Mastering Diverse Domains through World Models, arXiv:2301.04104v2, 2023; Nature, 2025 (arXiv:2301.04104v2). Official code: danijar/dreamerv3.

    Ajax reproduces the code that produced the paper's numbers (commit 2411f7d) plus one later upstream bug fix (29eb964, the replay context). The world-model design notes give the full specification, and deviations.md lists every version choice and every departure from the reference.

    Can I use?¶

    Feature DreamerV3
    Discrete actions yes
    Continuous actions yes
    Memory built in: the world model is recurrent (memory= is not accepted)
    Environments gymnax, Brax, MuJoCo Playground
    Observations flat vectors only; the environment must not normalise observations or rewards
    Several seeds in one call yes, train(seed=[...])
    Extension phases pretrain, post_update (after every update), eval_metrics, observe (the features join the observation the encoder reads and the decoder reconstructs)
    Resume and checkpoints yes; a resumed run continues the schedules and the replay, and equals the uninterrupted run (test)

    Example¶

    # doc: skip (compiles and trains for about a minute on a CPU; tests/agents/DreamerV3/test_dreamerv3_agent.py covers this path)
from ajax import DreamerV3
from ajax.logging import LoggingConfig

# The smallest preset and a low train ratio, for a quick look on a CPU.
agent = DreamerV3("CartPole-v1", model_size="1m", n_envs=4, train_ratio=32,
                  batch_size=4, batch_length=16)
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = agent.train(seed=0, n_timesteps=2_000, num_episode_test=2,
                                 logging_config=logging)
print(evaluations["Train/episodic mean reward"])  # the score the paper reports
print(evaluations["Eval/episodic mean reward"])

    The paper's DMC-proprio protocol (Table 2): the 12M model, 16 environments, a train ratio of 512, action repeat 2, and 500K environment frames, which is 250K rows at repeat 2:

    # doc: skip (the paper's full budget; benchmarks/world_models/paper_protocol.py runs it)
from ajax import DreamerV3

agent = DreamerV3("CheetahRun", model_size="12m", n_envs=16, train_ratio=512,
                  action_repeat=2, episode_length=1000)
state, _ = agent.train(seed=0, n_timesteps=250_000)  # 500K env frames

    Key hyperparameters¶

    Every default is the paper-era value.

    Argument Default What it does
    n_envs 16 environments stepped in parallel
    model_size "12m" preset of "1m", "12m", "25m", "50m", "100m", "200m", "400m"; sets units, deter, hidden, classes
    train_ratio 512 replayed steps trained per collected row
    batch_size, batch_length 16, 64 sequences per batch, and their length
    imag_horizon 15 imagined steps per start state
    return_horizon 333 1 / (1 - gamma): sets the discount
    lam 0.95 lambda of the imagined returns
    learning_rate 4e-5 a float or a schedule of the update count; a 1,000-update linear warmup multiplies it
    agc, eps 0.3, 1e-20 adaptive gradient clipping, LaProp's epsilon
    actent 3e-4 actor entropy scale
    free_nats 1.0 free bits of the KL losses
    dyn_scale, rep_scale 1.0, 0.1 dynamics and representation loss scales
    replay_capacity 5,000,000 rows kept, over all environments
    action_repeat, episode_length 1, 1000 simulator steps per agent step, and per episode (Brax, Playground)

    The other arguments (network depths, bins, unimix, the remaining loss scales, the slow critic and the return normaliser) are listed in the API below.

    Notes¶

    • What n_timesteps counts. One row per environment per vector step, reset rows included, as the reference's step does. env_frames = rows * action_repeat is logged next to it.
    • The score. The paper reports the returns of the stochastic policy's training episodes, logged as Train/episodic mean reward. The evaluation also samples its actions, since the reference has no deterministic mode, and draws fresh keys at each evaluation (new initial states and action noise); a rerun of the same seed draws the same ones.
    • Actions. Continuous actions are clipped to [-1, 1] and mapped onto the environment's bounds, the reference's ClipAction and NormalizeAction.
    • Memory use. Each replay row stores the observation, the action, the reward, the flags and the posterior latent: about 8.3 KB at 12M on a 24-dimensional observation, so the 250K rows of the DMC protocol take about 2.1 GB per seed, and about 3.2 GB with the training step's working set. agent.replay_bytes_per_seed gives the figure after train. Running several seeds multiplies it. The replay keeps min(ceil(replay_capacity / n_envs), rows per env of the run) rows per env (a capacity in rows, deviation D27), sized again by every train call, so that a run split into resumed calls keeps the replay of the uninterrupted run.
    • Recompilation. Widths, depths, counts, bins, imag_horizon, batch_size, batch_length, train_ratio and replay_capacity fix the compiled program; changing one recompiles.
    • Main deviations (all in deviations.md): training is synchronous and in float32 (the reference is asynchronous and computes in bfloat16); one decoder head for the flat observation; everything is checkpointed and seeded. The two-hot expectation is computed in an exact form (D22); the reference's form adds noise to early predictions under JIT, which measurably changes the early actor entropy.
    • The DMC tasks run on MuJoCo Playground's MJX ports, whose physics differ from dm_control's (E18), so comparisons with the published curves are approximate.

    Results¶

    Recorded on CPU in PERFORMANCE_REPORT.md, with the 1M preset and 20,000 rows, before evaluations drew fresh keys: Pendulum swings up from 12,000 rows on (final evaluation -222, against about -1,200 at the start). On CartPole Ajax was compared with the reference code itself on the same protocol, over three pre-registered rounds; once both used the same two-hot expectation, the training statistics' seed ranges overlapped the reference's in at least 52 of 58 windows, and all five Ajax seeds passed the redefined CartPole check, as did all five of the reference's. The GPU validation against the published DMC curves is specified in VALIDATION.md and has not been run yet. The probes (tests/probing) train DreamerV3 briefly on tiny environments with known answers (discounting, a continuous advantage, and a risky-or-safe choice it can only weigh in imagination), and its own tests (tests/agents/DreamerV3) check that a run split by a checkpoint equals the run left whole. On the CPU speed benchmark (benchmarks/agent_bench.py: CartPole, 4 environments, 8,000 rows, a smaller model than the paper's) DreamerV3 ran at 367 rows per second of execution (275 with compilation) at main a8a13c2.

    DreamerV3, paper-era (2411f7d + 29eb964), for vector observations and either action space (the module's tick).

    Every hyperparameter of the world model, the actor-critic and the optimiser (weight_decay included) is the DreamerV3Config field of the same name and default, documented there; setup builds model_config from them, the widths left None taking the model_size preset's.     replay_bytes_per_seed property ¶

    replay_bytes_per_seed

    Bytes of the resolved replay rings of one seed (0 before).

    prepare_replay ¶

    prepare_replay(start_tick, end_tick, agent_state)

    The replay of a call ending at tick end_tick, one ring of C rows per env (count_ring_rows), and the state it resumes from (DESIGN.md sections 5.5, 5.6, 6.3). A fresh run sizes the ring from its own length and records it, but for a 0-tick one (a checkpoint skeleton), which takes the ring the latest run recorded (the minimal ring before any) so that its shapes are that run's. A resumed run grows the state's ring to the uninterrupted run's (size_ring) and records it.

    init ¶

    init(key, context)

    A fresh agent: parameters, optimizers, collector, empty replay.

    collect ¶

    collect(agent_state, tick, context)

    Act and store one row per env (driver.py:55-81, replay.py:97-144).

    tick is the absolute, unbatched tick index (the scan input, offset on resume): the row of every env written now is the tick-th of its stream. Returns the state and tick, which locates the replay's newest rows for the tick's updates (update, after the tick's rows: deviation D3).

    update ¶

    update(agent_state, tick, context)

    One training step on a fresh batch, then the write-back.

    tick is the absolute, unbatched tick whose rows were added last: the replay holds tick + 1 rows per env. The batch pops the online queue and fills up uniformly (StreamReplay.sample); the learner's step (Algorithm J: replay context, joint gradient, LaProp, slow critic) uses fresh noise; its posterior latents of the trained rows are written back at once (synchronous, deviation D1). The loop folds the extensions' post_update phase after it.

    evaluate ¶

    evaluate(agent_state, key, context, num_episode_test)

    Sampled evaluation episodes from a zero carry (is_first first).

    The reference's policy samples in every mode (dreamerv3_spec 7.3); ajax.evaluate.evaluate_policy runs one episode in each of num_episode_test freshly reset envs with the training action repeat, from key: fresh at each evaluation (ajax.log.evaluation_keys), so each draws new initial states and action noise.

    policy_parts ¶

    policy_parts()

    As its evaluation acts: the row collector's sampling policy, from a zero carry.

    report ¶

    report(agent_state, aux)

    The logged training metrics: house keys, env_frames, losses.

    Train/episodic mean reward is the rolling mean of the training episodes' returns, the reference's score (dreamerv3_spec 7.3, 7.7); env_frames = rows * action_repeat the reference's x-axis, its step clock (rows, reset rows included) times the repeat (2411f7d dreamerv3/main.py:124-132, embodied/core/logger.py:32; DESIGN.md section 2): one row per episode above the simulator's frames; Train/n_updates the training steps so far; Train/ the mean of each training metric over the updates since the last log.

    restart_train_metrics ¶

    restart_train_metrics(agent_state, logged)

    The training metrics' means restart after each log (train.py:113-121).

    make_policy ¶

    make_policy(agent_state)

    observe_and_act with the agent's current parameters bound: the row collector's policy and the evaluation's.
