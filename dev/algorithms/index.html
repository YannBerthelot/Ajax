    Algorithms¶

    Ajax has nineteen agents, all exported from ajax. Each follows a published paper, and each page says where Ajax departs from it. Every agent takes an environment (TDMPC2MultiTask: a dataset, and environments to evaluate on), its own hyperparameters, episode_length and action_repeat (for Brax and Playground environments) and extensions=(). It trains one or several seeds in a single compiled program with agent.train(seed=[...], n_timesteps=...).

    • Actions: both means discrete and continuous action spaces. Agents that take only one kind check it at construction.
    • Memory: whether the agent accepts memory= (a GRU, LSTM, transformer or Mamba block; see Memory). DreamerV3's world model is recurrent by design.
    • Extension phases: every agent folds pretrain, post_update and eval_metrics; the column lists the others it folds. An extension that needs a phase the agent does not fold is refused at construction. See Extensions.
    • Continuous actions: every continuous agent acts in [-1, 1], squashed by tanh or clipped there, and Ajax maps that range onto the environment's bounds before each step: centre + half_range * action. On gymnax Pendulum, whose torque lies in [-2, 2], the agents reach the whole range. Experts are written in the environment's units; Ajax reads them in the agent's. See Environments.
    • Evaluation: with a logging_config, every agent evaluates its policy every log_frequency steps on num_episode_test episodes and train returns the evaluations. Each evaluation draws fresh random keys (new initial states), and a rerun of the same seed draws the same ones. The model-free agents evaluate their deterministic action (the mean, or the greedy action); DreamerV3 samples, as its reference does, and TD-MPC2 plans in evaluation mode. For SAC, TD3, REDQ, AVG, DQN, PQN and PPO, Eval/mean bias is the critic's estimate minus the discounted return actually obtained, averaged over the evaluated steps.

    Which agent should I use?¶

    Start from your problem, not from the algorithm.

    Discrete actions. PPO is the general choice; it also takes memory and image observations. DQN learns from a replay buffer, so it reuses every sample many times. PQN has no replay: it learns from many environments at once, which suits fast JAX simulators.

    Continuous actions, and samples are cheap. If the simulator runs many copies in parallel, PPO learns from large fresh rollouts and needs no replay buffer.

    Continuous actions, and every sample counts. Use an off-policy agent with a replay buffer. SAC is the default; TD3 learns a deterministic policy; REDQ trains an ensemble of ten critics with twenty critic updates per step, so it does far more work per sample.

    A task that never ends, such as holding a setpoint: discounting only shortens the agent's view. ASAC and RVI-SAC (off-policy) and APO (on-policy) optimise the average reward per step instead. A discounted agent can also centre its values on the reward rate with ValueCentering.

    Only a dataset, no simulator to explore with (logged runs, a plant's history): IQL trains on it offline (train_offline) and can fine-tune online after; TD3+BC is TD3 with a cloning term (TD3).

    Learning one transition at a time, without a replay buffer or target networks: AVG.

    The observation hides part of the state (a velocity, a cue seen earlier): give PPO, SAC, TD3, REDQ, ASAC or APG a memory=. DreamerV3 is recurrent already.

    You have an expert controller (a PID, a hand-written policy): SAC has the most expert support, and it alone folds the action phase, which lets the expert act during collection. SAC, TD3, REDQ and APO can clone the expert into the actor before training (the CloningPretrain extension), and SAC, TD3, REDQ, ASAC and APO accept the ImitationLoss term. See Expert guidance. SAC, TD3, REDQ, ASAC, AVG, PPO and APO can also learn a PID controller directly, with the PID policy of Networks. To imitate the expert without a reward, use DAgger.

    Your simulator is differentiable (a gymnax environment that exposes its transition gradients) and you want one controller for a family of systems: APG. Its contextual controller reads the tracking history, so one controller can serve the whole family.

    You want a model of the environment. DreamerV3 learns inside its world model and handles discrete and continuous actions. TD-MPC2 plans with its model at every step, for continuous control with fixed-length episodes (terminating ones with episodic=True). Both do much more computation per environment step than the model-free agents. To train one model offline on data from several tasks, use TDMPC2MultiTask.

    Supervised learning instead of value estimation: UDRL learns which action leads to which return, then asks for more.

    Speed¶

    The CPU speed benchmark (benchmarks/agent_bench.py: 4 environments, 8,000 steps, Pendulum or CartPole by agent) last ran at main a8a13c2, with every agent updating within the run. Counting execution alone, without compilation: PPO, APO, DQN, PQN, AVG, UDRL and APG ran at 9,000 to 37,000 steps per second; SAC, TD3 and ASAC at 1,250 to 2,700; REDQ at 47, since it makes 20 updates of 10 critics per step; DreamerV3 and TD-MPC2 at about 370 and 290, with smaller models than the papers'. The presets differ by agent, so the figures compare runs of one agent over time better than agents with each other. The benchmarks run on a CPU; Ajax claims no GPU speed-up. The full table is in PERFORMANCE_REPORT.md; see also Performance.
