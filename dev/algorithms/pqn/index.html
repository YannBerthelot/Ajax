    PQN¶

    Parallelised Q-Network is Q-learning without a replay buffer and without a target network. It collects short rollouts from many environments at once, as PPO does, and regresses the Q-network on Q(lambda) returns computed from them. A LayerNorm after every hidden layer keeps this stable. It is built for many vectorised environments, which replace the buffer as the source of varied data.

    Paper. Gallici et al., Simplifying Deep Temporal Difference Learning, 2024.

    Can I use?¶

    PQN
    Continuous actions (Box) No
    Discrete actions (Discrete) Yes
    Learning On-policy rollouts, no replay buffer
    Vectorised environments (n_envs) Yes, and it relies on them
    Recurrent memory (memory=) No
    Image observations (CNN encoder) Yes, with cnn_image_shape
    Extension phases pretrain, post_update, eval_metrics, observe, on_target, critic_loss

    Example¶

    from ajax import PQN
from ajax.logging import LoggingConfig

agent = PQN("CartPole-v1")  # 8 envs, 128-step rollouts
logging = LoggingConfig(log_frequency=32_768, backends=())
state, evaluations = agent.train(seed=[0, 1], n_timesteps=131_072, logging_config=logging)
print(evaluations["Eval/episodic mean reward"])  # one row per seed

    Key hyperparameters¶

    Defaults are read from PQN.__init__.

    Argument Default What it does
    n_envs 8 parallel environments
    learning_rate 2.5e-4 RAdam step size (the authors' optimiser, optax.radam)
    architecture ("128", "relu", "128", "relu") hidden layers; each Dense is followed by a LayerNorm
    gamma 0.99 discount
    q_lambda 0.65 the lambda of the Q(lambda) returns
    n_steps 128 rollout length per env
    n_epochs 4 passes over each rollout
    num_minibatches 4 minibatches per pass
    epsilon_start, epsilon_end 1.0, 0.05 exploration rate at the start and the end of its decay
    epsilon_decay_frac 0.5 fraction of the run over which epsilon decays
    reward_scale 1.0 multiplies the rewards in the target
    max_grad_norm 10.0 gradient clipping by global norm (the authors'); None turns it off
    normalize_observations, normalize_rewards False running normalisation
    reward_normalization_gamma None with normalize_rewards, divide by the spread of the discounted return
    td_loss_fn None the loss; None is half the squared error (the authors'), make_huber_td_loss(delta) the Huber loss
    cnn_image_shape, cnn_extra_obs_dim, cnn_spec None, 0, None convolutional encoder for flat image observations; None builds the reference network (see Notes)
    expose_recent_rollout False keep the last rollout on state.last_rollout even when no extension reads it
    episode_length, action_repeat None, 1 simulator steps per episode (1,000 when None) and per agent step, on Brax and Playground
    extensions () research features (see Extensions)

    A rollout holds n_steps * n_envs rows (1,024 by default), which must divide evenly into num_minibatches; PQN raises otherwise.

    Notes¶

    • Returns. As purejaxql computes them. With V(s) = max_a Q(s, a), each step's return is G_t = r_t + gamma ((1 - lambda) V(s_{t+1}) + lambda G_{t+1}), and G_t = r_t + gamma V(s_{t+1}) at the rollout's last step. At the end of an episode the return is the reward. A time limit ends an episode as a termination does, since gymnax's done flag does not tell them apart. The rollout's second-to-last step reads the last step's V(s_T) where its own V(s_{T-1}) belongs, as purejaxql's backward pass does.
    • One update. The returns are computed once per rollout with the current network, then held fixed for n_epochs passes of num_minibatches gradient steps, the rollout reshuffled each pass.
    • Why several envs. Without a buffer, the data's diversity comes from the parallel envs. The probes run PQN with 8 envs because with one env the value of the action it stops exploring drifts.
    • Exploration. Epsilon decays linearly with the training fraction, read once per update at the rollout's start, as purejaxql reads it; evaluation is greedy.
    • Extensions. on_target extensions reshape the returns before they are held fixed; critic_loss extensions add a term to every minibatch's TD loss.
    • Expert. With expert_policy= (an index per row), collection tracks the expert, its observation features read it, and evaluations log its return. Under JSRLCurriculum the expert acts the first steps of each episode; Q is fitted at the actions the steps executed, whose rewards the returns hold, not at the policy's choice. JSRL with PQN is Ajax's composition, not a published pairing; as with epsilon-greedy, the expert's steps lean PQN's untruncated returns toward its behaviour.
    • Initialisation. As the authors' code (mttga/purejaxql), which sets no initialiser: every Dense layer, the Q head included, starts with Flax's default lecun_normal kernel and a zero bias.
    • Images. With cnn_image_shape and no cnn_spec, PQN builds the authors' image network: Mnih et al.'s (MNIH_CNN) for images of at least 36 pixels a side, MinAtar's (MINATAR_CNN) for smaller ones, each layer he_normal and followed by a LayerNorm. The image features go straight to the Q head; architecture is not used. Their Atari network also divides pixels by 255; Ajax leaves that scaling to the environment.
    • Shared code. PQN shares the value agents' Q-network wrapper, TD loss step and epsilon-greedy collection, and the on-policy family's loop and minibatch shuffler; it imports nothing from DQN. Its own code (agents/PQN/PQN.py) is its update and the Q(lambda) returns, beside the LayerNorm network (agents/PQN/networks.py).

    Results¶

    The reproduction results set PQN beside its authors' code (purejaxql) on CartPole and Asterix-MinAtar, with learning curves. A conformance check (tests/conformance/test_pqn_purejaxql.py) runs one training iteration of each from the same state with the same random numbers and compares them step by step; the differences it finds are listed in the specifications. Unit tests (tests/agents/PQN and the contracts every agent shares) check its pieces against exact contracts, without learning. The probes (tests/probing) train it briefly on tiny environments with known answers: its Q(lambda) returns, discounting, episode ends, extension phases, and a run split by a checkpoint matching the run left whole. On the CPU speed benchmark (benchmarks/agent_bench.py: CartPole, 4 envs, 8,000 steps) PQN ran at 36,961 steps per second of execution (7,358 with compilation) at main a8a13c2 (see PERFORMANCE_REPORT.md).

    Parallelised Q-Network (Gallici et al., 2024) for discrete action spaces.

    On-policy value-based RL: vectorised rollouts, Q(lambda) regression targets, no replay buffer and no target network -- training stability instead comes from LayerNorm in the Q-network. The policy is greedy over Q, with epsilon-greedy exploration during collection.

    agent_state,

    One PQN update on an (n_steps, n_envs) rollout: Q(lambda) targets bootstrapped on the current network (no target network), then n_epochs epochs of TD steps, the rollout reshuffled each epoch; also logs the epsilon its rollout read (the schedule read once per update, as purejaxql reads it).
