    Agents¶

    Every agent but TDMPC2MultiTask subclasses ActorCritic. Its constructor takes the environment, the algorithm's own hyperparameters and extensions=(); train runs one or more seeds at once. TDMPC2MultiTask learns offline from a dataset and keeps its own train, with the same seeds-at-once call.

    Each agent's reference, with every constructor argument, is at the end of its algorithm page, next to the paper it follows and the notes on using it:

    Every agent but DreamerV3 and TD-MPC2 is a declared agent: its hyperparameters are the fields of a dataclass on a family of ajax.agents.families, which builds its constructor (keyword-only after env_id), run config and train function: a replay (SAC, TQC, REDQ, ASAC, RVISAC, CrossQ, TD3, IQL, DQN, DAgger: ReplayAgent), each step as it comes (AVG: IncrementalAgent), rollouts (PPO, APO, PQN: OnPolicyAgent) or an iteration of its own (UDRL, APG: OwnIterationAgent). Its fields are fixed once built: dataclasses.replace(agent, gamma=0.9) builds another.

    resume_iteration_offset(initial_state)

    Absolute index of the first scan iteration when resuming.

    train feeds it to the inner train function so a resumed run sees absolute iteration indices (see build_resumable_train).     Train on a transition dataset alone, with no environment step.

    n_updates of the agent's own update on a replay holding dataset's rows (:meth:ajax.agents.loop.TrainLoop.offline), evaluating every logging_config.log_frequency updates. Returns (state, out) as :meth:train does, with the state's timestep and evaluation count back at 0, so that train(initial_state=state, ...) fine-tunes online from it, its replay keeping the dataset's rows (with learning_starts=0, from the first step).

    ajax.agents.families ¶

    The agents' families. An agent declares its hyperparameters once, as the fields of a dataclass, and writes what its paper defines: its networks, its init (on its own key layout), its update and its equations. Its family builds everything else from those fields, the same for every member: the constructor, the logged run config, the optimisers, the replay, the extensions' binding, the collector's storage, the training loop's shape and the evaluation's value estimate::

    @dataclass(kw_only=True, eq=False, repr=False)
class IQL(ObservationNormalization, ExpertGuided, ReplayAgent):
    expectile: float = 0.7
    ...

    def init(self, key, context): ...
    def update(self, agent_state, context): ...

    An agent learning from a replay of transitions is a ReplayAgent, one learning from each rollout of its current policy an OnPolicyAgent, one whose iteration is its own (a differentiable rollout, a replay of segments) an OwnIterationAgent, and one storing rows in a replay of its own, sized per call (a world model's), an OwnReplayAgent. The shared knobs an algorithm may take beyond the ones every agent takes (gradient clipping, normalisation, an expert, image observations) are field mixins. The family reads some fields by name (DeclaredAgent, ReplayAgent, OnPolicyAgent). Every agent, family and mixin carries the literal @dataclass decorator, which the API docs read the constructor from; the contract an agent declares for the extensions and the loop (name, capabilities, ...) stays unannotated, so it is no field.

    TrainContext dataclass ¶

    TrainContext(
    env_args,
    network_args,
    actor_optimizer_args,
    critic_optimizer_args,
    extensions,
    total_timesteps,
    make_collector,
    buffer=None,
    recurrent=False,
    executed=None,
)

    What one train() call gives the agent's init and update, beyond its hyperparameters.

    It holds:

    • the run's environment config (env_args);
    • the network and optimiser configs (network_args, actor_optimizer_args, critic_optimizer_args);
    • the extensions, bound to this run;
    • the replay: a replay agent's buffer, an own-replay agent's own (None on-policy);
    • how to build the collector (make_collector);
    • the run's horizon (total_timesteps);
    • whether the run is recurrent (its networks have memory);
    • the residual-action hook (executed), None without a residual policy.

    Why it exists: an agent's hyperparameters are its fields, fixed once it is built. Everything that depends on one train() call (the env and the configs it may override, the extensions bound to them, the horizon) is passed explicitly to init and update, where SB3 keeps it as attributes of the agent and PureJaxRL in closures inside its make_train. One agent then trains any number of runs, and a test calls init or update alone on agent.make_context(total_timesteps) (CLAUDE.md rule 7: passed in, never global).

    ajax.agents.minibatch.choose_rollout_split ¶

    choose_rollout_split(
    agent_config, n_steps, n_envs, recurrent
)

    The rollout's RolloutSplit.

    time only when unroll_length asks for it (n_steps gives whole rollouts per env): with as many minibatches as envs, each minibatch is then one env's trajectory, its advantages normalised within it. It needs fragments that split evenly into more than one minibatch: recomputing GAE on a single minibatch, the whole rollout, with a critic that just stepped only makes the value targets oscillate (the flake of the one-env probing fixture). A recurrent rollout is a pool of sequences of bptt_length steps (by default default_bptt_length) that must split exactly into the minibatches, as Baselines' and CleanRL's recurrent PPO assert: a bptt_length that does not divide the default raises ValueError.
