    Environments and wrappers¶

    Agents take a gymnax, Brax or MuJoCo Playground environment, or its id, and wrap it themselves. Every continuous agent acts in [-1, 1], and agent_action_to_env maps its action onto the environment's bounds; an expert speaks the environment's units, and the agent reads it through ExpertInAgentUnits. See Environments and Differentiable simulation.

    ajax.environments.create ¶

    register_brax_builder ¶

    register_brax_builder(env_id, builder)

    Register a custom brax env builder for env_id.

    Mirrors register_playground_builder for brax-stack envs. The builder takes (n_envs, episode_length) and must return a fully wrapped env whose _ajax_env_id attribute equals env_id. Subsequent calls to _build_brax_env(env_id, ...) delegate to this builder. Used when a safety-experiments-style env wraps a stock brax robot with custom termination/observation-augmentation that must survive eval's rebuild. To support action_repeat > 1 the builder must also accept an action_repeat keyword (passed only when > 1).

    register_playground_builder ¶

    register_playground_builder(env_id, builder)

    Register a custom playground env builder for env_id.

    The builder takes (n_envs, episode_length) and must return a fully wrapped env whose _ajax_env_id attribute equals env_id. Subsequent calls to _build_playground_env(env_id, ...) delegate to this builder. To support action_repeat > 1 the builder must also accept an action_repeat keyword (passed only when > 1).

    build_env_from_id ¶

    build_env_from_id(
    env_id,
    n_envs=1,
    fresh_reset=True,
    *,
    episode_length=1000,
    action_repeat=1,
    differentiable_reset=False,
    episode_keys=True,
)

    Build a wrapped env from its id (gymnax, mujoco_playground or brax).

    fresh_reset only concerns mujoco_playground envs (see _build_playground_env); gymnax and Ajax's brax stack already draw a new initial state for every episode.

    action_repeat (default 1) repeats each agent action for that many simulator steps on brax / playground envs (see :func:_build_playground_env); episode_length (a keyword, default 1000) then counts simulator steps. gymnax envs do not support it.

    differentiable_reset concerns the auto-resets that compute a fresh reset inside step: brax envs, and playground envs with fresh_reset=True (the default). With differentiable_reset=False (the default) they evaluate the reset only on steps where some env is done, inside a lax.while_loop, because the reset can cost as much as many env steps. Gradients through such an env still flow with respect to the actions, the policy parameters and the env state, and forward mode (jax.jvp) works with respect to anything. Only reverse mode through the reset itself -- jax.grad with respect to something the reset depends on, such as physics parameters of the env -- fails, loudly, at trace time: "Reverse-mode differentiation does not work for lax.while_loop". Pass differentiable_reset=True for that case: the reset is then evaluated on every step and kept only for done envs, which reverse mode can cross, at the cost of a reset per step. Transitions are the same either way, up to float rounding. Gymnax envs (whose auto-reset is always computed) and playground's cached auto-reset ignore the flag, and evaluation (evaluate.setup_environment), which never differentiates, rebuilds the env with the default.

    episode_keys (default True) keys every env's resets by episode: env i's k-th episode starts, and on gymnax draws its dynamics, on keys of (i, k) alone, the same whatever the actions, updates and extensions before it (:func:with_episode_keys). False keeps each backend's own auto-reset, which reproduces runs from before episode keys. playground's cached auto-reset (fresh_reset=False) ignores it.

    with_episode_keys ¶

    with_episode_keys(env, on=True)

    A gymnax env with its resets keyed by episode: an EpisodeKeyedAutoResetWrapper directly over the env, under the task's own wrappers, each copied onto the keyed env. With on=False, a copy marked to keep the env's own auto-reset, which prepare_env then leaves as it is. A brax or playground stack keys its resets in its auto-reset wrapper instead (build_env_from_id's episode_keys).

    InitialStateWrapper ¶

    InitialStateWrapper(env, init_state_fn)

    Bases: GymnaxWrapper

    Override the plant's state at reset (an initial-condition distribution).

    init_state_fn(key, state, params) -> state receives the env's own reset state and returns the state to start from; the observation is recomputed with env.get_obs. Use it to narrow (or fix) the initial conditions of a benchmark, e.g. the p(O) of a control meta-dataset (Busetto et al. 2024 keep it fixed at the nominal steady state).

    Every episode starts this way, the auto-reset ones included: gymnax's step auto-resets with the inner env's reset_env, so step applies init_state_fn to that reset state too (fields the inner step carries across its auto-reset stay as it left them). Under resets keyed by episode its key derives from the episode's start key (episode_draws_key).

    EpisodeKeyedAutoResetWrapper ¶

    EpisodeKeyedAutoResetWrapper(env)

    Bases: GymnaxWrapper

    gymnax's auto-reset keyed by episode, directly over a gymnax env. A reset derives the env's episode root from its key ("episodes"); episode k starts on episode_start_key(root, k) and its step t draws on fold_index(fold_index(root, k), t), so it starts and draws alike whatever the actions, updates and extensions before it (PEGASUS, Ng and Jordan 2000). The step's own key reaches only the wrappers above.

    step is gymnax 1.0.1's Environment.step but for the split of its key: the next start, evaluated at every step as gymnax's is, draws on one key per episode. An env with its own step or reset is refused, since this wrapper would bypass it.

    AutoResetWrapper ¶

    AutoResetWrapper(env, differentiable_reset=False)

    Bases: BraxWrapper

    Automatically resets Brax envs that are done, sampling a new random seed for initialization at each reset. This seed is propagated through info["rng"]

    Ajax's brax stack with episode_keys=False, as before episode keys (FreshAutoResetWrapper keys them).

    By default the reset is evaluated only on steps where some env is done, inside a lax.while_loop (see :func:_call_if_any), and skipped on the others. Rollouts stay differentiable with respect to the actions, the policy parameters and the env state, none of which the reset depends on, and forward mode (jax.jvp) works with respect to anything. What reverse mode cannot do is differentiate through the reset itself, with respect to something it depends on (e.g. physics parameters of the env): jax.grad then raises "Reverse-mode differentiation does not work for lax.while_loop" at trace time. differentiable_reset=True evaluates the reset on every step instead and keeps the result only for done envs, which reverse mode can cross, at the cost of a reset per step.

    BatchRngWrapper ¶

    BatchRngWrapper(env, n_envs)

    Bases: BraxWrapper

    Splits an unbatched PRNG key into n_envs keys on reset.

    Playground's BraxAutoResetWrapper.reset (and FreshAutoResetWrapper.reset) assumes rng is already shape (n_envs, 2) so it can jax.vmap(jax.random.split)(rng). Ajax callers pass a single unbatched key, so this adapter bridges the two conventions.

    FinalObsWrapper ¶

    FinalObsWrapper(env)

    Bases: BraxWrapper

    Stashes state.obs in state.info['final_obs'] on every reset/step.

    Place this directly below an auto-reset wrapper in the stack. The auto-reset wrapper overwrites state.obs with the reset observation on done, so without this the pre-reset observation is lost — breaking correct value bootstrapping on truncation (PPO/SAC need V(s_T) at truncation, not V(s_reset)). With this wrapper, downstream code can read state.info['final_obs'] to recover the terminal observation.

    Backend-agnostic: duck-typed passthrough that works for both brax State and mujoco_playground State (both expose .obs and .info).

    FreshAutoResetWrapper ¶

    FreshAutoResetWrapper(
    env, differentiable_reset=False, episode_keys=True
)

    Bases: BraxWrapper

    Auto-resets a batched mujoco_playground or brax env to a fresh initial state.

    Drop-in replacement for playground's BraxAutoResetWrapper in Ajax's playground stack (EpisodeWrapper, VmapWrapper, FinalObsWrapper, this, BatchRngWrapper; see ajax.environments.create), and for AutoResetWrapper in its brax stack under episode keys. With its default full_reset=False, upstream caches each env's first reset and restarts every later episode from it, so a whole run sees only n_envs initial conditions, whereas dm_control draws a new one per episode. Upstream's full_reset=True does draw new ones, but it (a) evaluates a full reset on every step (on CheetahRun, whose reset runs a 200-step stabilisation, ~180x the cost of a step) and (b) replaces the whole info of done envs with the reset's, which zeroes truncation, episode_done and episode_metrics and overwrites final_obs with the reset observation, breaking the V(s_T) bootstrap at truncation.

    On a step where some env is done, this wrapper draws a fresh batched reset (computed only on such steps, see :func:_call_if_any) and gives each done env, from it:

    • data (a brax state's pipeline_state) and obs;
    • the info entries produced by the base environment's own reset, i.e. its per-episode state (its rng, task targets, ...).

    Everything else describes the transition just taken and passes through: reward, done, metrics, and the bookkeeping that the wrappers below write into info on every step (EpisodeWrapper's steps, truncation and episode_*; FinalObsWrapper's final_obs).

    With episode_keys (the default) env i's k-th episode starts on episode_start_key(root_i, k), as under EpisodeKeyedAutoResetWrapper; without, on its key split at every step, as before them.

    differentiable_reset=True evaluates the reset on every step instead, for reverse-mode gradients through the reset itself; see :class:AutoResetWrapper.

    TerminatedTruncatedWrapper ¶

    TerminatedTruncatedWrapper(env)

    Bases: GymnaxWrapper

    Split a time-limit-inclusive terminal flag back into terminated/truncated.

    Stock gymnax >= 1.0 environments already return the two flags apart, so they do not need this wrapper. It is for third-party environments that subclass gymnax's Environment but whose step_env still reports the pre-1.0 done = terminated | truncated, which gymnax's base step hands back in the terminated slot. Left unwrapped, such an env makes every time-limit truncation look like a natural termination, so PPO/SAC drop the V(s_T) bootstrap and silently underestimate the value of long-running states.

    The time limit is the truncated flag gymnax's base step reports: it is computed from the pre-reset state, whereas the returned state has already been auto-reset (time == 0) at the limit.

    ObservationNoiseWrapper ¶

    ObservationNoiseWrapper(env, sigma, scale=1.0)

    Bases: GymnaxWrapper

    Sensor noise on a gymnax env's observations, obs + sigma * scale * N(0, I), drawn afresh at every reset and step from a key folded off the call's own (the env's own draws are unchanged).

    The pre-reset observation an episode end leaves in the info gets the step's draw, so a transition's next observation is the one the agent then sees. scale is a scalar or one value per dimension (e.g. the observations' standard deviations). get_obs stays the state's noiseless observation, which an expert reads (interaction.get_raw_obs).

    init_norm_info ¶

    init_norm_info(batch_size, obs_shape, returns=False)

    Initialise running stats with leading axis batch_size.

    The leading axis is redundant (online_normalize collapses it on every update, so rows carry identical values) but it is load-bearing for env-side callers: env-side stats live inside the env state pytree, which Brax's VmapWrapper vmaps over the n_envs axis. Shrinking the stats to (1, *) would break that vmap with a mismatched-axis error. Agent-side callers should pass batch_size=1 instead (see init_agent_obs_norm).

    ajax.environments.obs_norm ¶

    Agent-side running observation normalization.

    Lives inside CollectorState.obs_norm_info so stats are part of agent_state and thread through naturally. Normalization is applied at every actor/critic apply_fn boundary; stats are updated only at collection time (online interaction and BC dataset prep). The replay buffer stores raw observations (their features included) so changing stats do not poison old samples; we re-normalize at sample time.

    Agent-side so that the statistics are the agent's, shipped with its policy, and cover its observation features (ajax.controller), which the env never sees: the env's columns and the normalised features; the raw features (an expert's action) come last and stay raw.

    init_agent_obs_norm ¶

    init_agent_obs_norm(obs_dim)

    Initialise running stats for an obs vector of size obs_dim.

    Stats are stored with leading shape 1 (not n_envs): online_normalize reduces the per-env axis on every update so all envs would share the same scalar stats anyway, and apply_obs_norm only needs the per-feature mean/var. The size-1 leading axis preserves broadcasting against batched obs (*, obs_dim) while saving an n_envs× memory factor on every checkpoint and vmap broadcast.

    update_obs_norm ¶

    update_obs_norm(obs, info, raw_columns=0)

    Update running stats with obs and return (normalized_obs, new_info).

    obs shape: (n_envs, obs_dim). When info is None the call is a no-op (returns input unchanged) so call sites can stay unconditional. The leading raw_columns stay raw (see online_normalize), as do the raw features after the columns the statistics cover.

    normalized_obs ¶

    normalized_obs(obs, info, raw_columns=0)

    obs normalised with the statistics info, not updated, as :func:update_obs_norm normalises (online_normalize): the frozen statistics of an on-policy agent's evaluation and of its final and reset observations. info None: obs as it is.

    apply_obs_norm ¶

    apply_obs_norm(obs, info)

    Normalize obs using existing stats (no update). Used at every actor/critic apply_fn site that consumes obs sampled from the buffer or carried by the eval scan, so stats updates stay localised to the collection sites. Falls back to raw obs while the running stats are still empty (count == 0), avoiding a divide-by-≈0 at step 1 before any update.

    The statistics cover the leading columns: the env's and the normalised features'; what follows stays raw: a raw feature (an expert's action) and a critic's action, already in action units, as the env's raw_columns keep a PID's terms raw.

    ajax.environments.system_class ¶

    System classes: distributions over environment parameters.

    A system class is a distribution p(S) over the dynamics of an environment, represented as a distribution over its EnvParams. It is the object that turns one environment into a family of environments for domain randomisation, meta-learning and in-context control (Busetto et al. 2024, "One controller to rule them all", arXiv:2411.06482).

    Sampling returns batched params: every leaf carries a leading axis of size n, one entry per parallel environment. :func:ajax.environments .interaction.reset / :func:~ajax.environments.interaction.step detect that leading axis and vmap over it (gymnax only: brax envs do not take per-step params). APG, DreamerV3 and TDMPC2 train on them; the agents of the shared loop compile them as a static argument and refuse them when built (ActorCritic.supports_batched_env_params).

    SystemClass ¶

    Base class: a distribution over EnvParams.

    Subclasses implement :meth:sample. The nominal params are kept so callers can always fall back to the reference system (evaluation on the nominal plant, curriculum stage 1, ...).

    sample ¶

    sample(rng, n)

    Draw n systems; returns batched params (leading axis n).

    FixedSystem dataclass ¶

    FixedSystem(nominal)

    Bases: SystemClass

    Degenerate class containing a single system (the nominal one).

    UniformPerturbation dataclass ¶

    UniformPerturbation(nominal, fields, scale=0.05)

    Bases: SystemClass

    Independent uniform relative perturbation of selected parameter fields.

    Each listed field p is drawn as p * (1 + U(-scale, scale)), independently per field and per sampled system (a vector or matrix field is scaled by one factor per system); every other field stays at its nominal value. This is the meta-dataset construction of Busetto et al. 2024 (there: scale=0.05 on the 19 evaporator constants).

    fields must name attributes of the nominal EnvParams; a typo raises at construction rather than silently sampling nothing.

    env_params_is_batched ¶

    env_params_is_batched(params)

    True when params carries one system per env along a leading axis.

    A batched params (from :meth:SystemClass.sample or :func:broadcast_env_params) has every leaf with the same leading axis. An unbatched one always has at least one rank-0 leaf (gymnax's max_steps_in_episode at minimum), even when other fields are vectors or matrices (e.g. a plant's state-space model), so "any leaf has rank >= 1" would misclassify those.

    n_systems ¶

    n_systems(params)

    The number of systems a batched params carries: its leaves' leading axis.

    broadcast_env_params ¶

    broadcast_env_params(params, n)

    Replicate an unbatched params n times along a new leading axis.

    Used to run a single nominal system through the batched code path (e.g. a fixed system during the first curriculum stage). Every leaf (scalar, vector or matrix) gets the new leading axis; an already batched params is returned unchanged.

    ajax.environments.model_reference ¶

    Model-reference tracking tasks on top of any gymnax environment.

    Model-reference control (Busetto et al. 2024, arXiv:2411.06482, §2) asks a controller to make a plant's measured output y_k follow the output y^d_k of a reference model M driven by a user reference r_k. This module turns any gymnax env into such a task:

    • :class:StepReference is the reference distribution p(R): piecewise-constant random steps of random amplitude and duration.
    • :class:LinearReferenceModel is a discrete-time linear M (x_{k+1} = A x_k + B r_k, y^d_k = C x_k + D r_k); the paper's first-order model is :meth:LinearReferenceModel.first_order.
    • :class:ModelReferenceWrapper exposes the controller's view of the problem: observation [e_k, u_{k-1}] (tracking error and previous input, optionally followed by the raw plant observation) and reward -||y^d_k - y_k||^2, so the undiscounted return is the negative closed-loop matching cost of eq. (9) and the paper's M-RMSE is sqrt(-return / horizon).

    Every operation is plain jnp so the wrapper is differentiable when the inner env is (see :mod:ajax.environments.differentiable), and it composes with :mod:ajax.environments.system_class batched params because the wrapper is per-env (Ajax vmaps reset/step).

    StepReference ¶

    Random piecewise-constant references r_{[0, N-1]}.

    Each segment holds a value drawn uniformly in [min_value, max_value] for a duration drawn uniformly in [min_duration, max_duration] steps (both inclusive), independently per output. The paper's evaporator case uses values in [20, 25] % and durations in [20, 50] s at 1 s sampling over N = 100.

    LinearReferenceModel ¶

    Discrete-time linear reference model M.

    x_{k+1} = A x_k + B r_k, y^d_k = C x_k + D r_k with A: (nx, nx), B: (nx, ny), C: (ny, nx), D: (ny, ny).

)

    Diagonal first-order model, one independent channel per output.

    Defaults are the paper's eq. (12): x_{k+1} = 0.4286 x_k + 0.7143 r_k, y^d_k = 0.5669 x_k + 0.2914 r_k (unit DC gain).

    init_state ¶

    State whose output equals the plant's initial output.

    The paper initialises x^M_0 at the plant's initial condition so the desired trajectory starts where the plant starts. Solves C x = y0 - D r0 in the least-squares sense.

    ajax.environments.pid_terms ¶

    The error terms a PID controller acts on, which the observation feature ajax.extensions.observe.PIDTermsInput appends to the observation and the PID policy (ajax.modules.pid_actor.PIDPolicy) reads there.

    A PID controller computes u_t = Kp e_t + Ki I_t + Kd D_t from the tracking error e_t = target_t - current_t, its integral I_t and its difference D_t. The terms are the discrete-time PID's with sampling period dt (backward-difference form, as in Astrom & Hagglund, Advanced PID Control, 2006, cited from memory, unverified)::

    I_t = clip(I_{t-1} + dt * e_t, -integral_limit, integral_limit),  I_{-1} = 0
D_t = (e_t - e_{t-1}) / dt,                                       D_0 = 0

    The clip is clamping anti-windup (integral_limit=None: no clip). Every episode starts afresh: the integral restarts from dt * e_0 and the difference from 0, so no term carries over from the previous episode.

    ajax.environments.differentiable ¶

    Differentiable closed-loop rollouts (backpropagation through the simulator).

    The collectors in :mod:ajax.environments.interaction wrap every env step in stop_gradient: RL agents treat the environment as a black box. This module is the opposite path, for analytic policy gradient methods that differentiate an objective through the dynamics themselves (Busetto et al. 2024's in-context controller, APG/SHAC-style trainers, ...):

    • :func:with_transition_gradients configures a (possibly wrapped) gymnax env so its transitions keep gradients. gymnax >= 1.0 detaches them by default and only some envs support the opt-in (Pendulum, MountainCarContinuous, PointRobot, Reacher, Swimmer at the time of writing); unsupported envs raise instead of silently training on zero gradients.
    • :func:closed_loop_rollout runs a fixed-horizon closed loop between a stateful policy and the env with no stop_gradient anywhere, so jax.grad of any function of the returned :class:Rollout flows through the policy, the environment, and the policy's carry across time (BPTT over the whole horizon).

    Gymnax only: brax/playground envs take no per-step params and have their own (MJX) gradient story.

    Rollout ¶

    Time-major closed-loop trajectory, leaves shaped (T, B, ...).

    obs[t] is what the policy saw at step t, action[t] what it applied, reward[t] / done[t] / next_obs[t] the env's response. resets[t] is the episode-start flag the policy was given at step t (True at t=0 and after a done). info is the env's per-step info dict with every leaf stacked over time (e.g. a tracking wrapper's desired output), for metrics that need more than the reward. policy_action[t] is the policy's own action, before an action_map mapped it onto the env (None without one), and policy_observation[t] what an observe made of obs[t] for the policy (None without one).

    with_transition_gradients ¶

    Return a copy of env whose transitions preserve gradients.

    Walks Ajax's GymnaxWrapper chain (wrappers keep the inner env on _env) so a wrapped env is re-wrapped around the gradient-enabled core. Raises ValueError when the core env does not implement differentiable transitions.

    Action units¶

    ajax.environments.utils.agent_action_to_env ¶

    agent_action_to_env(action, env, env_params=None)

    Map an agent action in [-1, 1] to the env's action bounds.

    Every Ajax env step carrying an agent's or an expert's action calls it: every continuous agent acts in [-1, 1] (squashed or not), whatever the env's box. action is [n_envs, *action_shape]. Continuous actions are clipped to [-1, 1] and, on every dimension of the Box with finite bounds [low, high], mapped affinely onto them: c + h * clip(a, -1, 1), with centre c = (high + low) / 2 and half-range h = (high - low) / 2 (CleanRL's action_bias and action_scale). This is DreamerV3's ClipAction + NormalizeAction (a dimension with an infinite bound keeps the clipped action) and TD-MPC2's action scaling. For [-1, 1] bounds -- every brax / playground env, gymnax envs like MountainCarContinuous -- the map is exactly the clip, even when the bounds are traced; gymnax Pendulum's torque is [-2, 2]. Per-env (batched) gymnax params (ajax.environments.system_class) give per-env bounds: env e's action is mapped with its own system's bounds. Discrete actions pass through. Replay stores the agent's raw action, not this one. :func:env_action_to_agent is the inverse.

    ajax.environments.utils.env_action_to_agent ¶

    env_action_to_agent(action, env, env_params=None)

    Map an action in the env's bounds to agent units, [-1, 1].

    The inverse of :func:agent_action_to_env on the env's box, (a - c) / h, with the same action layout and per-env bounds. It does not clip: an action outside the box stays outside [-1, 1]. It is the identity on [-1, 1] boxes, on a dimension with an infinite bound and on discrete actions.

    ajax.environments.utils.ExpertInAgentUnits ¶

    ExpertInAgentUnits(expert, env, env_params=None)

    An expert written in env units, read in agent units ([-1, 1]).

    What the expert returns -- expert(obs), a stateful expert(state, obs)'s action, step_with_gains's action -- goes through :func:env_action_to_agent's map, unclipped. init_state, learnable_fields, anchor_gains and step_with_gains exist exactly when the expert's do (hasattr still tells a stateful expert). It hashes by identity, for jit's static arguments.

    Its bounds are one (A,) box read from concrete params, also inside jit (static params): a stateless expert is also vmapped over single observations, where per-env bounds would broadcast its action. Per-env boxes that differ raise. On a discrete env the expert's index column passes through, and action_count (None when continuous) records the number of actions, the width of its one-hot.
