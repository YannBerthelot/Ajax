    Extensions¶

    An extension adds a research feature to any agent whose loop folds the phases it uses. The user guide shows how to use them and Writing an extension how to add one.

    ajax.extensions.base ¶

    The Extension framework — composable research features for any agent.

    An :class:Extension is a research feature (expert guidance, observation augmentation, online behavioural cloning, target modifiers, exploration schemes, instrumentation, …) that attaches to any agent without bloating the agent's own file. It implements only the lifecycle phases it touches; an agent's training loop folds every extension through each phase, in list order.

    Design contract¶

    • Static. Extensions are plain Python objects passed as static arguments to the jitted training step, so the fold unrolls at trace time (a Python for over a fixed tuple — no dynamic dispatch). Every extension must therefore be hashable: the default id-based hash is fine for a one-off instance; a @dataclass(frozen=True) is preferred for instances carrying config, so the JIT cache is reused across equivalent runs.
    • State lives in the pytree. An extension never stores mutable state on self — only frozen config. Anything that changes during training is a pytree returned by :meth:Extension.init_state and carried in BaseAgentState.ext_state (one entry per extension; the default () means stateless, zero overhead).
    • No-op by default. Every phase method has a default that is the identity / 0.0 / {} / unchanged-state, so an extension is exactly as invasive as the phases it overrides, and an empty :class:ExtensionStack is genuinely zero-cost.
    • Keys by name. In every phase an extension draws on a key of its own, derived from its name and occurrence (extension_key_names), so adding, removing or moving another extension changes none of its keys. Where its pretrain or post_update runs the agent's own steps, the stack lends it a key off the agent's and takes the agent's back after.

    Phases¶

    init_state build the extension's pytree state (once, on fresh init) pretrain one-shot, before the training loop (MC/BC pre-training) on_target transform the TD / value target critic_loss extra additive critic-loss term (summed over extensions) actor_loss extra additive actor-loss term (summed over extensions) action override the collection-time action (None = defer; the last non-None proposal in the stack wins) eval_action override the evaluation-time action (same rule) transform_action make the executed action a function of the policy's and the expert's (residual RL), in collection, the losses and evaluation; the replay stores the executed one actuate execute the chosen action through the expert (gain mode: it sets the expert's gains); the replay stores the chosen post_update hook after the update step (φ-refresh, schedules, …) eval_metrics extra metrics, merged into the eval log observe columns appended to every observation (an expert's action, the training progress), stored with it choose_warmup_action the actions of a warm-up step (ExpertWarmup's expert mix), uniform by default choose_replay_action the action a replay row stores (StorePolicyAction: the policy's), the executed one by default

    on_target, critic_loss and actor_loss may return (value, metrics) instead of their value: metrics, a dict of scalars named <extension>/<metric>, is logged with the update's own metrics (the last update's, or the mean over the update's epochs and minibatches, as the agent logs its own). Two extensions logging one name raise.

    Phase batches¶

    The batch dict of a phase holds the keys :data:COMMON_BATCH_KEYS lists, on every agent that folds it, and those the agent declares in its phase_batch_keys (on the shared steps: their sets in ajax.agents.loop, TARGET_KEYS and the others). An extension raises on a key it needs and does not find, rather than return a no-op. gamma is None for an average-reward agent, dones is where the target cut the bootstrap and targets the target, held constant; the critic (DQN's and PQN's q_state) and the actor come at the differentiated parameters. The replay agents' raw_observations is None in a run without an expert, whose replay does not keep them. a_expert is the agent's expert_policy's action at each row, stored at collection from the expert's state along the trajectory; None without one.

    ExtensionContext ¶

    Shared context handed to every extension phase.

    step and rng are traced; total_steps is static so it can drive Python-level decisions (e.g. schedule lengths) at trace time. The pretrain phase of a run on ajax.agents.loop.TrainLoop also gets its static env_args and, off-policy, its update(agent_state, experience) -> (agent_state, aux) and replay buffer, so an extension can run the agent's own update; each is None where the run has none.

    Extension ¶

    Base class for a composable research feature.

    Subclass and override only the phases the feature touches. Keep subclasses hashable (@dataclass(frozen=True) is the recommended form) and stateless on self — see the module docstring.

    observation_width ¶

    observation_width(env_args)

    The columns :meth:observe appends to every observation.

    init_observer ¶

    init_observer(n_envs)

    Its per-env state at an episode start ((): none).

    observe ¶

    observe(inputs, state)

    The (n_envs, observation_width) columns it appends to the observation inputs describes (:class:ajax.controller.ObserveInputs) and its state after that observation. It runs whenever an observation arrives, in collection and evaluation alike, and its columns are stored with the observation (ajax.controller). The default appends none.

    init_state ¶

    init_state(agent_state, rng)

    Return this extension's initial pytree state.

    Called once, on fresh initialisation only (skipped on resume). The default () marks a stateless extension — no pytree overhead in BaseAgentState.ext_state.

    pretrain(agent_state, ext_state, context)

    One-shot step before the training loop (e.g. MC/BC pre-train).

    Returns the (possibly updated) (agent_state, ext_state).

    replay_rows ¶

    replay_rows(n_envs)

    The rows its pretrain writes into a replay of n_envs envs (ExpertPrefill, PriorData); none by default.

    on_target ¶

    on_target(agent_state, ext_state, batch, target, context)

    Transform the TD / value target; or return (target, metrics) (the module docstring).

    critic_loss ¶

    critic_loss(agent_state, ext_state, batch, context)

    Extra additive critic-loss term (summed across extensions); or (term, metrics).

    actor_loss ¶

    actor_loss(agent_state, ext_state, batch, context)

    Extra additive actor-loss term (summed across extensions); or (term, metrics).

    action ¶

    action(agent_state, ext_state, obs, rng, context)

    Override the collection-time action; None defers.

    eval_action ¶

    eval_action(agent_state, ext_state, obs, rng, context)

    Override the evaluation-time action; None defers. obs is the shared evaluation's dict (ajax.evaluate.step_environment): executed_action, expert_action (the agent's expert's, None without one), observations (the critics' input) and raw_obs; expert_mask, written into it, marks where the expert's action was taken. rng is the extension's own key.

    transform_action ¶

    transform_action(actions, inputs)

    The executed action from the policy's actions and the expert's (:class:ajax.controller.TransformInputs), before the action is chosen: the warm-up and the acting modes act on executed actions, and the critics score them; the policy's by default.

    actuate ¶

    actuate(actions, inputs)

    The env's action from the chosen actions (warm-up draws included), executed through the expert of inputs (:class:ajax.controller.TransformInputs), and the expert's state after it. The replay stores the chosen actions; the default executes them as they are.

    policy_action_dim ¶

    policy_action_dim(env_args, expert)

    The dimension of the actions the policy chooses, where it is not the env's (gain mode: the expert's learnable gains); None: the env's.

    choose_warmup_action ¶

    choose_warmup_action(uniform_actions, inputs)

    The actions a warm-up step takes instead of uniform_actions, and whether the expert took them, one boolean for the step (ajax.controller.WarmupInputs); by default the uniform ones.

    choose_replay_action ¶

    choose_replay_action(executed_actions, policy_actions)

    The actions a replay row stores for a step: by default the ones executed (residual, warm-up or expert actions included), which generated the step's reward and next observation.

    policy_action_for_expert ¶

    policy_action_for_expert(policy_actions)

    For an action transform: the policy action, shaped like policy_actions, at which it executes its expert's own action. The rows the expert acts in (its prefill) store it as the policy's.

    reward ¶

    reward(agent_state, ext_state, batch, rewards, context)

    Replace a rollout's rewards before the agent's targets read them. Returns (rewards, ext_state, metrics).

    post_update ¶

    post_update(agent_state, ext_state, context)

    Hook after the update step. Returns (agent_state, ext_state).

    eval_metrics ¶

    eval_metrics(agent_state, ext_state, rng, context)

    Extra metrics, merged into the eval log.

    experts ¶

    experts()

    The experts this extension calls itself, on the observations it is given (without a state); none by default.

    uses_expert_actions_as_policy_actions ¶

    uses_expert_actions_as_policy_actions()

    Whether it puts an expert's actions where the policy's actions go: as the actor's target, or as an action its critics score. Gain mode refuses it, since there the expert's actions are env actions and the policy's are gains. None does by default.

    bind_to_agent ¶

    bind_to_agent(**agent_context)

    Return self, optionally populating closed-over agent context.

    The default is the identity: an extension ignores every kwarg it does not need.     compute_extensions_actor_loss(

    apply_eval_metrics(agent_state, step, rng, total_steps)

    bind_to_agent(**agent_context)

    with_experts ¶

    with_experts(convert)

    The stack with convert applied to every expert its extensions hold (their expert_fields; one still None is left). A convert memoised by identity keeps one expert one object, which :func:ajax.extensions.expert.reads_stored_expert_actions compares.

    check_extensions ¶

    check_extensions(
    agent_name,
    stack,
    capabilities,
    phases,
    *,
    context=(),
    pretrain_context=(),
    buffer_fields=(),
    batch_keys={},
    agent_expert=None,
    takes_expert_policy=False,
    stores_expert_actions=False,
)

    Reject the extensions of stack that cannot run on agent_name, whose run has capabilities and whose code folds phases, binds the context keys, fills the pretrain_context fields, stores the buffer_fields and passes, per phase, the batch_keys beyond the common ones (:func:~ajax.extensions.capabilities.check_capabilities), or that call a stateful expert without its state (:func:check_extension_experts).

    Raises a ValueError naming every offending extension: one whose phase an agent never folds would otherwise be silently ignored. Agents call it at construction (ActorCritic.__init__).

    holds_expert ¶

    holds_expert(agent_expert, stack)

    Whether a run has an expert: the agent's expert_policy, or one an extension holds (its expert_fields). Replay keeps the raw observations and the expert flags, which only experts read, for such a run (init_buffer's include_raw_obs, include_is_expert).

    check_extension_experts ¶

    check_extension_experts(
    agent_name,
    stack,
    agent_expert=None,
    stores_expert_actions=False,
)

    Reject an extension calling a stateful expert (one with init_state, called expert(state, obs)) without its state.

    An extension calls the experts it declares (:meth:Extension.experts) on the observations it is given, where no state of the expert exists: a stateful one is allowed only as the agent's expert_policy of an agent that stores that expert's actions from its state (stores_expert_actions), for an extension that reads them (reads_agent_expert_actions). Stateless experts are always allowed.

    phase_output ¶

    phase_output(out)

    A training phase's value and metrics: it returns its value, or (value, metrics) (the module docstring).

    merge_metrics ¶

    merge_metrics(*metrics)

    The extensions' training metrics in one dict; a name two of them log raises (two extensions of one class report the same names).

    extension_key_names ¶

    extension_key_names(extensions)

    Each extension's key name, "name#occurrence": its name (its class's qualified name where it keeps the base's) and how many extensions of that name come before it in the stack, so two of one class get keys of their own.

    ajax.extensions.expert ¶

    Expert-guidance research features as composable :class:Extensions.

    • :class:OnlineBC — value-weighted decaying BC loss term.
    • :class:ImitationLoss — plain BC loss term towards the expert.
    • :class:ResidualPolicy — execute clip(a_expert + scale·a_pi).
    • :class:ExpertGains — the action sets the expert's gains (gain mode).
    • ExpertWarmup — the expert acts on a share of the warm-up steps.
    • :class:JSRLCurriculum — per-episode expert→learner handoff.
    • :class:ExpertValueMetrics — the critic at the expert's actions, logged.

    Each extension carries only frozen config on self; the maths are the functions below. The expert is SAC's expert_policy: OnlineBC, ResidualPolicy and JSRLCurriculum read the expert action SAC computes. ImitationLoss holds its own expert, and reads the actions the agent stored when that expert is the agent's.

    OnlineBC dataclass ¶

    OnlineBC(
    bc_coef=1.0, critic_warmup_frac=0.15, name="online_bc"
)

    Bases: Extension

    Online, value-weighted, warmup-decaying behavioural-cloning term.

    A bc_coef · w(s) · ||μ_θ(s) - a_expert||² penalty (:func:compute_online_bc_loss) that decays to zero once the training fraction exceeds critic_warmup_frac. It reads the actor's mean action (pi_mean), the expert's action (a_expert, which SAC puts in its actor-loss batch) and the observations from the batch, and the frozen expert critic phi with its value range (expert_critic_params, expert_v_min, expert_v_max) and the critic phi is applied with from the agent's state, which :class:MCPretrain fits (refused without it). The expert's action is the agent's expert_policy's, so an agent without one refuses it (requires agent_expert); it raises on a batch without a_expert (an agent other than SAC). Until phi* exists the term is 0.

    Bases: Extension

    Behavioural-cloning regulariser: coef · mean((μ(s) - a_E(s))²) / 4.

    Same form as the actor-side BC term of TD3+BC (Fujimoto & Gu, 2021), with a frozen expert's action as the target: μ(s) is the actor's mean action (pi.mean(), which is TD3's deterministic action), a_E(s) the expert's action, held constant: its call on the raw observation, or, when it is the agent's expert_policy, the action collection stored from its tracked state (which a stateful expert, a PID with its integral, needs). The mean runs over batch and action dims; / 4 maps the squared distance of two actions in [-1, 1] to [0, 1]. Unlike :class:OnlineBC the term is unweighted and needs no pre-trained expert critic.

    q_filter=True counts only the rows where the critic rates the expert's action above the policy's (:func:q_filter_weight, at μ(s)) and still divides by every row, as the paper's fixed λ2 = 1/N_D does: the Q-filtered BC of Nair, McGrew, Andrychowicz, Zaremba and Abbeel (ICRA 2018, Sec. IV-C, eq. 8). Deviations: replay rows labelled with the expert's action, not a demonstration buffer (the replay's expert flags would restore it); coef on the BC term, not the paper's λ1 = 1e-3 on the RL term and λ2; the policy's mean action and the minimum over the agent's critics (TD3's actor reads its first, REDQ's the mean of its ensemble), not DDPG's one critic. The filter needs a Q critic, which SAC, TD3, REDQ, ASAC and AVG put in their actor-loss batch (critic_state); a state-value critic (PPO, APO) cannot rate an action. It refuses :class:ResidualPolicy, whose critic reads the executed action. imitation/q_filter_frac logs, at each evaluation, the share of a replay batch the filter keeps (every agent but AVG, which keeps no replay).

    With anneal_frac the term is multiplied by a weight falling linearly from 1 to 0 at that fraction of training (:func:anneal_weight), as in kickstarting (Schmitt et al., 2018, Kickstarting Deep Reinforcement Learning, arXiv:1803.03835, eqs. 2-3), whose distillation weight on the teacher decays so the student ends on its own RL loss. Deviations from kickstarting: a squared error on the mean action instead of the cross-entropy between the teacher's and the student's policies (the expert is deterministic: it gives an action, not a distribution); a linear schedule set by anneal_frac instead of the weights population-based training tunes. None keeps the weight at 1.

    target="replay" clones the replayed rows' own actions (actions, which SAC, TD3, REDQ and ASAC put in their actor-loss batch) instead of an expert's: logged data needs no expert, and expert_policy may be None. alpha makes the actor loss TD3+BC's (Fujimoto and Gu, 2021), λ · (the agent's own) + coef · mean((μ(s) - a)²) with λ = alpha / mean|Q_1(s, μ(s))| (:func:td3bc_lambda), the actions compared in the env's units and without the / 4: the term adds (λ - 1) times the agent's own loss (agent_loss in its actor batch), already counted. On TD3, whose own loss is -mean Q_1, that is the paper's -λ mean Q + mean((π(s) - a)²); anneal_frac and the filter act on the cloning part only. With both, on TD3, a transition dataset trained offline (train_offline) and normalize_observations=True (the dataset's statistics, sqrt(var + 1e-8) in place of the reference's std + 1e-3), it is TD3+BC.

    TD3, REDQ, ASAC, APO, SAC and PPO put pi_mean and raw_observations in their actor-loss batch, and all but PPO (which takes no expert) the stored a_expert; an agent whose batch has no pi_mean (a discrete-action policy) raises at trace time.

    ajax.extensions.target_mods ¶

    TD-target modifier research features as composable Extensions.

    These reshape the Bellman target before it enters the critic loss (the on_target phase):

    • IBRL: add gamma (1 - d) (Q_expert - Q_policy) where the expert's next action is selected, so the value function matches an argmax action-selection policy.
    • LCBGatedBootstrap: soft-blend the policy and expert TD targets by an LCB-scored sigmoid gate.
    • CriticBlend: a warmup-decaying blend of the Bellman target with the frozen expert critic's.
    • MCVarianceCorrection: replace high-ensemble-variance Bellman targets with the MC-pretrained oracle.
    • ValueBox: a value-threshold expert action override during collection (the action phase).

    The batch on_target reads is the dict the shared critic step builds (update_steps.apply_on_target): observations, actions, next_observations, rewards (unscaled), reward_scale, dones, gamma, raw_next_observations (the environment's own next observations, which an extension's expert reads: an agent keeps them when an extension carries an expert), next_a_expert, next_actions (the next actions the target scored) and critic_subset (the target critics it took its minimum over, where a random subset: REDQ's).

With all of them, the bonus is max(min Q(s', a_E) - min Q(s', a'), 0). With a random subset of them (REDQ's), a_E is selected on a fresh subset of the same size (draw_selection_critics), as the authors select on one random pair and value on another, so the bonus can be negative.

    Selection is hard by default, the authors' "ibrl". With soft_choice it is their "ibrl_soft", in acting and in the bootstrap alike, as their act_method sets both: the expert's action is chosen with probability sigmoid(soft_choice_beta (min Q(a_E) - min Q(a'))), their softmax over the two candidates (beta 10 in their configurations), and sampled, in evaluation too (choose_expert).

    With hybrid_acting (the default) it also acts as their act_method "ibrl", as every IBRL configuration of theirs does: it executes the better of the agent's action and the expert's (choose_action), in collection (the action stage, past the warm-up) and in evaluation (eval_action). The agent's is the one it would execute (TD3's noisy action, a sample; in evaluation its mean); each is scored by the target critics' minimum, over a fresh random subset where the target takes one (REDQ's), as the authors' forward_k draws a random pair per call. The replay flags the steps the expert's action took. The actor's loss ignores the choice, as theirs; their epsilon-greedy choice (ibrl_eps_greedy, 1 in every configuration) is left out.

    No original form exists for the rest, kept as Ajax's: SAC's, REDQ's and TQC's entropy term stays at a' when the expert is selected; TQC's bonus reads its quantiles' means, while its target pools truncated quantiles; a target without next actions (IQL's V(s')) scores a sample of the online actor instead.

    Thompson-sampling gate, with optional epsilon floor on policy picks, drawn on rng.

    Treat each candidate's Q as Gaussian(mu, (temperature * sigma)^2), draw one sample per side, pick whichever is larger. Equivalent to p(use_expert) = Phi((mu_e - mu_p) / (T * sqrt(sigma_e^2 + sigma_p^2))) in expectation, but stochastic per-step (which is what we want for exploration: the gate itself injects noise rather than deferring to a fixed rule).

    EVarEst critic objective as a critic_loss extension.

    Ports the additive form of EVAREST's :func:make_evarest_loss / :func:make_evarest_ppo_loss / :func:make_evarest_td_loss. The agent's vanilla critic loss already contains MSE = bias^2 + Var(residual); this extension adds the eq. (6) extra penalty term:

    penalty(alpha) = ((1 - 2 alpha) / alpha) * Var(q_preds - target_q)

    so the total objective becomes MSE + ((1-2 alpha)/alpha) * Var(residual). alpha=0.5 ⇒ coeff 0 ⇒ identical to vanilla; alpha->0 is the AVEC limit (use a small alpha rather than zero). coeff_override lets callers fix the coefficient directly (e.g. to disable the extra penalty entirely without recomputing alpha). It rebuilds the residual the agent's MSE term sees from the critic_loss batch: observations, targets and the critic (critic_params and critic_state, with actions for a Q-critic; DQN's and PQN's q_state and actions), and raises on a batch without them rather than add 0.
