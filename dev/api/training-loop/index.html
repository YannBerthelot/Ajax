    Training loop¶

    The agents share one loop, TrainLoop: it collects experience, waits for learning_starts, folds the extensions, evaluates, logs and resumes the same way for every agent. An agent supplies only its init and update. Architecture explains how the pieces fit.

    ajax.agents.loop ¶

    The training loop the agents share.

    An agent's make_train builds a :class:TrainLoop and hands it what makes the agent its algorithm: how to initialise its state and how to update it. The loop owns everything else, the same for every agent::

    fresh run:  state = init(key), then every extension's initial state
            and one-shot pretraining
resumed:    state = the checkpointed state
iterate:    collect one step per env (off-policy) or a rollout (on-policy)
            if timestep >= learning_starts (on-policy: always):
                state, aux = update(state, experience)
                apply the extensions' post_update
            else:
                aux = the update's metrics, filled with NaN
            evaluate and log every log_frequency steps

    An off-policy agent that acts, trains and evaluates its own way (the world models: a planner or a filtered latent acts through the row collector, a train ratio schedules the updates) supplies those steps too, and the loop runs them in the same order (:meth:TrainLoop.off_policy)::

    iterate:    state, experience = collect(state, tick)
            repeat n_updates(tick, state) times:
                state, _ = update(state, experience)
                apply the extensions' post_update
            evaluate and log every evaluation.every ticks

    A replay agent given a dataset trains offline instead (:meth:TrainLoop.offline)::

    fresh run:  the replay and the normalisers start from the dataset
iterate:    state, aux = update(state, None)   # no environment step
            apply the extensions' post_update
            evaluate and log every log_frequency updates

    The result is :func:ajax.perf_utils.build_resumable_train's jitted train(key, index, initial_state, resume_from_state), which :meth:ajax.agents.base.ActorCritic.train vmaps over seeds. It returns (state, None) without a logging config, the evaluation not even traced (tracing alone rebuilds the evaluation env). With one it evaluates every log_frequency steps, whether or not a backend (W&B, TensorBoard) records the logs, and returns (state, evaluations): every logged key's values at the evaluations, in order, padded to the most a call makes with -1 (integer leaves, the timestep) and NaN. They are written into rows the scan carries, not stacked per iteration, which would cost seeds x iterations memory.

    Evaluation dataclass ¶

    Evaluation(metrics, every, evaluate=None, after_log=None)

    An agent's own evaluation, every every ticks (None: never).

    metrics(agent_state, aux) are its training metrics (timestep included), updated with its policy's evaluate(agent_state, key) when it has one and the extensions' eval_metrics; after_log(agent_state, logged) runs on every tick after the gate.

    count ¶

    count(n_ticks)

    The most evaluations n_ticks consecutive ticks make.

    TrainLoop dataclass ¶

    TrainLoop(
    env_args,
    total_timesteps,
    num_episode_test,
    extensions,
    log,
    log_fn,
    log_frequency,
    start_timestep=0,
    end_timestep=None,

    One call's environment, budget, extensions and logging (compared and hashed by identity: the environment's parameters are arrays).

    A call trains from start_timestep (a resumed run's timestep, else 0) to end_timestep (None: the horizon); total_timesteps is the run's horizon: every schedule (the extensions' total_steps, the training fraction, the logging's end) runs over the whole run, so a run split into calls follows the schedules of one call; the call's own iterations come from its :attr:budget.

    warn_if_partial ¶

    warn_if_partial(per_iteration, unit)

    Warn when the budget is not a whole number of iterations of per_iteration env steps (unit names them): the iterations stop at a multiple of it, not at the call's end, so the run trains another number of steps than asked and an evaluation due at that end never happens (its row stays NaN).

    n_rollouts ¶

    n_rollouts(n_steps, timesteps=None)

    The iterations of :meth:on_policy for n_steps rollouts over timesteps (None: the budget, warning when it is not whole rollouts): in whole rollouts, plus one (as PPO always ran).

    evaluations_until ¶

    evaluations_until(timestep)

    The most evaluations one call reaching timestep makes: ajax.log's gate counts each one as a log point, so the k-th of the run comes at timestep k * log_frequency or later, and none comes past the horizon.

    collect_kwargs ¶

    collect_kwargs(recurrent, **kwargs)

    collect_experience's arguments for this run. With the agent's expert, its action pipeline also stores the expert's actions from the expert's tracked state, the run's action extensions act on its result, gain mode actuates the chosen action through the expert, and the default pipeline runs the run's warm-up chooser (expert_collect_kwargs); without it, the action extensions acting with an expert of their own (IBRL).

    post_update ¶

    post_update(agent_state)

    :func:apply_post_update at the collector's timestep.

    maybe_update ¶

    maybe_update(
    agent_state, learning_starts, update, timestep=None
)

    update and apply post_update once timestep, by default the steps collected, reaches learning_starts; before, the metrics have the update's structure, filled with NaN (which the logger drops).

    repeat_update ¶

    repeat_update(agent_state, n, update)

    n times update then post_update; the updates keep what they log on the state. An n derived from unbatched values (the tick, static hyperparameters) keeps the loop one while under the seed vmap; one read from the per-seed state runs it to the largest count, each seed's state frozen after its own.

    evaluate_and_log ¶

    evaluate_and_log(
    agent_state,
    aux,
    index,
    recurrent=False,
    agent_metrics=None,
    **kwargs,
)

    Evaluate and log every log_frequency steps (ajax.log.evaluate_and_log), the agent's family's agent_metrics and the extensions' eval metrics included; returns the state and the metrics (None without logging), only in the last fifth of training in a sweep. An agent storing normalised observations evaluates with them normalised by its running statistics, unless its own controller says how it acts.

    evaluate_every ¶

    evaluate_every(agent_state, aux, index, tick, evaluation)

    An agent's own evaluation and logs on the ticks t with (t + 1) % evaluation.every == 0 (:func:ajax.log.maybe_eval_and_log, the extensions' eval metrics included); returns the state and the metrics (None without logging).

    continued ¶

    continued(agent_state)

    A resumed state, its training progress measured against the run's horizon (a fresh state is built with it).

    train ¶

    train(
    init,
    iteration,
    num_updates,
    last_rollout=None,
    evaluations=None,
    update=None,
    buffer=None,
    one_update=None,
    resume=None,
    returns_iterations=False,
)

    The resumable train function: init (fresh runs only), then num_updates scan iterations iteration(agent_state, index, tick), recording the evaluations when logging (see the module docstring): n_evaluations rows, or evaluations.

    last_rollout, a (length, collect_kwargs) pair, pre-allocates agent_state.last_rollout for an agent exposing its rollouts. The extensions' pretraining gets the env, update and the replay buffer (ajax.extensions.base.ExtensionContext). one_update, a state to the state after one update, is given by an update keeping its actor's last metrics: a fresh or resumed state gets their slot (with_actor_metrics_slot). resume transforms a resumed state after continued (APG rebuilds its optimiser). With returns_iterations the train function returns every iteration's output, stacked, logging or not, instead of the rows.

    off_policy ¶

    off_policy(
    init,
    update,
    learning_starts=0,
    *,
    uniform_steps=None,
    recurrent=False,
    expose_rollout=False,
    after_collect=None,
    collect_kwargs=None,
    eval_kwargs=None,
    collect=None,
    n_updates=None,
    evaluation=None,
    num_ticks=None,
    keeps_actor_metrics=False,
)

    Train on one environment step per env per iteration (a tick).

    Each tick collects a step (uniform actions before uniform_steps, by default learning_starts; 0: the policy's from the first step, as TQC's authors act), applies after_collect(agent_state, transition) when given, then from learning_starts runs update(agent_state, transition) (without a replay, from the step collected at learning_starts), then evaluates the actor (:meth:evaluate_and_log). expose_rollout keeps the step on agent_state.last_rollout as a T = 1 rollout. The budget is :attr:budget // n_envs ticks.

    An agent acting, training and evaluating its own way (the module docstring) supplies those steps: collect replaces the collection and the arguments configuring it; n_updates(tick, agent_state) updates (of the absolute, unbatched tick: a train ratio, a burst; or of the collected state: the env steps the tick took) replace the learning_starts gate (:meth:repeat_update); evaluation replaces the actor's evaluation (:meth:evaluate_every); num_ticks the budget.

    keeps_actor_metrics: the update keeps its actor's last metrics on the state (update_steps.run_actor_if), which then gets their slot. With :attr:offline_data it trains offline instead (:meth:offline).

    offline ¶

    offline(
    init,
    update,
    buffer,
    recurrent=False,
    eval_kwargs=None,
    keeps_actor_metrics=False,
)

    Train on :attr:offline_data alone, with no environment step.

    A fresh run's replay and normalisers start from the dataset's rows (:func:seed_replay). Each tick runs update(agent_state, None) on that replay, applies post_update and counts the update in the collector's timestep: the schedules run over the updates, and the evaluations (:meth:evaluate_and_log) come every log_frequency updates and log the updates done as their timestep. The budget is :attr:budget updates.

    forced_reset ¶

    forced_reset(
    agent_state, n_steps, resets_per_eval, num_evals
)

    brax's num_resets_per_eval: every env reset (:func:ajax.environments.interaction.force_reset) every reset_every updates, resets_per_eval times per evaluation after the first of num_evals.

    Playground envs draw a fresh initial state at every episode end by default (build_env_from_id(fresh_reset=True)); with fresh_reset=False their auto-reset replays the first reset state, and without these resets a run sees only n_envs initial conditions.

    on_policy ¶

    on_policy(
    init,
    update,
    n_steps,
    *,
    recurrent=False,
    expose_rollout=False,
    forced_resets=(0, 1),
    collect_kwargs=None,
    eval_kwargs=None,
)

    Train on an n_steps rollout per env per iteration.

    Each iteration collects the rollout from the agent state agent_state_at_rollout_start (collect_experience with collect_kwargs), then runs update(agent_state, rollout, agent_state_at_rollout_start), resets every env on brax's cadence when forced_resets, (resets_per_eval, num_evals), asks for any (forced_reset), and applies post_update; expose_rollout keeps the rollout on agent_state.last_rollout. The budget is n_rollouts; the last one may reach past the call's end, and evaluates there when the horizon is further.

    record ¶

    record(rows, count, metrics)

    Write metrics into row count of rows when they are an evaluation (their timestep is not the -1 sentinel), else nothing.

    Returns the rows and the count of evaluations written.

    fresh_state ¶

    fresh_state(init, extensions, total_steps, key, **context)

    A fresh run's state: init(init_key) on split(key), then the extensions' initial states and one-shot pretraining on extension_key (:meth:ExtensionStack.apply_init; context: the pretraining's static context fields).

    with_actor_metrics_slot ¶

    with_actor_metrics_slot(agent_state, one_update)

    agent_state with the slot its update keeps the actor's last metrics in (BaseAgentState.last_actor_metrics, update_steps.run_actor_if): their structure, read from the trace of one_update (a state to the state after one update), NaN until the actor's first step, so the scan carry keeps one structure from the first update. A state that has the slot keeps it.

    with_horizon ¶

    with_horizon(agent_state, env_args, total_steps)

    A state whose collector keeps the run's horizon total_steps, which a feature reading the training progress needs (:func:ajax.controller.reads_progress); a resumed run measures its progress against its own call's.

    with_obs_norm ¶

    with_obs_norm(agent_state, env_args=None)

    An agent normalising its own observations (the collector's obs_norm_info) with those statistics mirrored on its networks, which apply them; collection refreshes the mirror at every step, and setting it at init keeps the scan carry's structure fixed. An agent storing normalised observations (env_args.store_normalized_obs) gets no mirror: its networks read them as stored.

    seed_replay ¶

    seed_replay(agent_state, buffer, data, env_args)

    agent_state with data's rows in its replay, where they stay (:func:ajax.buffers.dataset.fill_replay), and in the normalisers it has (count_in_normalisers).

    count_in_normalisers ¶

    count_in_normalisers(
    agent_state,
    obs,
    rewards,
    terminated,
    truncated,
    env_args,
)

    The agent state with rows written to its replay before training counted in the normalisers it has, each row once, as collection counts its own: their observations in its own observation statistics, mirrored on its networks, and in the env's reward statistics the reward or, with the normaliser's gamma, the discounted return of the episode so far (its running return left as it is). Time runs along the first axis of the rewards and the episode ends, the envs along the others; the observations keep their columns last. A normaliser the agent lacks costs nothing.

    ajax.agents.update_steps ¶

    The steps an agent's update is written in: a loss's gradients (compute_gradients), gradient steps with the extensions' loss terms added (critic_step, actor_step, apply_gradients_clipped_together for two networks clipped together), the extensions' target and post-update phases, the gates (run_if, run_actor_if) and keys (derive_extensions_key) around them, which ajax.agents.loop re-exports, and the target critics' Polyak update SAC, ASAC, REDQ and TQC share (update_target_networks).

    apply_post_update ¶

    apply_post_update(
    extensions, agent_state, step, total_steps
)

    Apply the extensions' post_update at step on a key derived from the updates' stream, which it leaves as it was: a run with extensions draws every other key as the run without them.

    derive_actor_key ¶

    derive_actor_key(agent_state)

    The key of an actor step that counts on some updates only (a policy delay, policy_update_start), derived from the updates' stream without advancing it: the stream's next keys are the same whether the step ran, or ran and was dropped, and a dropped step's keys are never drawn again.

    scan_on_indexed_keys ¶

    scan_on_indexed_keys(step, agent_state, length)

    final_aux_scan of step(agent_state, None) -> (agent_state, aux) over length steps, the i-th on the updates' stream restarted from one of its keys folded with i; then the stream goes on after that one key. It advances once whatever the length, so a count of steps (SAC's and REDQ's critic updates, DQN's gradient steps) moves no later draw.

    run_if ¶

    run_if(condition, update, state)

    update(state) where condition holds, else state unchanged: a policy delay, a target refresh, a warm-up. state is any tree: an agent's state, or one network's (DQN's target refresh).

    update returns the new state, or the new state and its metrics. Skipped, the metrics have update's structure, read from its trace (with the names the extensions log): NaN, -1 in integer leaves (ajax.log.unevaluated), which the logger drops; an actor's step keeps its last metrics instead (run_actor_if). A condition that is the Python True runs update with no gate. Under the seed vmap a condition read from per-seed state runs update every time and selects; one from unbatched counters runs it only where it holds.

    reached ¶

    reached(start, timestep)

    Whether timestep has reached start, the env steps an update step waits for (policy_update_start): the Python True, with nothing traced, when start is 0 or less, so an agent without the wait runs the program it ran before it had one.

    all_of ¶

    all_of(*conditions)

    Whether every condition holds; the Python Trues among them (no gate) add nothing to the program, and with nothing else left it is True.

    run_actor_if ¶

    run_actor_if(condition, update, agent_state)

    update(agent_state) -> (agent_state, metrics), an actor's step, where condition holds (a policy delay, policy_update_start). Skipped, agent_state is unchanged and the metrics are those of the actor's last step that ran, which the state keeps (last_actor_metrics, whose slot the training loop gives it): a skipped update logs the last real step, not NaN or zeros (owner, 2026-10-24), and NaN, which the logger drops, before the first. Without a gate (condition the Python True) update runs as it is and nothing is kept.

    derive_extensions_key ¶

    derive_extensions_key(key)

    The extensions' key of a step on key, which the step's own draws (on key and the keys it splits off it) never get.

    compute_gradients ¶

    compute_gradients(loss, params)

    The gradients of loss at params, and what loss returns beside its value.

    loss takes the parameters alone and returns (value, aux): the number to minimise and what to keep from computing it (its metrics). An agent fixes the loss's other inputs first, in a small local function. params is one network's parameters, or a tuple of several networks' (APO's summed loss), and the gradients have the same structure. A caller that logs the loss's value puts it in aux.

    gradient_step ¶

    gradient_step(train_state, loss_fn)

    One optimiser step down loss_fn(params) -> (loss, aux).

    Returns the stepped train state, the loss's aux and the global norm of the gradients, before any clipping the optimiser does (a caller that does not log it leaves it to dead-code elimination).

    apply_on_target ¶

    apply_on_target(
    extensions,
    agent_state,
    batch,
    target_q,
    key,
    total_timesteps,
    *,
    rewards,
    dones,
    gamma,
    reward_scale,
    next_actions=None,
    critic_subset=None,
)

    target_q with the extensions' on_target applied, no gradient flowing back through it (stop_gradient), and their metrics: critic_step's first half, which an agent whose target comes out of its own critic pass (CrossQ) calls inside its loss.

    batch is a Transition. rewards, dones (where the bootstrap is cut), gamma (None for an average-reward agent), reward_scale and next_actions (the next actions the target scored; None for a target scoring a state value, IQL's V(s')) and critic_subset (the indices of the target critics whose minimum it took, REDQ's random subset; None for a target over all its critics) are what the target used. The phase draws on a key derived from key, the step's (derive_extensions_key).

    compute_extensions_critic_loss ¶

    compute_extensions_critic_loss(
    extensions,
    agent_state,
    batch,
    params,
    target_q,
    key,
    total_timesteps,
)

    The extensions' critic_loss terms at the critic's params (the differentiated ones) on batch against target_q (no gradient flows back through it), and their metrics: critic_step's second half, on a key derived from key, the step's.

    critic_step ¶

    critic_step(
    agent_state,
    batch,
    target_q,
    value_loss,
    extensions,
    key,
    total_timesteps,
    **target_args,
)

    A replay agent's critic step on batch (a Transition).

    Applies the extensions' on_target to target_q, no gradient flowing back through it (apply_on_target, which target_args reach: what the target used), then steps the critic down value_loss(params, target_q) -> (loss, aux) plus their critic_loss terms (compute_extensions_critic_loss). The phases draw on keys derived from key, the step's, on which the agent may draw too. Returns the stepped critic state, aux, the gradients' norm (gradient_step) and the two phases' metrics.

    actor_step ¶

    actor_step(
    agent_state,
    policy_loss,
    extensions,
    key,
    total_timesteps,
    batch,
    critic_state=None,
)

    A replay agent's actor step on batch (a Transition).

    Steps the actor down policy_loss(params) -> (loss, aux, pi_mean) (pi_mean: the policy's mean action at the rows, None for a discrete policy) plus the extensions' actor_loss terms, on a key derived from key, the step's (derive_extensions_key). Their batch holds the rows' entries (REPLAY_ACTOR_KEYS: their observations, raw observations, actions and the expert's stored actions a_expert, and critic_state, the critics the agent's loss reads, None where it reads none), with the differentiated actor_params, the actor_state, pi_mean and agent_loss. An extension reads only the keys the agent declares (phase_batch_keys), those its rows hold. Returns the stepped actor state, aux, the gradients' norm (gradient_step) and the phase's metrics.

    clip_global_norm ¶

    clip_global_norm(grads, max_norm, eps=0.0)

    grads (any tree) times min(1, max_norm / (norm + eps)), their global norm taken over every leaf at once; None leaves them.

    With eps 0 it is tf.clip_by_global_norm, ppo2's (baselines ea25b9e ppo2/model.py:105-107); torch's clip_grad_norm_, which APO's reference code calls, adds 1e-6 to the norm (torch 1.5.1, torch/nn/utils/clip_grad.py:33-37).

    apply_gradients_clipped_together ¶

    apply_gradients_clipped_together(
    actor,
    critic,
    actor_grads,
    critic_grads,
    max_grad_norm,
    norm_eps=0.0,
)

    One Adam step of each network, their gradients first clipped together to one global norm (clip_global_norm), as ppo2's single optimiser and APO's reference code clip every parameter's gradient at once. Adam works per coordinate, so the two Adams act as one over the whole model.

    Returns the stepped actor and critic, then each one's gradient norm before the clip.

    update_target_networks ¶

    update_target_networks(agent_state, tau)

    Polyak-average the target critics towards the critics.

    ajax.perf_utils ¶

    Shared JAX-pure performance helpers for Ajax agents.

    Patterns the perf audits found across agents (PERFORMANCE_LOG.md), written once so a fix lands in one place instead of in every agent's train_*.py.

    build_resumable_train ¶

    build_resumable_train(
    *,
    init_fn,
    make_scan_fn,
    num_updates,
    resume_transform=None,
    carry_out=None,
)

    Build the canonical init-or-resume + lax.scan inner train fn.

    Every Ajax agent shares this skeleton, written once here so it cannot drift between agents: build a fresh agent_state with init_fn (its one-shot initialisation included, so a continued run does not re-run it) or, with resume_from_state=True, reuse the initial_state handed in from a checkpoint; then jax.lax.scan the per-iteration body num_updates times, its input the iteration index. Each agent's make_train keeps its own setup (networks, optimisers, action pipeline, logging) and hands the pieces over.

    The returned train function has the signature

    train(key, index=None, initial_state=None, resume_from_state=False,
      iteration_offset=0, shared=None)

    and is jitted with resume_from_state static (the init-fresh vs load-from-checkpoint branch is dead-code-eliminated) and initial_state donated: XLA reuses the incoming agent-state buffers on the resume path, saving one agent state of peak memory (donating None, the init path, is a no-op).

    The scan input is the iteration index iteration_offset + arange(num_updates): a resumed run passes the number of iterations already done so the body sees absolute iteration indices and every schedule computed from them (seed phase, update bursts, static resets, logging cadence) continues instead of restarting. A passed offset is a traced scalar (one compilation serves every offset) and must be unbatched -- pass it through jax.vmap with in_axes=None -- so the index, and every predicate derived from it, stays unbatched under the seed vmap. The default (the Python int 0, not passed) adds nothing to the program.

    shared is an optional pytree the body reads but never carries -- an offline dataset, say -- handed to make_scan_fn as the keyword argument shared (only when it is not None, so builders that do not take it are unchanged). Pass it through the seed vmap with in_axes=None: it then enters the compiled program once, as an argument shared by every seed. Closing over it instead would bake it into the program as a constant (HLO bloat, a recompilation per dataset), and a batched argument would copy it per seed.

    final_aux_scan ¶

    final_aux_scan(body, init_carry, length, xs=None)

    Run lax.scan and expose only the final-step aux from the body.

    Replaces the common idiom

    carry, ys = jax.lax.scan(body, init, xs, length=length)
last_aux = jax.tree.map(lambda x: x[-1], ys)

    with a carry-only variant that never materializes the leading scan axis on device for the aux. Critical under vmap-over-seeds because the discarded ys dimension would otherwise grow as [seeds, length, *aux_shape] purely to be thrown away.

    The body maps (carry, x) -> (new_carry, aux), aux a pytree of arrays (any structure).

    get_keys_and_new_state ¶

    get_keys_and_new_state(n=1)

    Draw n fresh random keys from the updates' key (rng).

    Returns the drawn keys, then a new agent state whose key has moved past them: shuffle_key, agent_state = agent_state.get_keys_and_new_state(). The new key is the carry, taken first (random_keys.split_carry_first), so a step drawing one key more or less leaves the stream's next keys as they were. The state it is called on is untouched (it is frozen), so drawing from it again would hand out the same keys: carry on with the state returned.
