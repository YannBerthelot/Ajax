    Changelog¶

    Versions follow semantic versioning; before 1.0, a breaking change bumps the minor version. Each release is tagged vX.Y.Z on main and published to PyPI as ajax-rl.

    Unreleased¶

    The next release is 0.6.0: the first item changes results.

    • New: agent.render(state, path) saves an episode of the trained policy as an animation: a GIF on the gymnax tasks gymnax draws, on MuJoCo Playground and on the mujoco: tasks, an interactive page on Brax (Train, evaluate, deploy, "Watch the policy"). The new render extra installs what the gymnax drawings need: matplotlib and Gymnasium's classic-control drawings.
    • New: ajax.wrappers.ObservationWrapper, a base class whose observation(obs) changes every observation, the one an episode's end leaves in the info included. A wrapper changing only what reset and step return trained on two kinds of observations, with no error (Environments, "Changing the observations"). The memory guide trains on a CartPole with hidden velocities built with it.
    • Sweeps on every agent of the shared loop. train(sweep=...) now varies numbers on APO, ASAC, AVG, DAgger, DQN, IQL, PQN, REDQ, RVI-SAC, TD3, TQC and UDRL as on SAC and PPO; agent.sweepable_fields() lists each agent's. A class declares the fields it defines (sweepable), a mixin its own, and an agent takes the union, less those it refuses with a reason (unsweepable). One test checks every declared field of every agent against separate runs. Not yet: CrossQ, the world models and APG, and fields whose optimiser or schedule is built with the agent (DQN's and CrossQ's learning_rate, the exploration's epsilon_decay_frac).
    • More checks, after a third newcomer trial:
      • an expert whose action drops its last axis is refused where Ajax first calls it, naming the expert and the axis (before, a broadcasting error, or a silent broadcast);
      • LoggingConfig(backends=TensorBoardBackend(...)), without the tuple, shows the tuple to write;
      • train refuses a keyword it does not take before anything starts, naming the one meant (logging: logging_config);
      • a dataset whose rows do not fit the agent's environment says so, and a gymnax environment with a step of its own (bsuite's DeepSea) names the two lines that build it;
      • the docs give each expert piece's module, how to record a trained agent's policy, what the seeds of a resuming call do, and what render needs for MinAtar (nothing) and Brax (the internet).
    • Clearer errors and checks, after a second newcomer trial:
      • an unknown environment id names the closest ids, and an unknown agent argument the closest arguments (learning_rate: actor_learning_rate, critic_learning_rate);
      • an agent on the wrong kind of actions names the agents that fit;
      • a mujoco: id without MuJoCo names the playground extra, and a Gymnasium environment outside the gymnasium extra (LunarLander's Box2D) no longer points at that extra;
      • predict checks the observation's shape, policy and predict refuse a seed_index the state does not hold (it returned an action before), policy.act refuses an observation without a row per environment, and evaluate, policy and predict say so when given train's evaluations instead of its state;
      • image observations read by an MLP warn and name the cnn_image_shape to pass, and one in another order than the environment's (channels first) raises;
      • a budget below one rollout warns that no evaluation is recorded.
    • Docs: where each source lists its environment ids, a hand-written loop for one environment with a recurrent policy, and PPO's rollout count corrected (Training).
    • New: a sweep reads by configuration. A sweep's default progress shows a line per configuration under each evaluation, and agent.by_configuration(evaluations.returns) gives each configuration with its rows, one per seed.
    • New: print(agent) shows the call that builds it, with the arguments that differ from their defaults.
    • Docs: writing your own environment has its own example (Environments), which says that gymnax applies the time limit: step_env returns the termination only. The sweep, save and load, TensorBoard and hand-written loop pages are corrected after a newcomer trial.

    • New: train(precision=...) runs the networks in bfloat16. Mixed precision: parameters, gradients and optimiser stay float32, the layers compute in bfloat16, every network returns float32. "auto" uses bfloat16 only where every device has bfloat16 units (NVIDIA compute capability 8.0 or more, TPU) and float32 elsewhere; "bfloat16" forces it; None (the default) is each agent's original precision, float32 for all for now, so nothing changes unless asked. The run config records the result. DreamerV3, whose original computes in bfloat16, stores its replay latents in the compute dtype: half the replay, without loss (docs/guide/performance.md, "bfloat16").

    • Changed: a resume holds no second copy of a large replay. A checkpoint now stores its arrays of 16 MiB or more after the pickle stream, and a restore copies each from the file straight to where the state keeps it (a 10-seed DreamerV3 replay in host memory: 80 GiB, held once instead of up to three times). load_checkpoint and load no longer keep the file's state while restoring it. Checkpoints written before still load. Upgrade note: a checkpoint holding such an array is no longer one pickle stream: read it with restore_into, load_checkpoint or load, not pickle.load, and an older Ajax cannot read it.

    • Fixed: a forced reset kept the reward normaliser's running return. With normalize_rewards and forced resets (num_resets_per_eval), the abandoned episodes' discounted return carried into the new episodes' rewards and statistics. It now restarts at zero, as SB3's VecNormalize.reset does; the statistics stay.

    • Deprecated: LoggingConfig(sweep=...) is now evaluate_last_fifth_only. The flag evaluates only in the last fifth of training; its name was also that of train(sweep=...), which trains several configurations in one program. sweep=True is still accepted: it warns (FutureWarning), sets the new field and reads False afterwards. Upgrade: rename the argument, and read evaluate_last_fifth_only.

    • DQN's Atari preset holds epsilon at 1 during the warm-up. Mnih et al.'s code starts the decay after its 50,000 warm-up steps and ends it a million steps later (google-deepmind/dqn@9d9b1d1, NeuralQLearner.lua:369-371); the preset decayed from step 0 to the same end, so its epsilon was up to 0.043 lower in between. DQN gains epsilon_decay_start (0 by default: other runs are unchanged), which the preset sets to 50,000 with epsilon_decay_frac=0.02. Upgrade: for the earlier schedule, pass epsilon_decay_start=0, epsilon_decay_frac=0.021 to DQN.preset("Atari", ...).

    • Fixed: n-step rewards were clipped after the sum. With n_step above 1 and normalize_rewards, each reward of a row is now divided and clipped at 10 before the discounted sum, as collection clips it and as SB3's NStepReplayBuffer does. Results change only where a normalised reward exceeds the clip.

    • agent.policy's act refuses a missing reward after an episode's first step. A policy that reads the last reward (PreviousReward, on by default with memory on SAC, TD3, REDQ, ASAC, TQC and RVI-SAC; UDRL) read zero when act was given neither done nor reward. Upgrade: pass done and reward to every act after the first.

    • Fixed: PreviousReward read the normalised reward in training. With normalize_rewards, collection appended the normalised reward where an evaluation and agent.policy append the environment's own, about 35 times apart on Pendulum. Collection now appends the environment's own. Recurrent SAC, TD3, REDQ, ASAC, TQC and RVI-SAC add the feature by default, so their results with normalize_rewards change.

    • Fixed: CloningPretrain made APO and AVG normalise observations twice. APO with normalize_observations and AVG store normalised observations; cloning also put the dataset's statistics on their networks, which normalised them again, and dropped observation_clip. Their results with CloningPretrain change.

    • PPO clips its value loss, as ppo2 does. Each squared value error is the larger of its own and that of the value clipped to clip_range around the value the rollout was collected with (Baselines' ppo2, model.py:66-75; PureJaxRL's recurrent PPO does the same). The new clip_value_loss turns it off; by default (None) PPO clips, except with unroll_length, Brax's PPO, which does not. PPO's results change. Upgrade: pass clip_value_loss=False for the old loss.

    • PPO steps TensorFlow 1's Adam, as ppo2 does. ppo2's tf.train.AdamOptimizer adds epsilon to the square root of the second moment before the bias correction; optax's Adam adds it after, an epsilon 32 times smaller at the first step and about the same after a few thousand. The new update rule "tf1_adam" (OptimizerConfig, ajax.networks.utils.scale_by_tf1_adam) is PPO's; with memory or unroll_length PPO keeps optax's Adam, as PureJaxRL and Brax use it. PPO's results change. Upgrade: no option restores optax's Adam on feedforward PPO; compare with runs of this version.

    • PreviousAction() appends the action executed before each observation (ajax.extensions.observe): zero at an episode's first observation, in agent units, a discrete action one-hot, never normalised. Collection stores it, and evaluation and agent.policy append it as collection does, so an actor with memory can read its own past actions, as Ni et al. (2022)'s recurrent actor does; a recurrent Q-critic then reads it from the observation instead of appending its own. It is opt-in: default runs do not change. Observation features read the action through ObserveInputs.previous_action.

    • PreviousReward() appends the reward paid for the action executed before each observation (ajax.extensions.observe), raw, zero at an episode's first observation, as Ni et al.'s recurrent networks read it. Collection stores it, evaluation appends it, and agent.policy's act reads the reward it is given (it refuses done without reward). Features read it through ObserveInputs.previous_reward. APG refuses it: its closed-loop rollout passes the features no reward yet.
    • Breaking: SAC, TD3, REDQ, ASAC, TQC and RVI-SAC with memory= build Ni et al. (2022)'s recurrent networks (twni2016/pomdp-baselines, the owner's reference for them; TQC and RVI-SAC by analogy). The memory reads the previous action, the previous reward and the observation through embeddings of 16, 16 and 32 units; a run with memory adds PreviousAction() and PreviousReward() where its extensions hold neither, so agent.policy's act needs each reward. The memory is 128 units wide and starts as Ni et al.'s unless the MemoryConfig sets them. The networks' layers run after the memory, on its output joined with a shortcut embedding of the observation (the critic's with the action asked about), and the critics read one memory. Every layer starts as Ni et al.'s. NetworkConfig gains input_embedding, shortcut_widths, embedding_kernel_init and critics_share_encoder; MemoryConfig.hidden_size defaults to None, the agent's reference width (64 where an agent has none, as before). Upgrade: a checkpoint of one of these agents trained with memory does not restore into this version: its parameters are another network's. Retrain, or pin the previous version to use it.
    • Breaking: their replay takes Ni et al.'s windows: burn_in=0 (was 8), sequence_length=64 (was 16) and, with memory, batch_size=64 windows (was 256). batch_size now defaults to None: 256 rows without memory, as before. A window's first row reads no previous action or reward (Ni et al.'s a[0] = r[0] = 0), unless the window starts from a stored memory. Upgrade: pass burn_in=8, sequence_length=16, batch_size=256 to train as before.
    • Recurrent TD3 is Ni et al.'s: its actor maximises min(Q1, Q2), and policy_delay defaults to None, 2 without memory as before and 1 with it; with memory, TD3's and REDQ's critics read the agent's [-1, 1] actions, not the env's units. Results with memory change. Upgrade: pass policy_delay=2 for the delayed actor; the critics' action units have no option.
    • Recurrent SAC's numerics are Ni et al.'s: with memory, the squashed log-density subtracts log(1 − tanh² + 1e-6) (also TQC's and RVI-SAC's; REDQ's and ASAC's already did), the critics' squared errors are summed, and the temperature steps alpha on the actor loss's own log-densities. Results with memory change, and no option restores the earlier numerics.

    • SAC, TD3, REDQ, TQC, ASAC and RVI-SAC can share a memory. With share_encoder=True, memory= and PreviousAction(), the critic's encoder and memory block read the observation and the previous action for both networks, as Ni et al.'s shared recurrent network does; the action the critic is asked about joins after the memory. The critic's loss trains it and the actor reads it without a gradient. Without PreviousAction() the agent refuses a shared memory.

    • Three defaults now come from the agents' reference code. An audit of every agent's defaults against its original code found these without a source:

    • SAC's actor and temperature step from the first update, as softlearning's do; policy_update_start and alpha_update_start were 2,000. Default runs do not change (the warm-up is 10,000 steps); runs with a shorter learning_starts do. Upgrade: pass both at 2,000 for the old behaviour.
    • REDQ warms up for 5,000 steps (learning_starts), its official code's start_steps, not 10,000. Upgrade: pass learning_starts=10_000.

    • DAgger's expert share falls linearly from 1 to 0 over 15 iterations, the reference code's LinearBetaSchedule(15). beta_decay becomes beta_schedule: LinearBetaSchedule(rampdown_rounds) or ExponentialBetaSchedule(decay), both in ajax.agents.DAgger.DAgger. Upgrade: beta_decay=d becomes beta_schedule=ExponentialBetaSchedule(d); the old default was ExponentialBetaSchedule(0.0).

    • DAgger fits its policy as its reference code does. At the end of each iteration of iteration_steps steps, it trains for 4 epochs over every state the replay holds, in shuffled minibatches of 32 (HumanCompatibleAI/imitation's DAggerTrainer); before, it took one gradient step per environment step. Its policy is a Gaussian with one learned standard deviation per action dimension (categorical for discrete actions), fitted by likelihood with an entropy bonus of weight 1e-3, and it acts by sampling; before, it was deterministic and fitted by squared error. This changes results. The new fit argument picks the fit: IterationFit(epochs=4, entropy_weight=1e-3), the default, or OnlineFit(), the earlier one; both are in ajax.agents.DAgger.DAgger. DAgger takes no train_frequency: its fit sets it. Upgrade: pass fit=OnlineFit() for the old behaviour, and to restore a DAgger checkpoint saved before this release.

    • normalize_rewards divides by the discounted return's spread and clips, as SB3's VecNormalize does. It divided each reward by the running standard deviation of the single-step reward, which is 0 for a constant reward (CartPole, MountainCar, Acrobot): every reward became ±10,000, and recurrent PPO with normalised rewards failed masked CartPole. reward_normalization_gamma now defaults to the agent's gamma (0.99 for APO, ASAC and RVI-SAC), and normalised rewards are clipped to ±10, at collection, at replay sampling and in evaluation. This changes results for runs with normalize_rewards=True. Upgrade: pass reward_normalization_gamma=0 to divide by the single-step reward's standard deviation again (now clipped).

    • PPO normalises observations and returns by default, as ppo2's MuJoCo run wraps its env in VecNormalize: normalize_observations=True, normalize_rewards=True (the return's spread, with gamma, clipped at 10) and the new observation_clip=10.0, which on-policy agents take (replay agents refuse it). This changes PPO's results. A sweep no longer varies gamma while the reward normaliser discounts with it; set reward_normalization_gamma to sweep it. Upgrade: pass normalize_observations=False, normalize_rewards=False for the old behaviour.
    • PPO's defaults are ppo2's MuJoCo run: one env (was 4) and 64-64 tanh layers (was 128-128), so 2048 steps make ppo2's 32 minibatches of 64. This changes results. Upgrade: pass n_envs=4, actor_architecture=("128", "tanh", "128", "tanh"), critic_architecture=("128", "tanh", "128", "tanh").
    • APG's in-context controller, IQL and PQN follow their reference code.
    • APG.contextual_controller builds the reference's transformer layers: no bias outside the input embedding, LayerNorm epsilon 1e-5, and an MLP four times as wide (buswayne/in-context-controller, --bias False). MemoryConfig gains bias, layer_norm_epsilon and mlp_ratio, whose defaults keep every other memory unchanged. Upgrade: a controller saved before restores with bias=True, layer_norm_epsilon=1e-6, mlp_ratio=2.
    • IQL's actor learning rate decays to 0 by a cosine over the run's updates, its reference Learner's default (actor_lr_decay="cosine"). A run split into calls passes its whole horizon (total_timesteps) to each. Upgrade: actor_lr_decay=None keeps the rate constant, as the reference's fine-tuning config does; pass it to fine-tune a state trained offline.

    • PQN's defaults are purejaxql's MinAtar config: 128 envs of 32 steps, 2 epochs of 32 minibatches, RAdam at 5e-4 decayed linearly over the run (lr_linear_decay), epsilon decaying over the first 10% of the run. Upgrade: n_envs=8, n_steps=128, n_epochs=4, num_minibatches=4, learning_rate=2.5e-4, lr_linear_decay=False, epsilon_decay_frac=0.5.

    • DQN's defaults are CleanRL's dqn.py (cleanrl fe8d8a0), its vector-observation reference: a 120-84 ReLU network (was 128-128), a replay of 10,000 (was 100,000), batches of 128 (was 64), 10,000 warm-up steps (was 1,000), one update every 10 environment steps (was every iteration) and a target refresh every 50 updates (was 500), CleanRL's 500 environment steps. The authors' centered RMSProp and Huber loss stay. This changes results. Upgrade: pass architecture=("128", "relu", "128", "relu"), buffer_size=100_000, batch_size=64, learning_starts=1_000, train_frequency=1, target_update_interval=500 for the old behaviour.

    • Replay agents take train_frequency, SB3's train_freq: from learning_starts, an update each time the steps collected reach a multiple of it. The default, 1, updates every iteration, as before, on every agent but DQN. An evaluation between two updates logs the last one's training metrics.

    • APO's defaults are its reference code's MuJoCo config (xtma/apo, mujoco_appo.py): rollouts of 10 envs x 200 steps (was 4 x 2,048), 20 minibatches per epoch (num_minibatches=20; was cut by batch_size), advantages not normalised (was normalised) and nu=1.0 (was 0.1). This changes results. A rollout's n_steps * n_envs must now be a multiple of num_minibatches; num_minibatches=0 cuts it by batch_size as before. To reproduce earlier runs, pass n_envs=4, n_steps=2048, num_minibatches=0, batch_size=64, normalize_advantage=True, nu=0.1. The benchmark's APO entry runs 500 such rollouts, evaluated every 20,000 steps, as the reference.

    • Per-task presets. Agent.preset(name, env_id, **overrides) builds an agent with the values its reference code tunes for one task, named after the task ("Hopper", "AntMaze", "Atari") rather than an env id; the arguments given win, and the run config records the name under "preset". Each agent module keeps its presets, with their sources, in a PRESETS table: ASAC's ten Gymnasium MuJoCo tasks, TQC's and REDQ's five MuJoCo tasks, CrossQ's Swimmer, IQL's AntMaze, TD3's D4RL (TD3+BC), PPO's, PQN's and DQN's Atari, PQN's CartPole, and DreamerV3's DMC, whose values the world-model paper protocol now reads. No default changes.
    • Hyperparameter sweeps in one program. agent.train(seed=..., sweep={"actor_learning_rate": [1e-4, 3e-4]}) trains several configurations, each with every seed, in one compiled program, as PureJaxRL does by vmapping over hyperparameters. Each member trains as a separate run of its configuration would, up to floating-point rounding, and agent.members lists the seed and values of each leading row. SAC and PPO declare which fields can vary (their learning rates, gamma and the like); other agents, and settings that change shapes, are refused. To allow it, PPO's GAE no longer takes gamma and gae_lambda as static jit arguments; results are unchanged.
    • DreamerV3 can keep its replay latents in host memory. With replay_on_host=True, the posterior latents stored with each replay row (about 99% of the replay's bytes: 8 GB per seed for 2^20 rows at 12M) stay in pinned host memory, inside the training state, so that more seeds fit on one accelerator, or a run fits on a busy one. Results are bitwise those of the default; each update is a little slower. A checkpoint restores each array into the memory its skeleton keeps it in, so a resumed run keeps the latents on the host.
    • The actor and the critic can share their encoder; image PPO now does by default. PPO, APO, SAC, TD3, REDQ, TQC, ASAC, RVI-SAC, AVG and IQL take share_encoder. With True the two networks read the observations through one encoder (the hidden layers or the CNN, and with PPO or APO the memory block). The critic owns it, and the actor reads a copy refreshed after every update. PPO and APO train it with both losses, as ppo2's one network; the off-policy agents with the critic's loss alone, the actor reading it without a gradient, as SAC-AE and DrQ do; their encoder is actor_architecture, and the critic's critic_architecture layers read its features with the action. None, the default, follows each agent's reference code: PPO shares its CNN, as ppo2 and CleanRL do on Atari; every other network stays apart, as before. This changes the results of PPO with cnn_image_shape.
    • Upgrade: to resume an image PPO checkpoint saved before, or to keep the earlier networks, pass share_encoder=False.
    • Recurrent PPO's heads each read the memory through a layer of their own, as PureJaxRL's recurrent PPO does (ppo_rnn.py: a Dense(128) and a ReLU per head, orthogonal with gain 2). The new NetworkConfig.head_architecture gives any agent's networks such hidden layers after the encoder and the memory block, and head_kernel_init their initialiser. This changes the results of PPO with memory. Its actor and critic keep separate memories: a shared one fails the memory probe, even with these layers.
    • Upgrade: to resume a recurrent PPO checkpoint saved before, or to keep the earlier networks, set agent.network_args = agent.network_args.replace(head_architecture=()).
    • DreamerV3 trains faster on the GPU. The world model's gradient through its 64 filtering steps now takes each RSSM weight's gradient once per update, as one product over all steps, instead of adding 64 small per-step products. Results are the same up to floating-point rounding. On a shared L40S (MuJoCo Warp Hopper), an update took 6-10% less time at 1 and 2 seeds; it has not been timed on a machine with no other job. It uses about 0.2 GB more GPU memory per seed, and the CPU bench's DreamerV3 run is about 6% slower.
    • The playground extra allows MuJoCo up to 3.15. It held mujoco and mujoco-mjx below 3.10 for one bug: Playground 0.2 compares MuJoCo versions as strings, so its ReacherEasy and ReacherHard failed on 3.10 and later with 'MjSpec' object has no attribute 'find_body'. As a deliberate workaround, Ajax now gives Playground's Reacher builder upstream's fix (Playground commit 33f1b284), only while the installed Playground still compares strings; it goes once a Playground 0.x release holds that commit. Every Playground task, Reacher included, takes MuJoCo 3.6 to 3.15 (MuJoCo Warp computes contact forces from 3.14).
    • MEW temperature annealing. MEW() (Adamczyk et al., 2026) lowers the temperature of a maximum-entropy agent (SAC, ASAC, AVG, CrossQ, REDQ, RVI-SAC, TQC) at a pace set by how much its recent rewards vary, in place of the agent's own temperature rule. It is opt-in: no agent's default changes. Other agents refuse it, naming the entropy_temperature capability they lack.
    • Logged runs evaluate between training chunks. With a LoggingConfig, training runs up to each evaluation as one compiled chunk, and the evaluation runs between chunks as a program of its own, as Brax does. Before, the evaluation sat inside every training step, which slowed the steps between evaluations too. Evaluations come at the same steps as before, with the same results up to floating-point rounding. On MuJoCo Warp (L40S, 10 seeds), a million-step run evaluated every 10,000 steps took 4% less time with SAC and 1% less with PPO.
    • Faster REDQ, and SAC without its unneeded gates. REDQ evaluates only the 2 target critics its target draws, as its official code does (Ajax evaluated all 10), and its 20 critic steps no longer copy every critic at each step. SAC no longer checks its 2,000-step actor and temperature starts at every update when, as by default, its updates start later. Results are the same up to floating-point rounding. At 10 seeds on a GTX 1080 Ti, REDQ took 20% less time and SAC 5% less; REDQ took 10% less on a CPU.
    • Datasets load into the replay in one step. train_offline, PriorData and retained data used to write a dataset into the replay one row per env at a time, which took about 20 s per million rows on a GPU. They now write it at once, with the same result. IQL's offline run on a million rows (1080 Ti, 2,000 updates) went from 17 s to 3 s. fill_replay(buffer_state, data) and seed_replay(agent_state, data, env_args) no longer take the replay's buffer: drop that argument.
    • Evaluation on another device. LoggingConfig(evaluation_device=...) scores each evaluation in a thread on that device, a second GPU or the CPU, while training goes on. The scores are those of the evaluation in place, and they reach the backends under their own timestep. It is opt-in: by default training still waits for each evaluation.
    • Training on MuJoCo Warp. On an NVIDIA GPU, agents now train on Playground tasks and the "mujoco:" tasks built with build_env_from_id(..., physics="warp"), about five times faster than on pure JAX for SAC and PPO on an L40S. Every online continuous-action agent was checked. Before, every agent failed on its first step: the auto-reset merged each physics array env by env, and Warp keeps its contact buffer for the whole batch of environments. That buffer now passes through the reset. Warp refuses a MuJoCo before 3.13 (the first whose Warp reports the convex collisions it drops), a CPU, differentiable_reset=True and APG, saying why. Pure-JAX runs are unchanged.
    • Warp's contact room. MuJoCo Warp keeps one contact buffer for all the worlds a run steps at once (seeds times envs). The "mujoco:" tasks left it at MuJoCo Warp's default, 48 contacts in all, which 47 Hopper worlds overflowed, and Warp then drops contacts with only a printed warning. They now give it 49,152 (1,024 worlds of 48), and a Warp step that runs out of contact or constraint room stops the run with an error.
    • Warp's convex-collision room. MuJoCo Warp sizes the buffer of its convex (GJK/EPA) collisions like the contact buffer unless told, and each physics call allocates scratch for every slot: 320 MB on "mujoco:Pusher-v5".     Upgrading from 0.5.0¶

    The default changes above each end with an "Upgrade:" line giving the arguments that restore the earlier behaviour: PPO (value clip, normalisation, one env and 64-64 layers), DQN, PQN, APO, REDQ's warm-up, DAgger's fit and beta_schedule, normalize_rewards, and the recurrent SAC family's networks and windows. Checkpoints of recurrent SAC-family agents and of DAgger saved before this version do not restore at the new defaults. The rest:

    • An expert must keep its action's last axis, as the expert guide has asked: expert(obs) returns (..., action_dim), an index column (..., 1) on discrete actions. One that returned (...,) and ran by broadcasting is now refused; add [..., None].
    • On-policy runs train one rollout fewer per train call, so their results move a little. A call asked for 8,192 steps of 1,024-step rollouts now stops at 8,192, not 9,216. What to do: compare with runs of this version. Code that took a second call's budget from the timestep reached can pass the run's remaining budget instead.
    • JSRLCurriculum follows its paper by default. It read a default of 1000 steps and fell with time. It now reads the horizon from the task and moves to the next stage when a moving average of the combined policy's evaluations comes within a tolerance of its best. schedule="random" is JSRL-Random. To keep the old form, pass schedule="time": decay_frac alone now raises. eval_episodes now defaults to 1, Ajax's value and not the paper's, since each evaluation spends steps on the plant. What to do: pass eval_episodes=10 for the old gate.
    • ResidualPolicy keeps the expert during the warm-up. Its warm-up executed uniform actions without the expert; it now draws uniform residuals around it. zero_start=True starts the policy as the expert, and critic_reads_residual=True has the critics read the residual, as both papers do. Runs with a residual policy and a warm-up change. What to do: compare with runs of this version.
    • PriorData's offline updates train SAC's actor and temperature. They ran below policy_update_start and alpha_update_start, so only the critics moved. Those starts still count the env steps collected online. Runs with PriorData change. What to do: compare with runs of this version.
    • IQL's state value reads normalised observations, as its actor and critics do. Runs with normalize_observations=True change. What to do: retrain; no option restores the raw read.
    • A replay row keeps the action executed. IQL's unsquashed samples left the action box, the env clipped them, and the replay kept the raw sample beside the reward of the clipped one. Rows now hold the clipped action, as IQL's reference does. Runs training IQL online change. On other replay agents only a row where an expert's action left the box changes.
    • Cloning reads its inputs as the run does. It divided by another standard deviation than the run on low-variance columns, and padded each epoch's last batch with zero rows. Runs with CloningPretrain change, and reset_actor_head=True now reaches TD3's output layer.
    • An expert reads the run's params. It read the env's default params, so a sensor set through params reached the agent and not the expert. Evaluation and UDRL pass them too.
    • The plane group takes target-gym>=0.7,<0.9, from a commit until 0.8.0 is released. Build its experts with REGISTRY[name].make_pid_controller().batched().
    • Fresh playground installs build the Reacher tasks. MuJoCo Playground 0.2.0 compares versions as strings, so ReacherEasy and ReacherHard failed on mujoco 3.10 and later with 'MjSpec' object has no attribute 'find_body'. Ajax now patches Playground's Reacher builder, and the extra takes mujoco 3.6 to 3.15 (see "The playground extra allows MuJoCo up to 3.15" above).
    • APO's Eval/mean average reward changes. It was the mean reward over 10,000 steps per test episode, the episodes restarting. It is now the official code's measure: the mean return / length of the first 10 trajectories to end on 10 environments of up to 1,000 steps, whatever num_episode_test is. What to do: compare with runs of this version.
    • Fresh playground installs import MuJoCo again. The extra now holds mujoco-mjx to mujoco's range, >=3.6,<3.16. mujoco-mjx 4.0 requires mujoco-core, which MuJoCo 4 split out of mujoco, so installers paired it with mujoco 3.9 and import mujoco failed with OSError: libmujoco.so.3.9.0: cannot open shared object file. The two ranges move together.
    • log_frequency=1 evaluates from the first step. With one env it skipped the evaluation at step 1, so the run came out one evaluation short and its last row stayed empty. Other settings evaluate as before.
    • LoggingConfig evaluates every 10,000 steps by default, not every 1,000: 100 evaluations over a million steps. At 1,000, evaluation took about half the time of a 10-seed SAC run on MuJoCo Warp. What to do: pass log_frequency=1_000 to keep the old rate.

    • The SAC family's update functions. critic_value_readers moved from ajax.agents.critics to ajax.agents.update_steps, and critic_step builds it unless an agent passes its own. The SAC family's TD targets and SAC's soft policy loss take their key as key, not rng. SAC.compute_td_target no longer takes recurrent, nor pre_train bc_min_log_std and bc_action_clip_eps, which no caller set (they are constants now). What to do: code calling these by keyword renames or drops the argument; no result changes.

    • train(devices=...) splits the seeds over several devices. Each device trains a consecutive slice of the seeds, or of a sweep's configurations over the seeds, at the same time; the results come back in the usual order on the first device. Without devices nothing changes.

    • agent.save(state, path) and load. save writes the state with the agent's class and its plain constructor arguments; ajax.load(path) or PPO.load(path) returns (agent, state). Arguments that are objects (a prebuilt environment, extensions, an expert policy) are passed to load again. save_checkpoint and load_checkpoint are unchanged, and read these files too.

A resumed run also kept the shorter replay it had grown out of until the call ended. Evaluations now update the state in place, and a resume frees the replay it replaces. No result changes. A state passed as initial_state was already used up by the call; now its old replay is freed too.

Measured on an RTX 2080 Ti at 10 seeds: SAC 4.9%, TD3 4.6%, TQC 3.9% less time per step; CrossQ and REDQ unchanged. Same steps in the same order; results move by floating-point rounding at most.

    • Faster: CQL and Cal-QL score their sampled actions in one critic pass where there were four. Same values to rounding.

    • New: TDMPC2.preset("MuJoCo", env_id). The two settings the latest official TD-MPC2 code changes for its gym MuJoCo tasks: discount_max=0.99 and rho=0.7. TD-MPC2's defaults are unchanged.

    • Changed default: a train call given no logging_config evaluates and prints. It evaluates about ten times over the call (every tenth of its steps, rounded up to whole iterations of the agent), prints a line for each (the mean return over the seeds, with the lowest and highest), and returns the evaluations where it returned None. Upgrade: pass logging_config=None for the earlier behaviour: no evaluation, nothing printed, None returned, and the fastest run. A call with a LoggingConfig is unchanged.

    • New: the evaluations by name. train's second value is still the dict of logged names, and now also has evaluations.returns (seeds x evaluations) and evaluations.timesteps.

    • New: agent.evaluate(state, episodes=10, seed=0), the returns of fresh episodes of each seed's trained policy, one row per seed, acting as agent.policy does; on a Gymnasium environment the episodes step in Python, one seed after another. The hook of that name on agents with their own loop (UDRL, APG, DreamerV3, TD-MPC2) is now evaluation_metrics; TDMPC2MultiTask.evaluate is unchanged.

    • New: LoggingConfig(on_evaluation=...), a function called in the training process with each seed's evaluation.

    Changes in detail¶

    • Gymnasium environments, if you choose them: "gymnasium:HalfCheetah-v5" (or GymnasiumEnv(...) for an environment of your own) trains any agent on a Gymnasium environment, MuJoCo's tasks included. It steps in Python, outside the compiled program, so it is slower and its seeds train one after another; a warning says so and names the closest JAX tasks, with what differs. The new gymnasium extra installs MuJoCo for it. Nothing changes for JAX environments.
    • RVI-SAC. A new average-reward agent, RVISAC (Hisaki and Ono, ICML 2024): SAC learned by RVI Q-learning, its target r - c 1(terminated) - xi + V'(s') going on through terminations, xi following the batch mean of the next values, and a reset cost c learned as a Lagrange multiplier on the termination rate. Its defaults, initialisation, update order and evaluation action are the authors' (yhisaki/average-reward-drl); one update matches theirs leaf by leaf (tests/conformance/test_rvisac_original.py).
    • ValueCentering and ResetCost. Two extensions bring RVI-SAC's pieces to the discounted agents. ValueCentering(rule) centres a one-step target on a learned reward rate (Naik et al., RLC 2024) by one of three rules in ajax.agents.centering: RVIBatchMean, TDErrorCentering, ReferencePoint. ResetCost() has the target go on through terminations and charges them a learned cost (ajax.agents.reset_cost). RVI-SAC calls the same functions.
    • What on_target may learn from. An extension's on_target may now return (target, metrics, ext_state) to update its own state, and its batch holds next_values (the value the target bootstrapped), terminated, predictions() and target_value_at(obs, actions). update_steps.critic_step returns the agent state (its critics stepped, the extensions' states updated) in place of the critic state, and ExtensionStack.apply_on_target returns the states as a third value. The agents' target helpers (compute_td_target, compute_td3_td_target, compute_redq_td_target, compute_tqc_td_target, compute_asac_td_target, compute_avg_td_target, IQL's compute_bellman_target, DQN's two) also return the value they bootstrapped. DQN's td_target_fn may return (target, next_actions, next_values); one returning the target alone still works. Two new capabilities: one_step_target and continuing_target.     • ASAC now does what the authors' code does (darer/ASAC.py): a termination drops the next value in the critic's target (it bootstrapped through it); the termination penalty follows their rule, p_0 times the larger reward of the batch's first two rows; theta averages the reward without the penalty, at the actions the actor step sampled, which the temperature step reads too; the entropy terms are measured from log(1/nA); and the policy's log-probability takes stable-baselines3's +1e-6 in the tanh correction. Runs with terminations learn other values; continuing tasks change less.
    • REDQ now does what the authors' code does (watchernyu/REDQ): its first update's critic targets and actor loss read the temperature 0.2, which the code's constructor leaves until its first temperature step, and the policy's log-probability takes the code's +1e-6 in the tanh correction. Later updates read exp(log_alpha) as before.
    • AVG reads its log-std head as a log-variance, as the authors' code does (gauthamvasan/avg): the policy's standard deviation is exp(out / 2), its clip bounding the log-variance. Runs start with a different spread and learn otherwise.
    • PQN now does what purejaxql does: a time limit ends an episode in its returns (it bootstrapped there), epsilon is read once per update instead of at every step, and the rollout's second-to-last step reads the last step's bootstrap, as purejaxql's backward pass does. Its reproduction comparisons become version 2.
    • APO ends an episode at a time limit, its next value dropped, and leaves that step out of the loss, as xtma/apo does (bootstrap_timelimit): it bootstrapped on the final observation and trained on the step. With normalize_advantage, the advantages use the other steps' mean and unbiased standard deviation, floored at 1e-6.
    • IQL sums its two critics' squared errors, as the reference does (ikostrikov/implicit_q_learning, update_q): it averaged them, which halved the critics' gradient against Adam's eps and max_grad_norm.
    • ExpertWarmup(fraction) (ajax.extensions.expert): during the warm-up the agent's expert takes a share of the steps, uniform actions the others, through a new controller phase, choose_warmup_action (no state and no key in the learner). SAC, TD3, REDQ, ASAC, CrossQ and IQL (with learning_starts above 0) run it, under residual RL and gain mode too, where the expert's steps store the policy action that executes its own action. DQN (no expert yet) and TD-MPC2 (its own collector) refuse it as not wired yet; TQC and AVG, which have no uniform warm-up, refuse it, as does TD3 given its own action_pipeline. SAC's expert_fraction keyword is removed in this release, and SAC with an expert no longer builds ExpertWarmup(fraction=0.7) on its own: pass the extension.
    • ExpertPrefill(n_steps) (ajax.extensions.pretrain): the agent's expert acts n_steps steps in every env before training and its transitions go to the replay as collection writes its own, on SAC, REDQ, ASAC, TQC, TD3, CrossQ and IQL. The rows count once in the observation and reward normalisers, as PriorData's do (one shared function, ajax.agents.loop.count_in_normalisers), and in no timestep. The pretraining now runs the replay's seeders (ExpertPrefill, PriorData) first, in stack order; train_offline refuses a prefill that would overwrite the dataset's rows. SAC's expert_buffer_n_steps keyword is removed in this release, and SAC with an expert no longer builds ExpertPrefill(n_steps=20_000) on its own: pass the extension.
    • SAC's expert prefill runs in the pretraining, as ExpertPrefill: init_SAC and SAC's make_train lose it and expert_buffer_n_steps. It is the same algorithm on other random numbers: the prefill draws the extension's key, and a run whose stack held no other learner extension now draws one more key per update. Under its old key the prefill's rows, statistics and timestep are bitwise the old ones. Under train_offline its rows now come after the dataset's, and a prefill that would overwrite them is refused. Its rows now count in the observation and reward normalisers, which they skipped: a run combining the prefill with normalisation starts from other statistics.
    • BellmanPretrain requires a seeded replay (ExpertPrefill or PriorData in the stack) instead of the agent's expert: with an expert and expert_buffer_n_steps=0 it ran on an empty replay, where it pre-trained on nothing, and now it is refused. Beside PriorData it runs without an expert.
    • Fixed: gain mode's expert columns. Under ExpertGains the replay's a_expert and next_a_expert took the width of the gains, while they hold the expert's env action: an expert with fewer gains than action dimensions crashed collection, and one with more had its action copied into every column. They now take the env's action width. Gain mode refuses an extension that uses an expert's actions where the policy's go (Extension.uses_expert_actions_as_policy_actions: ImitationLoss cloning its expert, OnlineBC, IBRL, LCBGatedBootstrap, CriticBlend, PhiRefresh, ExpertValueMetrics, CloningPretrain, MCPretrain): those are env actions, the policy's are gains.
    • Fixed: the expert prefill under an action transform. SAC's prefill (expert_buffer_n_steps, now ExpertPrefill) wrote the expert's env action into the action column, which gain mode keeps for the gains. A prefill row now stores what collection stores when the expert acts as itself, the policy action each transform names (policy_action_for_expert): the anchor gains (0) under ExpertGains, and under ResidualPolicy a residual of 0 as the policy's action (IQL fits those) beside the expert's executed action. SAC runs in gain mode with a prefill learn other values. A prefill row ending in a termination keeps the reset observation as its next one, as collection does (ASAC's differential target continues from it); it kept the final one.
    • NetworkConfig.squash_log_det_eps sets the guard inside the tanh log-det, log(1 - tanh(u)^2 + eps), for an agent whose reference uses one; 0, the exact log-det, by default. NetworkConfig.log_variance_head reads the log-std head as a log-variance, for the same reason.

    0.4.0¶

    The first release since 0.3.1 (April 2025), which held SAC alone. Ajax has since been reworked; the documentation describes the result. What a user of 0.3.1 meets:

    • Requirements: Python 3.12 or newer; JAX 0.10 and flax 0.12.8 or newer, with no upper bounds; gymnax 1.0.1 from PyPI instead of a fork. Ajax declares only the packages it imports, so gymnasium, mujoco, mujoco-mjx, pandas, matplotlib, pydantic and scipy are no longer installed with it. pip installs Ajax from PyPI or from its repository.
    • Distribution name: Ajax is on PyPI as ajax-rl (pip install ajax-rl); the import is unchanged, import ajax. A project that declares ajax from git or a path renames it ajax-rl.
    • Breaking: Brax and MuJoCo Playground are no longer installed with Ajax. A project that uses their environments asks for ajax-rl[playground] (which brings Brax) or ajax-rl[brax]; without them, building one of their environments raises an error that names the extra.
    • Extras: ajax-rl[cuda] (JAX with CUDA, Linux), ajax-rl[brax], ajax-rl[playground], ajax-rl[compare], ajax-rl[reproduction] and ajax-rl[wandb].
    • Agents: sixteen, each from a published paper: SAC, ASAC, REDQ, TD3, AVG, DQN, PQN, PPO, APO, UDRL, APG, DreamerV3, TDMPC2, TDMPC2MultiTask, IQL and DAgger, on one training loop, with several seeds in one compiled program. Each starts from its reference code's initialisation and optimiser settings where its algorithm page says so. TD3 makes the update of sfujim/TD3, its critics reading actions in the environment's units, as REDQ's do.
    • Extensions: research features passed as extensions=(...); an agent refuses, when built, one it cannot run.
    • Learning from data: train_offline(dataset, n_updates) trains a replay agent (SAC, TD3, REDQ, ASAC, DQN, IQL) on a transition dataset before it acts, then train fine-tunes it online. On it run TD3+BC (ImitationLoss(None, target="replay", alpha=2.5), the paper's actor loss), ReBRAC (with TargetBC), CQL and Cal-QL (ConservativeQ, CalQL, for a policy with a density) and IQL. GAIL (AdversarialReward on PPO) and DAgger imitate with no reward, and the expert-guidance extensions learn from an existing controller.
    • New modules: ajax.compare (AdaStop and confidence sequences), transition datasets (ajax.buffers.dataset), checkpoints (ajax.checkpoint), recurrent memory, and the reference comparisons under benchmarks/reference.
    • Development: dependency floors without caps, tested weekly at the newest and the oldest versions allowed; uv.lock refreshed monthly. Conformance checks (tests/conformance) compare one update of an agent with its original implementation's: PQN, TD3, TD3+BC, REDQ and AVG so far. The tests come in two tiers (CONTRIBUTING.md, Testing): the slow tier, every test that trains, also runs daily on main, on a pull request labelled run-slow-tier and before each release; tags come only from the Release workflow, once the slow tier passed on main's head.
