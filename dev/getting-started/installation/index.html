    Installation¶

    Ajax is on PyPI as ajax-rl and imports as ajax. It needs Python 3.12 or newer.

    pip install ajax-rl

    Brax and MuJoCo Playground environments need an extra: "ajax-rl[playground]" installs both, "ajax-rl[brax]" Brax alone. pip installs main from the repository:

    pip install "ajax-rl @ git+https://github.com/YannBerthelot/Ajax.git"

    pip does not read uv.lock, so it takes the newest versions that pyproject.toml allows. A weekly CI job tests those too, and another the oldest versions allowed (Dependencies and releases).

    From source¶

    uv installs Ajax from source:

    git clone https://github.com/YannBerthelot/Ajax.git
cd Ajax
uv sync

    uv sync creates .venv with the versions in uv.lock, which CI tests. Prefix commands with uv run, or activate the environment with source .venv/bin/activate. To check the install:

    uv run python -c "import ajax; print(ajax.__version__)"

    CPU or GPU¶

    Ajax installs JAX for the CPU. CUDA comes only from its cuda extra (Linux only); without it, JAX runs on the CPU even on a machine with an NVIDIA GPU. To use the GPU:

    uv sync --extra cuda

    A project that depends on Ajax asks for ajax-rl[cuda] instead.

    To keep a run on the CPU on a machine with a GPU, set JAX_PLATFORMS=cpu. The repository's make targets go further and hide the GPU from CUDA as well, so tests never compete with an experiment running on it:

    CUDA_VISIBLE_DEVICES="" JAX_PLATFORMS=cpu uv run python my_script.py

    Performance says when each device pays off.

    Dependency groups¶

    uv sync installs the runtime and the dev group by default. The others are opt-in.

    Group Default What it adds
    dev yes pytest, coverage, pre-commit, ruff, mypy, the probing environments the tests train on, and the playground extra
    wandb no the wandb extra (below)
    plane no TargetGym, for the Plane3DCircle scenario of the speed benchmark (benchmarks/perf_bench.py)
    docs no MkDocs and its plugins, to build this site 
    uv sync --group plane         # add an opt-in group
uv sync --no-default-groups   # the runtime alone

    The docs group builds the site without the runtime (uv sync --only-group docs): the API pages are read from the source, not imported.

    Extras¶

    Extra What it adds
    cuda JAX with CUDA, on Linux (above)
    brax Brax, for Brax environments such as "ant"
    playground MuJoCo Playground and Brax, for Playground environments such as "CartpoleBalance"
    compare the adastop package, whose confidence sequence ajax.compare.estimate uses; AdaStop itself needs no extra
    reproduction Hugging Face Hub, pandas and pyarrow, for ajax.reproduction.load (Reproduction)
    wandb Weights & Biases, for logging with WandbBackend; the wandb group installs it in a checkout 
    uv sync --extra compare

    Brax and MuJoCo Playground come only with their extras: a project that uses their environments asks for ajax-rl[playground], or ajax-rl[brax] for Brax alone. Without them, building a Brax or Playground environment raises an error that names the extra. The dev group installs both, so uv sync in this repository has them.

    The compare extra takes adastop from a commit of its main branch, named in [tool.uv.sources], until a release includes the confidence sequence. pip does not read that table: with pip, install adastop from that commit yourself.

    Using Ajax from another project¶

    Ajax and every runtime dependency, gymnax 1.0.1 included, come from PyPI:

    [project]
dependencies = ["ajax-rl"]  # "ajax-rl[cuda]" for CUDA, "ajax-rl[playground]" for Brax and Playground envs

[tool.uv.sources]
ajax-rl = { git = "https://github.com/YannBerthelot/Ajax.git" }  # optional: main instead of a release

    A project that declared ajax from git or a path renames it ajax-rl; the import stays import ajax.

    uv resolves that project's own versions within Ajax's bounds, not those of Ajax's uv.lock.

    The compile cache¶

    import ajax turns on JAX's persistent compile cache, in ~/.cache/ajax/jax_compile_cache. A second process that runs the same program loads it from disk instead of compiling it again. Two environment variables control it:

    Variable Effect
    AJAX_JAX_COMPILE_CACHE_DIR puts the cache somewhere else
    AJAX_NO_COMPILE_CACHE=1 turns the cache off and leaves the disk untouched

    Performance explains what it saves and when it does not apply.

    Weights & Biases¶

    A LoggingConfig logs to the backends you name, and to TensorBoard when it names none. To log to Weights & Biases, install the wandb extra (pip install "ajax-rl[wandb]", or uv sync --group wandb in a checkout), name WandbBackend, and log in once with uv run wandb login before the first run that uses it. Runs that keep their results in memory (backends=()), as in the quickstart, or write TensorBoard files need no account.

    Working on Ajax¶

    After uv sync, run uv run pre-commit install once, so ruff and mypy check every commit. make docs builds this site as CI does (uv run --group docs mkdocs build --strict: a broken link or a docstring naming a parameter the code does not have fails it), and make docs-serve serves it at http://127.0.0.1:8000, rebuilt on save. Contributing covers the rest.
