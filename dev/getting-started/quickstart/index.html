    Quickstart¶

    This page trains an agent, reads its results, runs the trained policy and saves it. Each example runs on a laptop CPU in under a minute, compilation included.

    The same steps are a notebook, notebooks/quickstart.ipynb (open in Colab), and complete scripts are in examples/.

    Train an agent¶

    An agent takes an environment id and its hyperparameters; train runs it. Here PPO learns CartPole with three seeds at once:

    from ajax import PPO

agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, evaluations = agent.train(seed=[1, 2, 3], n_timesteps=40_960)

    It prints a line when it starts, one per evaluation and one at the end:

    PPO, 3 run(s) of 40,960 steps: compiling, then a line per evaluation (pass logging_config=None for a silent run with none).
      4,096 / 40,960 steps | return 171.1 (min 69.6, max 280.0 over 3 seeds) | 2.5 s
      8,192 / 40,960 steps | return 259.1 (min 156.9, max 450.1 over 3 seeds) | 4.2 s
...
     40,960 / 40,960 steps | return 500.0 (min 500.0, max 500.0 over 3 seeds) | 5.5 s
Done in 5.5 s.

    What happened:

    • PPO("CartPole-v1", ...) looked the id up in gymnax and built 8 copies of the environment, which step in parallel inside each seed.
    • train compiled the training, environment included, and ran the three seeds side by side. The first line's time includes the compilation.
    • Ten times over the run it evaluated each seed's policy on 10 test episodes (num_episode_test) and printed their mean return, with the lowest and highest seed.

    evaluations holds what was printed, and every other logged value:

    import matplotlib.pyplot as plt

from ajax import PPO

agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, evaluations = agent.train(seed=[1, 2, 3], n_timesteps=40_960)

steps = evaluations.timesteps  # [ 4096  8192 ... 40960]
returns = evaluations.returns  # shape (3, 10): seeds x evaluations

plt.plot(steps, returns.mean(axis=0))
plt.fill_between(steps, returns.min(axis=0), returns.max(axis=0), alpha=0.3)
plt.xlabel("environment steps")
plt.ylabel("evaluation return")
plt.savefig("cartpole.png")

    It is a dict of every logged name to an array with one row per seed and one column per evaluation; returns and timesteps are its two most read entries. One seed has its row too: after train(seed=0), the run's curve is evaluations.returns[0]. To choose when the evaluations come, or to log to TensorBoard or Weights & Biases, pass a LoggingConfig (Logging); logging_config=None trains with no evaluation and prints nothing, which is the fastest. Training an agent has the details.

    JAX environments first, Gymnasium supported¶

    "CartPole-v1" above is gymnax's CartPole, written in JAX, not Gymnasium's. Ajax is meant to be used with JAX environments: gymnax, Brax, MuJoCo Playground, Gymnasium's MuJoCo tasks in JAX ("mujoco:<id>"), or your own with gymnax's interface. The environment then compiles into the same program as the agent, and the whole run, every environment copy and every seed, stays on one device from start to end, a CPU or a GPU. That is where the speed comes from, and what the rest of this documentation assumes.

    Gymnasium environments are supported too. Ask for one with the gymnasium: prefix:

    from ajax import PPO

agent = PPO("gymnasium:CartPole-v1", n_envs=8, n_steps=128)
state, evaluations = agent.train(seed=[1, 2], n_timesteps=2_048)
print(agent.evaluate(state, episodes=5).mean(axis=1))

    The calls are the same, but the environment steps in Python:

    • every step leaves the compiled program and comes back, so training is slower and a GPU does not help;
    • the seeds train one after another, not side by side;
    • some features refuse it (resuming from a saved state, action repeat, gradients through the environment).

    Use it when your task has no JAX version, and a JAX environment whenever one exists. An id without the prefix never reaches Gymnasium, and building one warns that it steps in Python, naming the closest JAX tasks. Gymnasium's MuJoCo tasks need the gymnasium extra (Installation). Environments says where each source lists its ids, and Gymnasium environments the closest JAX task of each Gymnasium one.

    Continuous actions¶

    The same pattern works for every agent. SAC on Pendulum:

    from ajax import SAC

# SAC waits learning_starts steps (10,000 by default) before its first update;
# this short demonstration starts after 1,000.
agent = SAC("Pendulum-v1", learning_starts=1_000)
state, evaluations = agent.train(seed=[1, 2], n_timesteps=3_000)

    Three thousand steps show the mechanics, not a trained pendulum: give SAC tens of thousands of steps for that. The algorithm pages help pick an agent and list each one's defaults.

    Use the trained policy¶

    evaluate runs fresh episodes of each seed's trained policy and returns their returns, one row per seed:

    from ajax import PPO

agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, _ = agent.train(seed=[0, 1], n_timesteps=16_384, logging_config=None)

returns = agent.evaluate(state, episodes=20)  # shape (2, 20)
print(returns.mean(axis=1))  # each seed's score

    To watch it, render saves one episode of a seed's policy as an animation. It needs the render extra (pip install "ajax-rl[render]"):

    import os
import tempfile

from ajax import PPO

agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, _ = agent.train(seed=[0, 1], n_timesteps=16_384, logging_config=None)
agent.render(state, os.path.join(tempfile.mkdtemp(), "cartpole.gif"))

    Watch the policy covers Brax and MuJoCo tasks.

    To act in a loop of your own, agent.predict(state, observation) returns the first seed's action for an observation (seed_index picks another), in the environment's units, and agent.policy(state) carries a memory from step to step. Train, evaluate, deploy shows both.

    Save and load¶

    agent.save writes the state with the agent's class and arguments; ajax.load builds both again:

    import os
import tempfile

import ajax
from ajax import PPO

agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, _ = agent.train(seed=[0, 1], n_timesteps=8_192, logging_config=None)
path = os.path.join(tempfile.mkdtemp(), "ppo_cartpole.pkl")
agent.save(state, path)

# Later, in another process.
agent, state = ajax.load(path)
print(agent.evaluate(state, episodes=5).mean(axis=1))
state, _ = agent.train(seed=[0, 1], n_timesteps=8_192, initial_state=state)

    Checkpoints and resuming explains what a resume keeps, and which arguments must be passed again.

    Where next¶

    • Train, evaluate, deploy: act with a trained policy in a loop of your own, save it and load it elsewhere.
    • Environments: gymnax, Brax and MuJoCo Playground ids, your own environments, normalisation and time limits.
