    Why Ajax¶

    This page is for deciding whether Ajax suits your work. It explains what Ajax offers, with examples, compares it with other libraries, and says when one of them fits better. The examples run on a laptop CPU in under a minute each, except the world-model one.

    One program for the whole run¶

    train compiles the whole run into one JAX program: the environment's steps, the replay buffer or the rollout, the updates and the evaluations. The seeds run side by side in that program, through jax.vmap, and so do the configurations of a hyperparameter sweep. No step goes back to Python, so the program runs on a CPU or a GPU alike:

    import jax

from ajax import PPO

print(jax.default_backend())  # "cpu" here; "gpu" when JAX finds one
agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
# 4 seeds of 2 clip ranges: 8 runs, each with 8 copies of CartPole, in one program.
state, evaluations = agent.train(
    seed=[0, 1, 2, 3], n_timesteps=16_384, sweep={"clip_range": [0.1, 0.2]}
)
print(evaluations.returns.shape)  # a row per run, a column per evaluation

    A GPU gains most on agents whose updates take the time (many critics, wide networks, world models) and little on those spending it on one simulator step per seed (CPU or GPU). The same script runs on a GPU once JAX has CUDA (Installation).

    This needs an environment written in JAX: gymnax, Brax, MuJoCo Playground, Gymnasium's MuJoCo tasks on MJX or your own (Environments); a Gymnasium environment steps in Python. Only logging leaves the program, to hand over each evaluation. TDMPC2MultiTask alone trains otherwise: offline, evaluating its tasks from Python between compiled chunks of updates.

    Variations that combine¶

    A variant of an algorithm is an argument of its agent, not another class: recurrent PPO is PPO with memory= (Memory), images go through a CNN encoder with cnn_image_shape=, and a PIDPolicy as actor_architecture makes the actor a PID controller (Networks). Research features (cloning an expert, an extra loss term, a diagnostic) are extensions, passed as extensions=(...), and they add up: the TD3 below clones an expert, then keeps an imitation term in its loss. An agent refuses, when built, an extension it cannot run, and says why (Compatibility).

    Checked against the original code¶

    Each agent starts from the code behind its paper's results, with that code's defaults, initialisation and order of updates; its algorithm page cites the code and lists where Ajax departs from it. Its defaults can therefore differ from another library's (Coming from SB3). Three kinds of tests check the agents (Testing):

    • unit tests, on each update's maths with hand-computed values;
    • probes, which train an agent on a small problem with a known answer and name the mistake behind a wrong one, such as a discount applied twice;
    • conformance checks, which run one training step of Ajax and of the original implementation from the same state and compare them.

    Comparisons of whole training runs with reference implementations are in progress (Reproduction).

    Average-reward agents¶

    Most agents maximise a discounted return: a reward k steps ahead counts gamma**k times as much as one now. For a task that never ends, such as holding a setpoint or running a plant, the discount is not part of the problem; it only shortens how far ahead the agent looks. An average-reward agent maximises the reward per step over the long run instead, and has no discount factor. Ajax has three, each following its paper: ASAC (Adamczyk et al., 2025) and RVI-SAC (Hisaki and Ono, 2024), SAC for this criterion, and APO (Ma et al., 2021), PPO for it. ASAC and APO keep their estimate of the reward per step on the state:

    from ajax import APO, ASAC

# On-policy: PPO's clipped update on the reward minus the reward per step.
apo = APO("Pendulum-v1", n_envs=4)
state, _ = apo.train(seed=[0, 1], n_timesteps=4_000)
print(state.average_reward)  # one estimate per seed

# Off-policy: soft actor-critic on the same criterion.
asac = ASAC("Pendulum-v1", learning_starts=1_000)
state, _ = asac.train(seed=[0, 1], n_timesteps=2_000)
print(state.theta)  # its reward-rate estimate, entropy term included

    These budgets show the calls; Pendulum needs far more steps to be solved.

    Learning from an expert or from data¶

    Often a controller already exists for the task: a tuned PID, a model predictive controller, an earlier policy. In Ajax this expert is a JAX function from the environment's raw observations to actions in its units (a stateful one, such as a PID with its integral, works too), and an agent can learn from it instead of starting from scratch.

    Most agents can clone the expert before training (CloningPretrain) or add an imitation term to the actor's loss (ImitationLoss), and most replay agents can start with its transitions in the replay (ExpertPrefill). SAC takes nearly every such extension, among them residual policies, JSRL hand-over and IBRL targets. Recorded transitions work too: prior data in the replay, as in RLPD (PriorData), or train_offline. Given expert_policy=, an agent logs the expert's return at each evaluation, so the curves show when it overtakes the expert. Expert guidance gives each method and its paper.

    import jax.numpy as jnp

from ajax import SAC, TD3
from ajax.extensions.expert import ImitationLoss
from ajax.extensions.pretrain import CloningPretrain, ExpertPrefill
from ajax.logging import LoggingConfig


def pd_expert(obs):
    """A PD controller on Pendulum's raw observation [cos θ, sin θ, θ̇],
    answering a torque in the environment's units, [-2, 2]."""
    theta = jnp.arctan2(obs[..., 1], obs[..., 0])
    return jnp.clip(-(2.0 * theta + 0.5 * obs[..., 2]), -2.0, 2.0)[..., None]


# SAC writes 1,000 expert steps to its replay buffer before training.
sac = SAC("Pendulum-v1", expert_policy=pd_expert, learning_starts=1_000,
          extensions=(ExpertPrefill(n_steps=1_000),))
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = sac.train(seed=0, n_timesteps=2_000, logging_config=logging)
print(evaluations["Eval/expert bias"])  # the agent's return minus the expert's

# TD3 clones the expert on 1,000 of its steps before training, then keeps
# pulling its actor towards the expert's actions with an extra loss term.
td3 = TD3("Pendulum-v1", learning_starts=1_000, extensions=(
    CloningPretrain(pd_expert, n_steps=1_000, epochs=2),
    ImitationLoss(pd_expert),
))
state, _ = td3.train(seed=0, n_timesteps=2_000)

    World models¶

    A world-model agent learns a model of the environment, a network that predicts what happens next and what reward follows, and uses it to act. DreamerV3 learns its policy inside the model, from imagined trajectories; TD-MPC2 plans with the model at every step, and TDMPC2MultiTask trains one model offline on the data of several tasks. Each follows the code behind its paper's results, and the deviations register lists where Ajax departs from it. World models explains them in plain words.

    # doc: skip (about half a minute on a laptop CPU, compilation included)
from ajax import DreamerV3

# The smallest model and a low train ratio, for a first look on a CPU.
agent = DreamerV3("CartPole-v1", model_size="1m", n_envs=4, train_ratio=32,
                  batch_size=4, batch_length=16)
state, _ = agent.train(seed=0, n_timesteps=1_000)

    Both are much heavier than the model-free agents: use a GPU for anything beyond a check.

    Other libraries¶

    These also compile the environment and the training loop into one JAX program:

    • Brax's training agents: PPO, SAC, APG, ARS, ES and behaviour cloning (with DAgger from a teacher policy), trained across devices and hosts. Ajax's APG adds recurrent memory and Busetto et al.'s contextual controller.
    • Stoix: about 25 algorithms, among them R2D2, MPO and MuZero, trained across devices. Its Anakin architecture runs end to end, and Sebulba trains on environments not written in JAX.
    • Rejax: PPO, SAC, DQN and its variants, PQN, IQN and TD3. A whole run is jitted, and can be vmapped over seeds and hyperparameters (README).

    CleanRL's QDagger also learns from a teacher policy, for DQN. TorchRL and Tianshou take Gymnasium environments, and between them their pages list IQL, CQL, GAIL, REDQ, CrossQ and Dreamer, all of which Ajax has; TorchRL's Dreamer is written in PyTorch and steps its environments from Python.

    When to use something else¶

    • Your environment is not written in JAX. Ajax trains on a Gymnasium environment, but slowly, stepping it in Python (Gymnasium environments). SB3 and SBX are built around Gymnasium's interface, and SB3 ships a checker for it (custom envs, README); TorchRL and Tianshou take such environments too (TorchRL, Tianshou), and Stoix's Sebulba architecture trains on them at scale (Stoix).
    • You train one run on several devices. Ajax splits a run's seeds over devices (Performance), but each seed trains on one: it has no pmap or sharding. Brax's training agents and Stoix train across devices (Brax, Stoix).
    • You want to sweep any hyperparameter of any agent in one program. train(sweep=...) varies only the numbers an agent declares sweepable, and APG, DreamerV3 and TD-MPC2 declare none (Hyperparameter sweeps). Any other value compiles a program of its own. Rejax vmaps over hyperparameters as well as seeds (README).
    • You want a mature, stable library. SB3 describes itself as stable, focused on bug fixes and maintenance, with documentation, high code coverage and type hints, and its RL Baselines3 Zoo adds tuned hyperparameters, pre-trained agents and training scripts (README). Ajax is younger, with no zoo or pre-trained agents.
    • Your observations are dictionaries. SB3 supports single-level Dict observation spaces (algorithms); Ajax's networks read one flat vector, and flatten an image into one (Networks).
    • You want SB3's interface with JAX networks. SBX shares SB3's API and works with the RL Zoo; it calls itself a proof of concept (README).
    • You want an algorithm in one file, with nothing imported. PureJaxRL's implementations are single files, not a library to import (README); an Ajax agent's file holds its algorithm, on a shared loop, networks and logging. PureJaxRL's README compares its speed with PyTorch implementations; Ajax's speeds include no comparison with PureJaxRL.
    • You need an algorithm Ajax does not have, such as A2C, TRPO or invalid-action masking: SB3, sb3-contrib or SBX have them (algorithms, contrib, README).
