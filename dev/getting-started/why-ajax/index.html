    Why Ajax¶

    Stable-Baselines3 (SB3) is a PyTorch library of reinforcement-learning agents, with more agents in sb3-contrib. SBX is its JAX version. PureJaxRL is a set of single-file JAX implementations. Ajax is built around four things:

    1. End to end on the accelerator: the environment and the training loop compile into one JAX program, as in PureJaxRL and the other end-to-end JAX libraries.
    2. Average-reward agents: ASAC and APO, for tasks that never end.
    3. Expert-guided agents: agents that learn from a controller you already have.
    4. World models: DreamerV3 and TD-MPC2, in the same compiled program as the environment.

    This page shows each one, compares the libraries and says when another library fits better. The examples run on a laptop CPU in under a minute each, except the world-model one.

    End to end on the accelerator¶

    train compiles the whole run into one JAX program: the environment's steps, the replay buffer or rollout, the updates and the evaluations. The seeds run side by side in that same program, through jax.vmap. The loop does not come back to Python between two steps, so the program can run on a GPU the way it runs on a CPU, without a round trip to the host at each step. This is PureJaxRL's approach, and every Ajax agent trains this way except TDMPC2MultiTask, which learns offline from a dataset and evaluates its tasks from Python between compiled chunks of updates. It needs an environment written in JAX: gymnax, Brax, MuJoCo Playground or TargetGym. Logging and the critic pre-training extensions do call back to the host, to hand over their records or print progress.

    import jax

from ajax import PPO

print(jax.default_backend())  # "cpu" here; "gpu" when JAX finds one
# 8 seeds, each with 8 copies of CartPole, compiled and run as one program.
agent = PPO("CartPole-v1", n_envs=8, n_steps=128)
state, _ = agent.train(seed=list(range(8)), n_timesteps=16_384)
print(state.collector_state.timestep)  # one count per seed

    The same script runs on a GPU when JAX is installed with CUDA support and finds one (Installation). This section describes how the program is built, not a measured gain: Ajax's tests and per-agent benchmark run on the CPU, and no measurement compares a run on a GPU with the same run on a CPU. Performance has the costs that were measured: compilation, seeds, each agent's speed on a CPU.

    Average-reward agents¶

    Most agents maximise a discounted return: a reward k steps ahead counts gamma**k times as much as one now. For a task that never ends, such as holding a setpoint or running a plant, the discount is not part of the problem; it only shortens how far ahead the agent looks. An average-reward agent maximises the reward per step over the long run instead, and has no discount factor. Ajax has two, each following its paper: ASAC (Adamczyk et al., 2025), SAC for this criterion, and APO (Ma et al., 2021), PPO for it. Each keeps its estimate of the reward per step on the state.

    from ajax import APO, ASAC

# On-policy: PPO's clipped update on the reward minus the reward per step.
apo = APO("Pendulum-v1", n_envs=4, n_steps=256)
state, _ = apo.train(seed=[0, 1], n_timesteps=4_096)
print(state.average_reward)  # one estimate per seed

# Off-policy: soft actor-critic on the same criterion.
asac = ASAC("Pendulum-v1", learning_starts=1_000)
state, _ = asac.train(seed=[0, 1], n_timesteps=2_000)
print(state.theta)  # its reward-rate estimate, entropy term included

    These budgets show the calls; Pendulum needs far more steps to be solved.

    Expert-guided agents¶

    Often a controller already exists for the task: a tuned PID, a model predictive controller, an earlier policy. In Ajax an expert is a JAX function from observations to actions (or a stateful one, such as a PID carrying its integral, which gets its state back at every step), and an agent can learn from it instead of starting from scratch. The expert reads the environment's raw observations and answers in the environment's action units; the agent converts its answers to its own units, [-1, 1].

    SAC uses it the most: it fills the replay buffer with the expert's experience, lets the expert act during warm-up, and takes the expert extensions: online behaviour cloning, residual policies, JSRL hand-over, IBRL targets and EDGE exploration, among others. SAC, TD3, REDQ and APO can clone the expert before training (CloningPretrain), and SAC, TD3, REDQ, ASAC and APO can add an imitation term to the actor's loss (ImitationLoss). SAC, TD3, REDQ, APO and AVG, given expert_policy=, also log the expert's own return at each evaluation, so the curves show whether the agent has overtaken it. Expert guidance covers every option.

    import jax.numpy as jnp

from ajax import SAC, TD3
from ajax.extensions.expert import ImitationLoss
from ajax.extensions.pretrain import CloningPretrain, ExpertPrefill
from ajax.logging import LoggingConfig


def pd_expert(obs):
    """A PD controller on Pendulum's raw observation [cos θ, sin θ, θ̇],
    answering a torque in the environment's units, [-2, 2]."""
    theta = jnp.arctan2(obs[..., 1], obs[..., 0])
    return jnp.clip(-(2.0 * theta + 0.5 * obs[..., 2]), -2.0, 2.0)[..., None]


# SAC writes 1,000 expert steps to its replay buffer before training.
sac = SAC("Pendulum-v1", expert_policy=pd_expert, learning_starts=1_000,
          extensions=(ExpertPrefill(n_steps=1_000),))
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = sac.train(seed=0, n_timesteps=2_000, logging_config=logging)
print(evaluations["Eval/expert bias"])  # the agent's return minus the expert's

# TD3 clones the expert on 1,000 of its steps before training, then keeps
# pulling its actor towards the expert's actions with an extra loss term.
td3 = TD3("Pendulum-v1", learning_starts=1_000, extensions=(
    CloningPretrain(pd_expert, n_steps=1_000, epochs=2),
    ImitationLoss(pd_expert),
))
state, _ = td3.train(seed=0, n_timesteps=2_000)

    World models¶

    A world-model agent learns a model of the environment, a network that predicts what happens next and what reward follows, and uses it to act. DreamerV3 learns its policy inside the model, from imagined trajectories; TD-MPC2 plans with the model at every step; TDMPC2MultiTask trains one model offline on the data of several tasks. Each follows the code that produced its paper's results: the deviations register lists where Ajax departs from it, and tests compare Ajax's components with it. DreamerV3 and TD-MPC2 run in one compiled program with the environment, like the other agents; TDMPC2MultiTask steps no environment while it trains. World models explains them in plain words.

    # doc: skip (about half a minute on a laptop CPU, compilation included)
from ajax import DreamerV3

# The smallest model and a low train ratio, for a first look on a CPU.
agent = DreamerV3("CartPole-v1", model_size="1m", n_envs=4, train_ratio=32,
                  batch_size=4, batch_length=16)
state, _ = agent.train(seed=0, n_timesteps=1_000)

    Both agents are much heavier than the model-free ones: use a GPU for anything beyond a check.

    Other end-to-end JAX libraries¶

    These also compile the environment and the training loop into one JAX program, as their repositories read on 17 October 2026:

    • Brax's training agents: PPO, SAC, APG, ARS, ES and behaviour cloning, which can run DAgger online from a teacher policy. They train across devices and hosts. Ajax's APG adds recurrent memory and Busetto et al.'s contextual controller.
    • Stoix: about 25 algorithms, among them R2D2, MPO and MuZero. Its Anakin architecture runs end to end with a JAX environment, and Sebulba trains on environments not written in JAX. It trains across devices.
    • Rejax: PPO, SAC, DQN and its variants, PQN, IQN and TD3. The whole run is jitted, and it can be vmapped over seeds and over hyperparameters (README).

    CleanRL's QDagger also learns from a teacher policy, for DQN.

    TorchRL and Tianshou¶

    As their repositories read on 27 October 2026, both take Gymnasium environments, and between them their pages list IQL, CQL, GAIL, REDQ, CrossQ and Dreamer (TorchRL, Tianshou). Ajax's offline agents match what they offer. TorchRL's Dreamer is written in PyTorch and steps its environments from Python. Ajax's range of agents is unusual among end-to-end JAX libraries, not beside these two.

    When to use something else¶

    • Your environment is not written in JAX. A Gymnasium environment that steps in Python, an external simulator or a real system cannot run inside Ajax's compiled program (Environments). SB3 and SBX take environments with the Gymnasium interface, and SB3 ships a checker for it (custom envs, README); TorchRL and Tianshou take them too (TorchRL, Tianshou). For such environments at scale, Stoix has its Sebulba architecture (Stoix).
    • You train on several devices. Ajax runs on one device for now; it has no pmap or sharding. Brax's training agents and Stoix train across devices (Brax, Stoix).
    • You want a hyperparameter sweep in one program. Ajax compiles the hyperparameters into the program, so each trial of a sweep compiles anew (Performance). Rejax vmaps over hyperparameters as well as seeds (README).
    • You want a mature, stable library. SB3 describes itself as stable, with development focused on bug fixes and maintenance, and lists documentation, high code coverage and type hints among its features (README). It installs with pip, and the RL Baselines3 Zoo adds tuned hyperparameters, pre-trained agents and training scripts (README). Ajax is on PyPI as ajax-rl (Installation) and has no such zoo.
    • Your observations are dictionaries. SB3 supports single-level Dict observation spaces (algorithms); Ajax's networks read one flat vector, and it flattens image observations into one (Networks).
    • You want SB3's interface with JAX networks. SBX shares SB3's API and works with the RL Zoo (README). It calls itself a proof of concept (README).
    • You want to read or change one algorithm in one file. PureJaxRL's implementations are single files, not a library meant to be imported (README). Its README reports its own speed comparisons with PyTorch implementations, including on a GPU; Ajax has not measured a GPU speed-up.
    • You need an algorithm Ajax does not have, such as A2C, TRPO or invalid-action masking: SB3, sb3-contrib or SBX have them (algorithms, contrib, README).
