    Expert guidance¶

    Often a controller already exists for the task: a tuned PID, a model predictive controller, a hand-written rule, an earlier policy. Expert guidance lets an agent learn from such an expert instead of starting from scratch: copy it before training, let it act while the agent is still poor, use its values in the critic's target, and then improve on it. Recorded transitions, from an expert or any earlier run, can start a replay agent's buffer too.

    This page is for readers who have an expert or a dataset. It covers what Ajax accepts as an expert, an example, how to choose the pieces, and how each piece acts during training. Choosing the pieces names each method, its paper and the agents that run it.

    The expert¶

    An expert maps observations to actions, in one of two forms:

    • Stateless: expert(obs) -> action.
    • Stateful, for a controller with memory such as a PID's integral: an object with init_state(n_envs), which returns the starting state for n_envs environments, and expert(state, obs) -> (action, new_state). TargetGym's PID experts (target_gym.experts.pid.FunctionalExpertPolicy) have this form: build one with target_gym.registry.REGISTRY[name].make_pid_controller().batched(). target_gym.make_expert(name) returns TargetGym's own form, with reset and step, which Ajax does not call.

    Four conventions matter:

    1. It lives in the environment's units, both ways. It reads the environment's own observation, before any observation normalisation and without the columns an agent appends (the training fraction, the expert's own state). It returns actions within the environment's bounds: on Pendulum, a torque between -2 and 2. Ajax reads that action in the agent's units, [-1, 1] (Actions), without clipping it, so it can be stored and compared with the agent's own actions; when it is executed, the usual map sends it back to the environment, clipped at its bounds.
    2. Its state is tracked. Wherever Ajax runs a stateful expert itself (collection, the expert prefill and warm-up, the cloning and Monte-Carlo rollouts, evaluation), it keeps one state per environment copy and starts every episode from init_state.
    3. It works on batches. Ajax calls it on one observation per environment, and on replay batches. Index the last axis (obs[..., 0]), not the first, and keep the action's last axis ([..., None] for one action; a discrete action's index is an int (n, 1) column).
    4. It is part of the compiled program: a plain function or a frozen dataclass works.

    A stateful expert, a PID on Pendulum's angle:

    from dataclasses import dataclass

import jax.numpy as jnp

from ajax import SAC
from ajax.logging import LoggingConfig


@dataclass(frozen=True)
class PIDExpert:
    """A PID on the pole's angle; its state is the error's integral."""

    kp: float = 2.0
    ki: float = 0.1
    kd: float = 0.5
    dt: float = 0.05  # Pendulum's time step

    def init_state(self, n_envs):
        return jnp.zeros((n_envs, 1))

    def __call__(self, integral, obs):
        theta = jnp.arctan2(obs[..., 1:2], obs[..., 0:1])  # raw [cos, sin, velocity]
        integral = integral + self.dt * theta
        torque = -(self.kp * theta + self.ki * integral + self.kd * obs[..., 2:3])
        return jnp.clip(torque, -2.0, 2.0), integral  # newton-metres, as the env takes them


agent = SAC("Pendulum-v1", expert_policy=PIDExpert(), learning_starts=500)
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = agent.train(seed=0, n_timesteps=1_000, logging_config=logging)
print(evaluations["Eval/episodic mean expert reward"])  # the PID's own return

    Extensions that call an expert on a replay batch (ImitationLoss, IBRL, LCBGatedBootstrap, CriticBlend, PhiRefresh) call it as expert(obs), where no expert state exists. A stateful expert is allowed there only when it is the agent's own expert_policy (the same object), on an agent that stores that expert's actions: SAC, TD3, REDQ, CrossQ, TQC, ASAC, RVI-SAC, AVG, DQN, DAgger and APO. The extension then reads the actions the agent stored at collection, computed from the expert's tracked state. Any other stateful expert is refused when the agent is built.

    Which agents take an expert¶

    Every agent but REINFORCE and the world models takes an expert_policy=: collection tracks it along each trajectory, the extensions read it, and evaluations log its return. DAgger requires one, as the expert labels every state it visits. Compatibility lists which expert extension runs on which agent.

    With an expert, each evaluation also logs Eval/episodic mean expert reward, the expert's return on the same episodes as the agent's, and Eval/expert bias, the agent's return minus the expert's (positive once the agent does better). eval_expert_policy sets another expert for that comparison alone, when the one to compare against is not the one to learn from.

    No expert with memory

    With memory=, every agent but APG refuses an expert_policy, and every extension but the observation features and StorePolicyAction, when training starts.

    Example¶

    SAC on Pendulum with a PD controller that is good near the top and poor elsewhere. ExpertPrefill fills the replay with the expert's experience, MCPretrain fits a critic to the expert's returns, OnlineBC pulls the actor towards the expert early on, and EDGEExploration lets the expert act while the critic rates it higher than the policy:

    import jax.numpy as jnp

from ajax import SAC
from ajax.extensions.expert import OnlineBC
from ajax.extensions.exploration import EDGEExploration
from ajax.extensions.pretrain import ExpertPrefill, MCPretrain
from ajax.logging import LoggingConfig


def pd_expert(obs):
    """A PD controller on Pendulum's raw observation [cos θ, sin θ, θ̇]."""
    theta = jnp.arctan2(obs[..., 1], obs[..., 0])
    torque = -(2.0 * theta + 0.5 * obs[..., 2])
    return jnp.clip(torque, -2.0, 2.0)[..., None]  # the env's torque range


agent = SAC(
    "Pendulum-v1",
    expert_policy=pd_expert,
    learning_starts=1_000,
    extensions=(
        # 1,000 expert steps written to the replay before training.
        ExpertPrefill(n_steps=1_000),
        # The frozen expert critic, fitted to ~1,000 steps of the expert's returns.
        MCPretrain(pd_expert, n_mc_steps=100, n_mc_episodes=10, n_steps=200),
        OnlineBC(bc_coef=1.0, critic_warmup_frac=0.2),
        EDGEExploration(gate="argmax", decay_frac=0.3),
    ),
)
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = agent.train(seed=0, n_timesteps=2_000, logging_config=logging)
print(evaluations["Eval/episodic mean reward"])
print(evaluations["Eval/expert bias"])       # agent minus expert
print(evaluations["edge/live_expert_frac"])  # share of envs the expert drove

    At this budget the agent has barely started: the example shows the wiring. For a real run, give MCPretrain a few hundred thousand expert steps (its defaults collect about a million) and train for tens of thousands of steps.

    The extensions that hold an expert themselves (CloningPretrain, MCPretrain, PhiRefresh, IBRL, LCBGatedBootstrap, CriticBlend, ImitationLoss) take it as their first argument. Pass the same object you give the agent: the target extensions, PhiRefresh and ImitationLoss then read the actions the agent stored at collection rather than calling the expert again. CloningPretrain must have it when the agent's observations carry the expert's action or state, and MCPretrain when they carry its state; they are refused otherwise.

    How the pieces act, step by step¶

    Before training¶

    1. Replay prefill. ExpertPrefill(n_steps) runs the expert for n_steps steps in each environment and writes them to the replay, flagged as expert rows. Every row also stores the expert's action at s and s′, which several extensions read later; under gain mode it stores the anchor gains (action 0), as collection does when the expert acts as itself. offline_updates runs the agent's own update on them before it acts. By default the expert is the agent's; expert= gives the prefill one of its own, so a run with no expert online queries none.
    2. Cloning. CloningPretrain(expert, n_steps=...) rolls the expert out for n_steps steps per environment, in the observation layout the agent sees, and trains the actor to reproduce its actions for epochs passes in batches of batch_size, at the actor's learning rate. The actor learns on observations standardised with the dataset's statistics, so the agent's running observation statistics start from them (an agent that kept none gets them) and the actor keeps seeing inputs as it did when cloned. reset_log_std=True restores the cloned actor's exploration noise afterwards, reset_actor_head=True keeps only its hidden layers, and skip_actor=True leaves the actor as it was. Put it first among the pre-training extensions: the critics the others pre-train read the statistics it sets.
    3. Critic pre-training. MCPretrain runs the expert, fits a separate critic, the frozen expert critic φ*, to its Monte-Carlo returns, and records the range of values it predicts. Unlike a Bellman target, a Monte-Carlo return does not lean on an untrained critic, so it is unbiased. BellmanPretrain instead runs ordinary critic updates on the prefilled replay; it is kept for ablations.

    Warm-up¶

    Until learning_starts, an agent with a warm-up acts uniformly at random. With ExpertWarmup(fraction), at each step, with probability fraction, every environment takes the expert's action instead, and the replay flags those rows. Under gain mode, or with ResidualPolicy, the warm-up draws the policy's actions, and the expert's rows store the one that executes the expert's own action (0).

    Collection¶

    Collection extensions decide, at each step, whether the expert or the policy acts. The shared collector runs them around the agent's own action choice, on every off-policy agent with an expert, and UDRL's collector does too, in one of two places, which each extension names in its action_slot:

    • Before the warm-up's choice ("pre_warmup"): EDGEExploration, a value-based gate comparing the expert's action with the one the step would execute, which the critics are trained on; JSRLCurriculum, where the expert starts each episode and the learner takes over; IBRL's acting and EpsilonGreedyPresample.
    • After it ("post_warmup"): ValueBox, which lets the expert act wherever its value exceeds a threshold that rises over training (the step that enters this region ends the agent's episode in the stored transition, and pays the expert's value as a reward in place of the bootstrap), and CHEQ.

    JSRLCurriculum's schedule sets h, the expert's steps at the start of each episode, from the task's horizon down to 0 in n_stages stages. "performance" is the paper's JSRL-Curriculum: h moves down a stage when an evaluation of the combined policy passes, every eval_every steps, on eval_episodes episodes of its own (1 by default, as they are steps on the plant, which ajax.ledger charges). It passes when the moving average of the last moving_average evaluations clears threshold or, without one, comes within tolerance of the best previous moving average. "random" is the paper's JSRL-Random: h drawn from those stages each episode. "time" is Ajax's own: h falls linearly to 0 at decay_frac of training, whatever the performance.

    JSRL on a short run

    With "performance", h stays at the horizon until the first evaluation, after eval_every steps (10,000 by default). A shorter run logs jsrl/expert_frac at 1.0 throughout: the expert drives every step. On a short run, lower eval_every.

    Where an extension hands the expert a step, UDRL's segment keeps the choice that executes the expert's action, which its actor then fits under the command the step realised: Ajax's composition of JSRL and EDGE with UDRL, not a published pairing.

    ResidualPolicy changes what the policy's action means: the agent executes clip(a_E + scale · a_π, −1, 1), in agent units, in collection (the warm-up too, which draws uniform residuals around the expert), in the critics' target, in the actor's loss and in evaluation; the replay stores the executed action. The policy then learns a correction to the expert (residual RL). zero_start=True puts the actor's output head at 0, so that the policy starts as the expert (Silver et al., 2018). critic_reads_residual=True stores the residual and has the critics read it, as both Johannink et al. and Silver et al. do; it needs a Q critic. UDRL acts through the residual in its own collector, and APG in its differentiable rollout, whose gradient runs through the residual and the expert.

    The replay flags the steps where the expert acted, and replay/expert_share logs their share of the rows held at each evaluation. The replay keeps the raw observations and these flags only in a run with an expert (the agent's expert_policy, or one an extension holds).

    Critic¶

    Target extensions change what the critic learns towards. IBRL and LCBGatedBootstrap compare the expert's and the policy's next actions.

    IBRL computes its target as its authors' code does (hengyuan-hu/ibrl): the policy's next action is the one the agent's target scored (TD3's smoothed target action, the sample SAC's, REDQ's and TQC's targets valued). REDQ's target takes the minimum over a random subset of its critics; there IBRL selects between the two actions on a second random subset of the same size and values the selected one on the target's, as the authors' code selects on one random pair and values on another, so the bonus can be negative. The rest has no original form and is Ajax's own: the entropy term of SAC's, REDQ's and TQC's targets stays at the policy's action when the expert is selected, TQC's bonus reads its quantiles' means, and IQL, whose target scores no next action, scores a sample of its actor.

    IBRL also acts as the authors' code acts (hybrid_acting=False leaves the target alone): past the warm-up it executes the better of the agent's action (TD3's noisy one, a sample) and the expert's, each scored by the minimum over the target critics (on REDQ, over a fresh random subset of the target's size), and the replay flags the rows the expert's action took. Evaluation makes the same choice from the agent's evaluation action, its mean. ibrl/expert_frac and Eval/expert share log how often the expert's action was taken. IBRL uses its own expert, which need not be the agent's. tests/conformance/test_ibrl_original.py checks the target and the acting against the authors' code on fixed inputs.

    The choice is hard by default (the authors' ibrl). IBRL(expert_policy, soft_choice=True) makes it their ibrl_soft, in acting and in the target alike: the expert's action is taken with probability sigmoid(β (Q(a_E) − Q(a))), β being soft_choice_beta (10 by default, as in their configurations). The target can then draw an expert's action worth less than the policy's, so its bonus can be negative, and evaluation draws too, as in the authors' code.

    LCBGatedBootstrap scores the same next actions and blends minima over the same critics. CriticBlend and MCVarianceCorrection lean on φ*, so they need MCPretrain in the same stack, and PhiRefresh refits φ* during training on the rows where the expert acted.

    Actor¶

    OnlineBC adds a cloning term to the actor's loss, weighted by φ*'s value at each state and fading out over critic_warmup_frac of training. It needs MCPretrain.

    ImitationLoss adds the unweighted cloning term of TD3+BC (below). With q_filter=True it counts only the rows where the agent's critics rate the expert's action above the policy's mean action, min_k Q_k(s, a_E) > min_k Q_k(s, μ(s)): the Q-filter of Nair et al. (ICRA 2018, Sec. IV-C). Where the agent already does better than the expert, it stops copying it, with no schedule to tune: a PID that is good near the setpoint and poor in transients keeps guiding only where it still helps. Unlike the paper, the rows are replay rows labelled with the expert's action, not a separate demonstration buffer, and coef weights the cloning term in place of the paper's two weights. The filter needs a critic that ranks actions, a Q critic: PPO's and APO's state-value critics cannot. The minimum runs over all the agent's critics, though TD3's actor follows its first and REDQ's the mean of its ensemble. Pair it with the expert prefill, as the paper pairs it with demonstrations.

    Observation¶

    Observation features append columns to every observation, which the actor, the critics and the replay all read (ajax.extensions.observe):

    • ExpertActionInput() appends the expert's action, so the policy can condition on the expert's suggestion. It stays raw, as an action; a discrete expert's index enters one-hot.
    • ExpertStateInput.for_expert(expert) appends a stateful expert's internal state (a PID's integral, say).
    • TrainingProgressInput() appends the fraction of training done; an evaluation holds the collector's.

    They join an observation when it arrives, in collection and evaluation, and are stored with it.

    Evaluation¶

    Besides the expert's return and the bias above, ExpertValueMetrics logs the critic's value at the expert's actions (value/q_expert_mean) and its gap to the value of the actions taken (value/q_gap). EDGEExploration logs edge/live_expert_frac, and ImitationLoss(q_filter=True) the share of a replay batch its filter keeps (imitation/q_filter_frac; not on AVG, which keeps no replay).

    Imitation alongside the reward¶

    ImitationLoss is the behaviour-cloning term of TD3+BC (Fujimoto and Gu, 2021) with a fixed expert as the target: coef · mean((μ(s) − a_E(s))²) / 4, where μ(s) is the actor's mean action and a_E(s) the expert's, both in agent units. Dividing by 4 maps the squared distance of two actions in [-1, 1] to [0, 1]. Unlike OnlineBC, it is unweighted and needs no expert critic. Give the agent the same expert as its expert_policy to use a stateful one: the term then reads the actions the agent stored along each trajectory.

    With anneal_frac=f, the term's weight falls linearly from 1 to 0 at the fraction f of training, as in kickstarting (Schmitt et al., 2018), so the agent ends on its own objective. Kickstarting uses a cross-entropy to a stochastic teacher and tunes the schedule; here the expert is deterministic and the schedule linear.

    The agents that take ImitationLoss can also start from a clone of the expert, as here on TD3:

    import jax.numpy as jnp

from ajax import TD3
from ajax.extensions.expert import ImitationLoss
from ajax.extensions.pretrain import CloningPretrain


def pd_expert(obs):
    theta = jnp.arctan2(obs[..., 1], obs[..., 0])
    return jnp.clip(-(2.0 * theta + 0.5 * obs[..., 2]), -2.0, 2.0)[..., None]


agent = TD3(
    "Pendulum-v1",
    expert_policy=pd_expert,  # logs the expert's own return at evaluations
    learning_starts=500,
    extensions=(
        CloningPretrain(pd_expert, n_steps=1_000, epochs=2),
        ImitationLoss(pd_expert, coef=1.0),
    ),
)
state, _ = agent.train(seed=0, n_timesteps=2_000)

    Learning a PID's gains: gain mode¶

    With a stateful PID expert that exposes learnable_fields, anchor_gains and step_with_gains (TargetGym's FunctionalExpertPolicy after register_learnable_gains), the ExpertGains extension makes an agent schedule the expert's gains instead of acting directly. The off-policy actor-critics, PPO, APO, APG and UDRL run it, with the expert as their expert_policy.

    The actor outputs one number a in [-1, 1] per learnable gain; the gain applied is anchor · max_factor^a, by default between a tenth and ten times the expert's own. The PID computes the action. The replay, or the rollout, holds the gains (the agent's actions, as many as the learnable gains), so the critics score them and the warm-up draws uniform gains; the expert's own action is stored as a_expert, as wide as the environment's action.

    An agent refuses this mode, when it is built, with ResidualPolicy (one action transform per agent), with ExpertActionInput (the expert's action does not exist before the actor has chosen the gains), and with the extensions that use the expert's actions where the policy's go (cloning the expert, OnlineBC, IBRL, MCPretrain, the collection extensions that hand the expert a step, and the like: environment actions against gains, not wired yet).

    It is different from the PID policy, in which the actor itself is a PID whose gains are learned, on most continuous-action agents.

    Acting around a controller¶

    ajax.extensions.structure holds three arms that keep the expert and change what is around it. Each asks only for what it uses: the expert's call expert(memory, obs), which columns of the observation hold its targets and its readings, and its gains. TargetGym's batched controllers have that form, and its environments name the columns in obs_target_index and obs_value_index. Read them from the environment rather than writing positions, since observation layouts change between versions.

    • Moving the target. OuterLoopReference(target_channels, max_change), with the expert as expert_policy: the policy outputs one change per target, bounded by max_change in the target's units, and the expert acts on the moved target. No change is the expert.
    • Scheduling gains. GainScheduledLaw(expert, obs_width) as expert_policy, with ExpertGains(max_factor=2.0): the policy sets a multiplier per gain, and the multipliers move at most max_log_rate a step. The action changes as the law does between two steps at the same gains (the velocity form), so a new gain alone moves nothing, and unit multipliers are the law. Add ExpertStateInput.for_expert(layer), so that the policy reads the multipliers it moves from.
    • Tracking what ran. Add BumplessTracking(reading_channels) to a switching or blending arm (JSRLCurriculum, CHEQ, IBRL, ResidualPolicy): the expert's memory takes the error at which it would have output the action applied, which an environment reports in info["applied_action"], and otherwise the command. Without it, the memory advances on the error whoever acts. A step the expert chose itself stays its own, and a law sitting at its own limit keeps its own anti-windup. Handing back still steps by the proportional term.

    GainScheduledLaw reads the expert's step_with_gains, learnable_fields and anchor_gains. TargetGym's batched form has them for the laws it registers. For the others, ExpertLaw builds them from the law:

    # doc: skip
from target_gym.registry import REGISTRY

from ajax.extensions.structure import ExpertLaw

law = ExpertLaw.of(
    REGISTRY["four_tank"].make_pid_controller(),
    gain_names=("Kp_1", "Ti_1", "Kp_2", "Ti_2"),
)

    Limits and caveats¶

    • No expert with memory. With memory=, every agent but APG refuses an expert and the extensions acting in its learner.
    • φ* is SAC's. MCPretrain, and the extensions reading the φ* it fits (OnlineBC, CriticBlend, MCVarianceCorrection, ValueBox, PhiRefresh), run on SAC only; the catalogue gives each extension's scope.
    • Stateless queries. An extension that calls its expert on replayed observations needs a stateless expert, unless it is the agent's own on an agent that stores its actions (The expert).
    • Budgets add up. The prefill, cloning and MCPretrain rollouts run before the first training step and are not counted in n_timesteps.
