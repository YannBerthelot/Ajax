    Extensions¶

    An extension adds a research feature to an agent's training without changing the agent: an extra term in a loss, a change to the TD target, another way to pick actions while collecting, an expert to learn from, a pre-training step, or measurements logged at each evaluation. Ajax ships thirty-two of them, listed in the catalogue below.

    Why extensions instead of agent options? An agent's constructor takes its paper's hyperparameters plus extensions=(). The exceptions are expert_policy (SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, PPO, APO, IQL, DAgger), whose return each evaluation logs, and eval_expert_policy, an expert used for that comparison alone. SAC's former options are extensions now (SAC): its expert prefill and warm-up mix are ExpertPrefill and ExpertWarmup, its store_policy_action is StorePolicyAction. Observation features (an expert's action or state, the training progress) are extensions too: ajax.extensions.observe, on every agent that collects with the shared collector. A feature written into an agent grows that agent's file and ties it to one experiment; SAC once had about a hundred constructor keywords that way. Kept apart, a feature works with every agent that runs the parts of training it touches, and each agent's code stays readable next to its paper.

    Using extensions¶

    Pass a tuple (or list) of extension objects as extensions=. Each object holds its own settings:

    from ajax import PPO
from ajax.extensions.instrumentation import BiasVorePenalty, ConditioningMetrics
from ajax.logging import LoggingConfig

agent = PPO(
    "CartPole-v1",
    extensions=(
        BiasVorePenalty(alpha=0.3),  # an extra critic-loss term
        ConditioningMetrics(),  # measurements at each evaluation
    ),
)
logging = LoggingConfig(log_frequency=8_192, backends=())
state, evaluations = agent.train(seed=[1, 2], n_timesteps=16_384, logging_config=logging)
print(evaluations["Cond/critic_srank"])  # one row per seed, one column per evaluation

    A few rules follow from how Ajax compiles training:

    • Extensions are fixed for a run. They are compiled into the training program, so changing a setting means a new agent and a new compilation. Two extensions with equal settings compare and hash equal, as static arguments must. A second agent built the same way traces the same program again, and the compile cache loads it instead of compiling it, unless the run logs.
    • What changes during training lives in the agent's state, in state.ext_state (one entry per extension). It is saved in checkpoints and carried over when you resume a run.
    • One-shot work runs once. An extension's initial state and its pretrain step run on a fresh run only, not when a run resumes from initial_state=.
    • Measurements need evaluations. Extensions that add metrics run when the agent evaluates, which needs a logging_config. Their keys then appear in the returned evaluations next to Eval/episodic mean reward (see Logging).
    • Order matters only where it can. Target changes apply one after the other, in list order. Loss terms add up, so their order does not matter. For collection actions, the last extension that proposes one wins.

    An empty tuple costs nothing: the agent's program is the same as without the argument.

    The phases¶

    An extension overrides one or more phases, the points of the training loop where it may act. Every other phase keeps a default that changes nothing.

    Phase When it runs What it may do Across a stack
    init_state once, on a fresh run build the extension's state one state per extension
    pretrain once, before training, on a fresh run change the agent's state (clone the actor, pre-train a critic) in list order, the replay's seeders (ExpertPrefill, PriorData) first
    reward after each rollout, before the agent's targets replace the rollout's rewards, and update the extension's own state in list order, each sees the previous result
    on_target at each critic update change the TD or value target, and log metrics in list order, each sees the previous result
    critic_loss at each critic update add a term to the critic loss, and log metrics summed
    actor_loss at each actor update add a term to the actor loss, and log metrics summed
    action at each collection step replace the action the agent would take the last proposal wins
    eval_action at each evaluation step, on the agents evaluating through the shared loop replace the executed action the last proposal wins
    transform_action at each collection step, before the action is chosen, in the losses and at evaluation make the executed action a function of the policy's and the expert's; the replay stores the executed one, which the critics score one per agent
    actuate at each collection step, after the action is chosen, and at evaluation execute the chosen action through the expert (gain mode); the replay stores the chosen one one per agent
    choose_warmup_action at each warm-up step (before learning_starts) choose the warm-up's actions instead of the uniform ones, and say whether the expert took them (the replay flags those rows) one per agent; the agents with a uniform warm-up (SAC, TD3, REDQ, ASAC, CrossQ, IQL, AVG)
    choose_replay_action at each collection step, as the replay stores the step choose the action the replay row stores instead of the executed one one per agent; the replay agents (SAC, TD3, TQC, REDQ, ASAC, CrossQ and IQL)
    post_update after each update change the agent's state (schedules, refreshes) in list order
    eval_metrics at each evaluation add metrics to the log merged
    observe whenever an observation arrives, in collection and evaluation append columns to it, stored with it (an observation feature) in column order: the normalised ones, then the raw ones

    The agent hands its stack (an ExtensionStack) to its training step, which makes one call per phase: apply_init (every initial state, then every pretrain), apply_on_target, compute_extensions_critic_loss, compute_extensions_actor_loss, apply_post_update and apply_eval_metrics. Each call gets a random key of its own, on which the agent draws nothing else (init_state and eval_metrics split it, one sub-key per extension). On an empty stack a fold returns its input untouched and draws nothing. The action, transform_action and actuate phases are the exceptions: the agent's controller (its action pipeline, the shared collector and evaluation) calls them directly (see below).

    Which agent runs which phase¶

    Every agent runs pretrain, post_update and eval_metrics, which belong to the shared training loop. The others depend on what the agent's update has: a target, a critic, an actor, a collection step it lets an extension change.

    Agent on_target critic_loss actor_loss action, transform_action
    SAC yes yes yes yes, with an expert_policy
    TD3, REDQ, CrossQ, TQC, ASAC, AVG, IQL yes yes yes no
    PPO, APO yes (value targets) yes yes no
    DQN, PQN yes yes (the Q-network's loss) no no
    UDRL, DAgger, APG no no yes no
    DreamerV3, TDMPC2, TDMPC2MultiTask no no no no

    What an agent has, and what an extension needs¶

    Each agent says what its algorithm has, in capabilities:

    Capability Meaning Agents
    actor a policy network trained by gradient all but DQN, PQN
    q_critic a learned action value Q(s, a) SAC, TD3, REDQ, CrossQ, TQC, ASAC, AVG, DQN, PQN, TDMPC2, IQL
    v_critic a learned state value V(s) PPO, APO, DreamerV3, IQL
    discounted it maximises a discounted return all but ASAC, APO, UDRL, DAgger, APG
    replay its updates sample stored past transitions SAC, TD3, REDQ, CrossQ, TQC, ASAC, DQN, UDRL, DAgger, DreamerV3, TDMPC2, IQL
    off_policy its update stays correct on actions its policy did not choose all but PPO, APO, APG
    critic_ensemble two critics or more SAC, TD3, REDQ, CrossQ, TQC, ASAC, TDMPC2, IQL; AVG with num_critics of 2 or more
    target_critic a slowly updated copy of its critic, which its bootstrap reads SAC, TD3, REDQ, TQC, ASAC, DQN, TDMPC2, IQL
    distributional_critic its critic predicts quantiles of the return, and regresses on many target values per row TQC
    obs_networks its policy and value networks read the observation, not a world model's latent state (memory needs it) all but DreamerV3, TDMPC2
    reward_learning it learns from the reward, not from an expert's labels alone (ExpertActionInput needs it) all but DAgger

    A run adds what its configuration gives: critic (a Q or V critic), scalar_target (a critic regressing on one target value per row, not a distributional_critic: the extensions that blend, replace or compare that value need it), continuous_actions or discrete_actions (the environment), agent_expert (the agent has an expert_policy), stored_steps (a replay, or the latest rollout an on-policy or incremental agent keeps), and phi_star when an extension of the stack fits it (MCPretrain).

    An extension needs what its phases imply (on_target and critic_loss a critic, actor_loss an actor, action an off-policy update, since the executed action is then not the policy's, transform_action continuous actions) and what it declares in requires. An extension needing nothing runs on every agent. When the agent is built, an extension needing something its run lacks is refused with MissingCapability, which names it:

    import jax.numpy as jnp

from ajax import DQN
from ajax.extensions.expert import ImitationLoss


def expert(obs):
    return jnp.zeros(obs.shape[:-1] + (1,))


try:
    DQN("CartPole-v1", extensions=(ImitationLoss(expert),))
except ValueError as error:
    print(error)  # DQN cannot run ImitationLoss ('imitation_loss'), which needs actor (...), continuous_actions (...).

    When the run has everything but the agent's code does not pass it on yet (it does not fold the phase, bind the extension's context, put a batch key in the phase's batch or store a replay field), the refusal is NotWired, which says what is missing.

    Compatibility shows, for every agent and module, which runs, which the algorithm cannot run, and which is not wired yet.

    Two more limits:

    • action is SAC's alone, and only with an expert_policy and without gain mode (ExpertGains). transform_action runs on SAC, TD3, REDQ, TQC, CrossQ, ASAC and AVG, whose critics score the executed action, and on PPO, APO and IQL, whose updates read the policy's own action (IQL's replay keeps it beside the executed one), and on APG and UDRL, in their own rollouts. actuate runs on SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, PPO, APO, IQL, APG and UDRL, with an expert. SAC's collection step offers two places for an extension to act, before and after its warm-up choice, and an extension says which one in its action_slot ("pre_warmup" or "post_warmup"). Expert guidance explains them.
    • Memory and extensions do not mix yet. With memory=, PPO, SAC, TD3, REDQ and ASAC raise when training starts if you also pass extensions. APG takes both.

    What a phase hands an extension¶

    on_target, critic_loss and actor_loss hand the extension a batch dictionary of the quantities at that point of the update. Every agent folding a phase passes the keys of the first column; each agent lists the rest in its phase_batch_keys (ajax.SAC.phase_batch_keys, for instance). The replay actor-critics (SAC, TD3, REDQ, CrossQ, TQC, ASAC, AVG, IQL) share most of theirs:

    Phase Every agent folding it The replay actor-critics add
    on_target observations, next_observations, rewards, gamma actions, dones, reward_scale, raw_next_observations, next_a_expert, next_action (None where nothing stores them), next_actions, critic_subset
    critic_loss observations, targets actions, next_observations, critic_params, critic_state, actor_state, return_to_go
    actor_loss actor_params actor_state, observations, raw_observations, pi_mean, agent_loss, critic_state; actions and a_expert on most (None without an expert_policy)

    PPO and APO add terminated, truncated, gae and values to on_target; DQN and PQN add actions, dones, reward_scale and their q_state; APG's actor_loss holds its rollout and returns. pi_mean is None for a discrete policy.

    gamma is None for an average-reward agent. dones marks where the target cut the bootstrap. targets is the target, held constant. The critic (critic_params, or DQN's and PQN's q_state) and the actor (actor_params) are the parameters being differentiated. pi_mean is the actor's mean action. raw_observations are the environment's own observations, before any normalisation; a replay agent keeps them only in a run with an expert, and passes None otherwise, except UDRL, whose segments hold them anyway. next_actions are the next actions the target scored (None for a target on a state value, IQL's V(s')). critic_subset holds the indices of the target critics whose minimum the target took, where it took a random subset of them (REDQ's), and None where it took all of them. An agent's own keys are in its phase_batch_keys.

    An extension never falls back to adding nothing, so a misplaced extension cannot look like a result. One declaring the keys it reads (batch_keys) is refused when the agent is built if the batch lacks them: ImitationLoss on PPO, whose actor batch has no pi_mean. One reading a key it does not declare raises when the program is built.

    What an extension declares¶

    Besides its phases, an extension states what it needs as class attributes, which the agent reads when it is built:

    Attribute What it says
    buffer_fields replay fields beyond the agent's own that the extension reads. Today only raw_next_obs, the environment's own next observation; SAC, TD3, REDQ, ASAC and AVG store it when an extension declares it, and the other agents refuse such an extension.
    expert_fields the fields holding an expert. The agent converts each one to agent units, and a run whose extensions hold an expert keeps the replay fields only experts read.
    experts() the experts the extension calls itself, without a state, on the observations it is given.
    reads_agent_expert_actions the extension reads the expert's actions the agent stored at collection when its expert is the agent's own expert_policy (SAC, TD3, REDQ, ASAC, AVG and APO store them).
    uses_expert_actions_as_policy_actions() the extension puts an expert's actions where the policy's go: as the actor's target, or as an action its critics score. Gain mode refuses it, since there the policy chooses gains.
    requires the capabilities it needs beyond those its phases imply (needs() returns them all; an extension whose needs depend on its options overrides it).
    provides the capabilities it gives the rest of its stack: MCPretrain provides phi_star.
    context the agent-context keys it cannot work without (bind_to_agent); an agent's extension_context lists those it binds.
    pretrain_context the ExtensionContext fields its pretrain reads (update, buffer: PriorData); an agent's pretrain_context lists those its loop fills.
    batch_keys per phase, the batch keys it reads beyond those every agent folding the phase passes (reads() returns them).
    reads_step_in_episode the extension reads each copy's step within its episode, which the agent then counts.
    reads_last_rollout the extension reads the agent's latest rollout (state.last_rollout), which an on-policy or incremental agent then keeps.
    action_slot where in SAC's action pipeline its action runs.

    φ* is a separate critic fitted to an expert's returns before training. MCPretrain fits it (it provides phi_star); OnlineBC, CriticBlend, MCVarianceCorrection, ValueBox and PhiRefresh read it (they require phi_star). Without MCPretrain in the stack they would add nothing for the whole run, or fail when the program is built, so the agent refuses them. EDGEExploration scores with φ* when it exists and with the agent's own critic otherwise, so it needs no MCPretrain.

    What is checked, and when¶

    When the agent is built, its stack is refused (ValueError, naming each offending extension) if an extension:

    • needs a capability the run lacks (MissingCapability): φ* without an MCPretrain in the stack, the agent's expert_policy on an agent without one, a Q critic on PPO;
    • implements a phase the agent does not run, needs context the agent does not bind, reads a batch key the phase's batch lacks or a replay field the agent does not store (buffer_fields) (NotWired);
    • calls a stateful expert without its state. An extension calls its expert on the observations it is given, where no expert state exists. A stateful expert is allowed only when it is the agent's own expert_policy, on an agent that stores its actions from the expert's tracked state, and the extension reads those actions;
    • (SAC) acts in collection without an action_slot, or acts in collection or makes the policy residual in a run without an expert_policy or with gain mode.

    When training starts, CloningPretrain raises when placed after another pre-training extension, and PriorData on a replay whose rows it cannot fill.

    Catalogue¶

    The checks above are necessary but not always sufficient: the last column says where each extension does its job, and Compatibility, generated from the code, where the agent accepts it. "SAC with an expert" means SAC(..., expert_policy=...).

    Learning from an expert (ajax.extensions.expert)

    Extension What it does Phases Works with
    OnlineBC Pulls the actor's mean action towards the expert's, weighted by φ*'s value at each state, fading to zero over the first critic_warmup_frac of training. Logs online_bc/term and its weight online_bc/weight. actor_loss SAC with an expert and MCPretrain
    ImitationLoss Adds coef · mean((μ(s) − a_E(s))²) / 4, the behaviour-cloning term of TD3+BC, towards a fixed expert it holds. When that expert is the agent's expert_policy, it reads the actions the agent stored, so the expert may be stateful. With anneal_frac, its weight falls linearly to 0 at that fraction of training (kickstarting). With q_filter=True a row counts only where the critic rates the expert's action above the policy's (Q-filtered BC), and evaluations log the share of a replay batch it keeps (imitation/q_filter_frac; not on AVG, which keeps no replay). With target="replay" it clones the replayed rows' own actions, so logged data needs no expert, and with alpha the actor loss becomes TD3+BC's: λ times the agent's own loss plus coef · mean((μ(s) − a)²) with no / 4, λ = alpha / mean|Q_1(s, μ(s))|, the actions compared in the environment's units (see TD3+BC). Logs imitation/term and the squared distance before the filter and the schedule, imitation/mse. actor_loss, eval_metrics SAC, TD3, REDQ, ASAC, AVG, APO, DAgger, and PPO, APG and UDRL with a stateless expert (they take none); a discrete policy has no mean action and raises (no cross-entropy form yet). q_filter=True: SAC, TD3, REDQ, ASAC and AVG, without ResidualPolicy; refused where the critic rates states, not actions (PPO, APO), or there is none (APG, UDRL)
    ResidualPolicy Executes clip(a_E + scale · a_π, −1, 1): the policy learns a correction on top of the expert. The replay stores the executed action and the critics score it. transform_action SAC (without gain mode), TD3, REDQ, TQC, CrossQ, ASAC, AVG, PPO, APO, IQL, APG and UDRL with an expert
    ExpertGains Gain mode: the policy's action a sets each of the expert's learnable gains to anchor · 10^a, and the expert acts with them; the replay and the critics hold the gains. Needs a stateful expert with learnable_fields (register_learnable_gains). actuate SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, PPO, APO, IQL, APG and UDRL with such an expert, without ExpertActionInput
    ExpertWarmup During the warm-up, the expert takes a share fraction of the steps (one draw per step for every copy) and uniform random actions the others; the replay flags the rows the expert took. It acts in the controller only: no state, no key in the learner. choose_warmup_action SAC, TD3, REDQ, ASAC, CrossQ, IQL, AVG and DQN with an expert and learning_starts > 0
    JSRLCurriculum The expert acts for the first H_t steps of each episode, the policy afterwards; H_t shrinks from episode_length to 0 over decay_frac of training. Logs jsrl/horizon and jsrl/expert_frac. action, eval_metrics an off-policy agent with an expert (SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, IQL, DAgger, DQN, PQN), and UDRL
    StorePolicyAction An off-policy-correctness ablation: the replay stores the action the policy chose, not the one executed, so the rows an expert, a warm-up or a residual acted in no longer hold the action behind their reward and next observation. It acts in the controller only. choose_replay_action SAC, TD3, TQC, REDQ, ASAC, CrossQ, IQL, DQN and UDRL; not DAgger, which learns from no stored action
    ExpertValueMetrics Logs the critic's value at the expert's actions (value/q_expert_mean), its gap to the value of the actions taken (value/q_gap) and, with MCPretrain, its gap to φ* (value/phi_star_q_gap_ood), on one replay batch per evaluation. eval_metrics SAC, TD3, REDQ, TQC, CrossQ, ASAC, IQL and DQN with an expert

    Observation features (ajax.extensions.observe)

    Extension What it does Phases Works with
    ExpertActionInput Appends the expert's action at each observation, from the state the agent tracks it in; raw (an action). observe agents with an expert (SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, IQL, PPO, APO, DQN, PQN, APG, UDRL), not under gain mode (ExpertGains); not DAgger, which would read the label it learns
    ExpertStateInput Appends a stateful expert's internal state before its call at the observation (ExpertStateInput.for_expert(expert) sizes it). observe agents with a stateful expert (SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, IQL, PPO, APO, DAgger, DQN, PQN, APG, UDRL)

    TrainingProgressInput Appends the fraction of training done (ajax.schedule.progress); an evaluation holds the collector's. observe every agent but TDMPC2MultiTask, whose dataset holds no feature columns

    Exploration (ajax.extensions.exploration)

    Extension What it does Phases Works with
    EDGEExploration Lets the expert act in place of the policy, step by step, as a gate (gate=) decides. "fixed": with probability fixed_prob; "argmax": whenever the critic rates the expert's action higher; "boltzmann": with a probability that grows with that gap. These three fade out over decay_frac of training. "lcb", "argmax_lcb" and "thompson" also weigh the critics' disagreement. Logs edge/live_expert_frac and its gate's schedule (edge/decay or edge/beta). action, eval_metrics an off-policy agent with an expert, continuous actions (SAC, TD3, REDQ, TQC, CrossQ, ASAC, AVG, IQL, DAgger)

    Changing the critic's target (ajax.extensions.target_mods)

    Extension What it does Phases Works with
    IBRL Adds γ(1 − d) · max(Q(s′, a_E) − Q(s′, a′), 0) to the target, so the values match acting with whichever of expert and policy looks better: a′ is the next action the target scored, Q the minimum over the critics the target took its minimum over. On REDQ the expert is selected on a fresh random subset of critics, so the bonus can be negative (Expert guidance). With hybrid_acting (the default), it also acts with whichever of the two the target critics rate higher, in collection and evaluation. soft_choice=True draws the choice instead, in acting and in the target (whose bonus can then be negative), taking the expert's action with probability sigmoid(soft_choice_beta · (Q(a_E) − Q(a))) (soft_choice_beta 10 by default). Logs ibrl/bonus and ibrl/expert_wins, and with hybrid_acting ibrl/expert_frac. on_target; action, eval_action, eval_metrics with hybrid_acting SAC, TD3, REDQ, TQC, IQL; refused on an average-reward target (ASAC, APO), which has no discount for the bonus
    LCBGatedBootstrap Blends the policy's and the expert's next-action values in the target, weighted by a sigmoid of their pessimistic (lower-confidence-bound) scores. Logs its pessimism lcb_bootstrap/beta and its mean gate lcb_bootstrap/p_expert. on_target, eval_metrics SAC, TD3, REDQ, which have critic ensembles; refused on an average-reward target (ASAC, APO)
    CriticBlend Blends the target with a one-step target on φ*, (1 − α) y + α y_E, with α falling from 1 to 0 over critic_warmup_frac. Logs α as critic_blend/expert_weight, and critic_blend/target_gap. on_target, eval_metrics SAC with MCPretrain
    MCVarianceCorrection Where the critics disagree by more than threshold (variance), uses φ*'s value as the target. Logs mc_variance/replaced_frac. on_target SAC with MCPretrain
    ValueBox Lets the expert act where its value under φ* exceeds a threshold that rises from the lowest to the highest expert value over training. Logs value_box/threshold, value_box/in_box_frac and value_box/expert_frac. action, eval_metrics SAC with an expert and MCPretrain

    Pre-training (ajax.extensions.pretrain)

    Extension What it does Phases Works with
    CloningPretrain Rolls the expert out for n_steps steps per copy and trains the actor to reproduce its actions (epochs passes in batches of batch_size, at the actor's learning rate); the agent's observation statistics start from the dataset's. Logs the mean loss of its first and last epoch, cloning/first_loss and cloning/last_loss. pretrain, eval_metrics SAC, TD3, REDQ, ASAC, AVG, APO, DAgger (other agents refuse it when built)
    MCPretrain Rolls the expert out, fits φ* to its Monte-Carlo returns, records its value range, and by default nudges the agent's own critic towards it. Logs the range, mc_pretrain/v_min and mc_pretrain/v_max, and the fit: its first and last loss, mc_pretrain/first_loss and mc_pretrain/last_loss, and φ*'s mean value at the expert's actions, mc_pretrain/q_expert_mean. pretrain, eval_metrics SAC (other agents refuse it when built)
    BellmanPretrain Runs n_steps ordinary critic updates on the replay buffer before training, once ExpertPrefill or PriorData has filled it. Its values bootstrap from an untrained critic; kept for ablations. Logs the critic loss of its first and last update, bellman_pretrain/first_loss and bellman_pretrain/last_loss. pretrain, eval_metrics SAC with ExpertPrefill or PriorData
    PhiRefresh Every interval steps, refits φ* for steps updates on the replay rows where the expert acted. post_update SAC with an expert and MCPretrain
    PriorData Adds a transition dataset (ajax.buffers.dataset) to the replay, where it stays, and to the observation and reward statistics, then runs offline_updates of the agent's own update on it before acting. Pair it with learning_starts=0. pretrain SAC, TD3, REDQ, ASAC, TQC, CrossQ, IQL, DQN (other agents refuse it when built)
    ExpertPrefill The agent's expert acts n_steps steps in every copy before training, and its transitions go to the replay as collection writes its own, flagged as expert rows. They count once in the observation and reward statistics, as PriorData's do, and in no timestep. It runs before the other pre-training, which may read its rows. pretrain SAC, REDQ, ASAC, TQC, TD3, CrossQ, IQL with an expert_policy

    Offline RL (ajax.extensions.offline)

    Extension What it does Phases Works with
    ConservativeQ CQL(H)'s critic term: alpha times, for each critic, the logsumexp of its values at n_actions uniform actions and as many of the policy's at s and s' (each less its log-density), minus its value at the data's action. Logs cql/term and cql/gap. critic_loss SAC, REDQ, ASAC, AVG, IQL: a Q critic and a policy with a density, refused on a deterministic one (TD3); see SAC
    CalQL ConservativeQ with the policy actions' values floored at the row's return to go (Cal-QL), from a transition dataset (return_to_go; collected rows have none). Also logs calql/bound_frac, the share it raised. critic_loss SAC, REDQ, IQL (the replays that keep the return to go); refused on an average-reward critic (ASAC), without a replay (AVG) or on a deterministic policy (TD3)
    TargetBC ReBRAC's critic penalty: the target less γ (1 − d) β Σ (ã′ − a′)², ã′ the next actions the target scored and a′ the dataset's next action (next_action; a row without one keeps its target). Logs target_bc/penalty and target_bc/known_frac. on_target TD3, whose on_target batch holds its target's next actions (see ReBRAC)

    Extension What it does Phases Works with
    AdversarialReward GAIL: a discriminator, trained after each rollout to tell its rows from a transition dataset of demonstrations, replaces the rollout's rewards with -log(1 - D(s, a)); the environment's own reward is not used.     Measuring the critic (ajax.extensions.instrumentation)

    Extension What it does Phases Works with
    ConditioningMetrics Logs the critic's effective rank (Cond/critic_srank), its fraction of dormant units, its feature and weight norms. It finds the critic from the agent's networks: an ensemble critic, or a Q-network. eval_metrics replay agents given buffer= (SAC, TD3, REDQ, ASAC, DQN); PPO, APO, PQN and AVG, which keep their latest rollout for it (AVG's is one step per copy)
    BiasVoreDecomposition Splits the critic's squared one-step error into squared bias and variance (EVarEst/bias_sq, EVarEst/var_resid, EVarEst/mse, EVarEst/abs_bias), against a one-step target on its current parameters, or your own value_target_fn. eval_metrics as ConditioningMetrics
    BiasVorePenalty Adds ((1 − 2α)/α) · Var(residual) to the critic loss; alpha=0.5 adds nothing. Logs bias_vore/penalty and bias_vore/residual_var. critic_loss every agent with a critic_loss phase: SAC, TD3, REDQ, ASAC, AVG, PPO, APO, DQN, PQN

    Measuring a replay agent's critic¶

    ConditioningMetrics and BiasVoreDecomposition need states the agent has visited. An on-policy or incremental agent keeps its latest rollout for them, as in the example at the top of this page. A replay agent keeps them in its replay buffer, and the extension must be given the buffer object. The extension is built before the agent, so take the buffer from an agent built with the same settings (n_envs, buffer_size, batch_size):

    from ajax import SAC
from ajax.extensions.instrumentation import BiasVoreDecomposition, ConditioningMetrics
from ajax.logging import LoggingConfig

buffer = SAC("Pendulum-v1", learning_starts=500).buffer  # same settings as below
agent = SAC(
    "Pendulum-v1",
    learning_starts=500,
    extensions=(ConditioningMetrics(buffer=buffer), BiasVoreDecomposition(buffer=buffer)),
)
logging = LoggingConfig(log_frequency=1_000, backends=())
state, evaluations = agent.train(seed=0, n_timesteps=2_000, logging_config=logging)
print(evaluations["Cond/critic_dormant_frac"], evaluations["EVarEst/bias_sq"])

    When the batch they need is not available yet (an evaluation before the first rollout, say), these extensions log nothing rather than wrong numbers.

    Extensions that need the agent's context¶

    Some extensions need objects only the agent builds: its environment, network settings, optimisers, replay buffer or discount. They receive them through bind_to_agent, which an agent calls on its whole stack when it builds its training program; each extension picks the arguments it needs and returns a filled-in copy. Each agent lists the keys it binds in its extension_context. SAC binds everything its extensions read, which is why MCPretrain, BellmanPretrain and PhiRefresh work with SAC only. TD3, REDQ, ASAC, AVG and APO bind their environment, actor optimiser and expert_policy, which is what CloningPretrain needs; TD3, REDQ and ASAC also bind their replay buffer, which ExpertValueMetrics reads. DreamerV3 binds its own context. The other agents bind nothing. You never call bind_to_agent yourself.

    Writing your own¶

    An extension is a frozen dataclass subclassing Extension that overrides the phases it needs and declares what it reads. Writing an extension walks through the contract, the dictionary each phase receives on each agent, and a complete example. If a feature seems to need a new keyword on an agent, that is the sign it should be an extension instead.
