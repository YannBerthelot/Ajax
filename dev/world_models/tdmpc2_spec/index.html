    TD-MPC2: implementation reference (merged and verified)¶

    This document gives the Ajax (JAX) implementer one place to work from instead of the paper and the code. Each row merges the extractor's spec with the adversarial verifier's corrections and the items the verifier found missing. Re-checks made during the merge are logged in §0.5.

    0. Sources, pinned versions, conventions¶

    0.1 Sources¶

    Source Pin Notes

    0.4 Conventions¶

    • Symbols: H = horizon = 3; B = batch; L = latent_dim; A = action dim (padded A_max in multi-task); K = num_bins = 101; N = num_samples = 512; P = num_pi_trajs = 24; E = num_elites = 64; Nq = num_q; T = episode length in agent steps (after action repeat); ST = single-task; MT = multi-task.
    • Tensors are time-major (T, B, ·). ‖·‖ is the L2 norm. "Agent step" means one action-repeated env.step.
    • Paper-vs-code labels: agree, conflict, code_only, paper_only.

    0.5 Merge log: corrections applied and re-checks made during the merge¶

    1. All verifier corrections are applied. No correction was rejected.
    2. JAX truncated_normal. The model spec said it "truncates at ±2σ and rescales the std". The update verifier recalled a 1/0.8796 rescale. I checked the installed source (Ajax/.tox/py/.../jax/_src/nn/initializers.py, jax 0.10.2): random.truncated_normal(key, -2, 2, …) * stddev, with no std correction. With stddev 0.02 it truncates at ±0.04 and the realised std is ≈0.0176. Both claims are therefore off for this version. The conclusion is unchanged: use jax.nn.initializers.normal(0.02) (§1.13).
    3. When the task-embedding leak started. The specs cite 8b73181 and 603b67c. Both are dated 2024-09-25, share parent 88095e7 and are in HEAD lineage, so both are cited.
    4. Origin of the termination head. 26c7211 and cc62c4c are both "init" commits dated 2024-01-07 and both in HEAD lineage. Both are cited.
    5. b67b21c vs 5f6fade. Verified with git diff: the agent algorithm is identical (see §0.1). The b67b21c buffer was confirmed in git show b67b21c:tdmpc2/common/buffer.py (capacity in episodes, RandomSampler, RandomCropTensorDict(H+1)).
    6. The b67b21c dropout no-op. Confirmed. Ensemble.modules() was overridden to return the stateless nn.Sequential. Iterating it yields only the top-level NormedLinear/Linear children, none of which is an nn.Dropout, so m.p = 0 never ran.
    7. Step units of the results CSVs. Confirmed: myo-hand-key-turn.csv (action repeat 1) is spaced 50,000 apart and walker-run.csv (action repeat 2) 100,000 apart.
    8. 5f6fade update_pi was read directly: pi_optim.zero_grad at the start, track_q_grad(False), online Q(..., 'avg') in train mode, pi_loss = ((β·log_pis − qs).mean((1,2))·ρ).mean().
    9. Task-embedding max_norm in JAX. The update spec recommended "project after each optimizer step". The model verifier showed this is not exact, and the training verifier showed the "stop-gradient scale" formula is self-contradictory. The lazy look-up-time renorm with write-back is adopted (§1.22).
    10. Q-ensemble dropout at PE (correction made in M2 by running 5f6fade). Rows 1.1, 1.10, 2.3, 2.15, 2.16, 3.3 and 3.14, §2.A, the §2.C pseudocode and the §3.C pseudocode describe the HEAD behaviour; each carries a [PE: …] marker. At 5f6fade (and b67b21c) Ensemble wraps the functional module of combine_state_for_ensemble in a torch.vmap closure; that module is not a registered child, so model.train() / model.eval() never reach its nn.Dropout and Q dropout is active in every pass: the TD target's target-Q pass, the value and policy losses, and planning. HEAD's tensordict Ensemble registers self.module, so there dropout follows train/eval. See deviations.md §2.
    11. Planning re-checked by running 5f6fade (M3). docs/world_models/parity/tdmpc2_plan_fixtures.py runs the unmodified act()/plan() with every random draw recorded and the per-iteration statistics read from plan()'s locals; Ajax's planner reproduces five chained decisions: t0, two warm starts, an eval-mode warm start, and t0 at an episode boundary while the agent holds a non-zero _prev_mean; with random reward, Q and policy heads, π trajectories are elites in some iteration of every decision (rows 3.5-3.21 confirmed). In the fixture the drawn elite is never a π trajectory (once the Gaussian samples converge they outrank the π trajectories), so that case of 3.19 is covered by Ajax-side tests. Corrections: (a) 3.23 and 3.15: with every value tied, torch.topk (CPU, torch 2.2.2) does not pick "arbitrary" elites but the first 64 candidates in index order, i.e. the 24 π trajectories and the first 40 Gaussian samples, as lax.top_k does (recorded; the CUDA order of the paper's runs is not verified). When tied values straddle the top-k boundary, its CPU topk selects a different subset of them than lax.top_k (lower index first), not only a different order (verified on torch 2.2.2 CPU in the M3 review; not recorded in the fixture). (b) 3.10 and §3.A: planning runs in eval mode but, at PE, with Q dropout (item 10); the model is verified to be in eval mode during plan(). (c) 3.10: the discount powers are Python floats (float64 products), rounded to float32 where they scale a tensor. (d) 3.19: np.random.choice(p=score) is inverse-CDF sampling with one uniform (cumsum, normalised by its last entry, searchsorted(side='right')); Ajax uses the same algorithm, in float32.
    12. Multi-task re-checked by running 5f6fade (M8). docs/world_models/parity/tdmpc2_multitask_fixtures.py runs the unmodified agent with cfg.multitask=True on three synthetic tasks of different obs/action dims (padded), recording the embedding table on entry to update(), at the _td_target call, on entry to update_pi and on exit, and five act(..., task) decisions (all three tasks); Ajax reproduces every loss, gradient norm, table and planning statistic. Confirmed: (a) 1.22: embedding_renorm_ rescales only looked-up rows of norm > 1, by 1/(norm + 1e-7); inside one update it binds at the first look-up (encode(obs[1:]), pre-step) and again at the policy loss' first look-up after optim.step() (post-step: an Adam step can push a renormed row back above 1, which the fixture records), so "renorm once per update" would miss the second write-back (row 1.22 corrected); rows absent from a batch are not renormed and still move by Adam momentum; act() persists its renorm (Ajax: T15). (b) 1.9/1.23: masked dims are exactly 0 in the policy's action, and n in the entropy is the valid-dim count per sample. (d) 2.20/3.12: the per-task discounts are a float32 tensor; in planning discount *= self.discount[task] multiplies float32 tensors (the single-task planner's powers are float64 Python floats). (e) The world-model clip includes _task_emb's gradient, and with track_q_grad(False) the policy loss gives it none (2.18).

    1.A Implementation subtleties (world model)¶

    • Use NormedLinear order Linear → Dropout → LN → act. Dropout appears only in each Q member's first layer.
    • Use LayerNorm eps 1e-5. Flax defaults to 1e-6.
    • Initialise with normal(0.02) (torch's trunc bounds are absolute ±2), not truncated_normal(0.02). Zero the final weight of the reward head and of every Q member. Do not zero π's final layer. Init each Q member with its own key, then stack. Clone the target after zeroing.
    • Concat order: [obs, e] for the encoder, [z, e, a] for dynamics, reward and Q, [z, e] for π and termination. The order is needed for checkpoint compatibility and the paper's parameter counts.
    • SimNorm comes after LayerNorm in the last layer of the encoder and of the dynamics. It has no temperature.
    • Q('min'|'avg'): one randperm(Nq)[:2] per call, shared by the whole batch and horizon. Reduce decoded scalars.
    • two_hot: clamp in symlog space to [−10, 10]; 101 bins linear in symlog space; linear interpolation in symlog space. Decode = symexp(E_p[b]).
    • Shared TwoHot block with DreamerV3: DreamerV3 (revised code, embodied/jax/heads.py:132-144, outs.py:273-330) puts 255 bins at symexp(linspace(−20, 0)) mirrored (raw space), interpolates two-hot weights in raw space, decodes as E_p[bins] with a symmetric summation, and uses log1p/expm1. A shared block therefore needs parameters for bin locations, interpolation space and decode transform. TD-MPC2's configuration is bins = linspace(−10, 10, 101) in symlog space with decode symexp(E_p[b]).
    • Task embedding: use the lazy look-up-time renorm with write-back (§1.22), not differentiable normalisation. Target and detached Q use the online table.
    • There is no observation normalisation and no symlog on observations or latents.
    • MT masking: multiply mean, log_std and ε by the mask before computing the log-prob. Masked actions are then exactly 0.
    • Use the parameter counts in §1.24 as architecture unit tests.

    2.A Implementation subtleties (update)¶

    • The TD target bootstraps from the encoded next observation h(s_{t+1}), not from the dynamics prediction that Eq. 3 literally writes. It is a one-step target per t, with no λ-returns.
    • Every Q head regresses the same y. The value loss is divided by H·Nq; the reward and consistency losses by H. F.mse_loss is a mean over batch and latent dim.
    • ρ weighting: the world-model losses use t = 0..H−1 (1, .5, .25). The policy loss uses t = 0..H (1, .5, .25, .125) and takes a mean over H+1.
    • Freshness: the policy loss uses pre-step zs and post-step Q (and e). The EMA uses the post-step Q. Make this explicit in a functional implementation.
    • Dropout is on for the value-loss and policy-loss Q forwards and off for the TD target and planning, with independent masks per member and per call [PE: dropout active in every Q pass; §0.5 item 10].
    • RunningScale: t=0 Q only, linear-interpolated 5/95 percentiles over the batch, clamp the range at ≥ 1, lerp with τ = 0.01, update before dividing, init 1. It is not checkpointed.
    • The world-model clip is one global norm over all world-model params, not per group. π is clipped separately.
    • Entropy: implement whichever version is chosen explicitly. Never compute HEAD's −lp·scaled/(lp+1e−8) literally; use −n·lp_g.
    • MT: per-sample γ via discount[task]; prefix masks; one RunningScale shared by all tasks; stop-gradient e in the policy loss (recommended).
    • In JAX, thread RNG keys for: π sample in the TD target, TD Q-pair permutation, value-loss dropout (Nq keys), π sample in the policy loss, policy-loss Q-pair permutation, and policy-loss dropout (Nq keys) [PE: and the TD target's target-Q dropout].

    3.C Reference pseudocode: plan() (HEAD, single env)¶

    def plan(obs, t0, eval_mode, task):              # no_grad, eval mode (no Q dropout)  [PE: Q dropout on]
    z = enc(obs[None], task)                     # [1,L]
    if P > 0:                                    # P = 24
        _z = repeat(z, P)
        for t in 0..H-2: pi_a[t] = pi(_z).sample; _z = d(_z, pi_a[t])
        pi_a[H-1] = pi(_z).sample                # [H,P,A]
    z = repeat(z, N)                             # [N,L], N = 512
    mean = zeros[H,A]; std = full[H,A](2.0)      # std NEVER warm-started
    if not t0: mean[:-1] = prev_mean[1:]         # mean[-1] = 0
    actions[:, :P] = pi_a                        # fixed for all iterations
    for it in range(iterations):                 # 6 (+2 if A >= 20)
        actions[:, P:] = clip(mean[:,None] + std[:,None]*randn[H,N-P,A], -1, 1)
        if MT: actions *= mask[task]
        V  = nan_to_num(estimate_value(z, actions, task), 0)    # [N,1]
        ix = top_k(V[:,0], 64)
        eV, eA = V[ix], actions[:, ix]                          # [64,1], [H,64,A]
        score = exp(0.5*(eV - max(eV))); score /= sum(score)
        mean = sum_k score_k*eA[:,k] / (sum(score) + 1e-9)
        std  = sqrt(sum_k score_k*(eA[:,k] - mean)^2 / (sum(score) + 1e-9))
        std  = clip(std, 0.05, 2.0)
        if MT: mean *= mask[task]; std *= mask[task]
    k = categorical(log(score))                  # last iteration
    a = eA[0, k]
    if not eval_mode: a += std[0] * randn[A]
    prev_mean = mean
    return clip(a, -1, 1)

def estimate_value(z, actions, task):
    G, disc, term = 0, 1, zeros[N,1]
    for t in 0..H-1:
        r = two_hot_inv(R(z, actions[t]))
        z = d(z, actions[t])
        G += disc * (1 - term) * r
        disc *= gamma[task]
        if episodic: term = min(term + (sigmoid(Term(z)) > 0.5), 1)
    aH = pi(z).sample
    return G + disc * (1 - term) * Q_avg(z, aH)  # online Q, one random distinct pair per call, decoded then averaged

    3.A Implementation subtleties (planning)¶

    • N = 512 includes the 24 π trajectories: there are 488 Gaussian samples. π trajectories are generated once per step, never resampled, and re-scored every iteration.
    • Prior trajectories and the terminal action use the stochastic squashed sample, even in eval_mode.
    • The warm start shifts only the mean, and the last row is 0. std resets to 2 every step. t0 zeroes the mean. Store the final weighted mean, not the executed action.
    • Clamp candidates to [−1, 1] before evaluation.
    • In the value estimate, the reward comes from (z_t, a_t) before the dynamics step. The terminal value is γ^H · avg of 2 decoded online heads at π(z_H).sample.
    • Score is exp(0.5·(V − max)) over elites. The 0.5 multiplies.
    • std is the biased weighted std around the new mean, clamped to [0.05, 2]. MT masking comes after the clamp.
    • There is no momentum and no elite carry-over.
    • eval_mode removes only the final additive noise.
    • Planning uses only online networks, in eval mode [PE: Q dropout still on, §0.5 item 10]. Target and detached Q are not used, and RunningScale is not applied.
    • Functional/vmapped Ajax port (a design choice the reference does not cover): carry prev_mean [E,H,A] in the actor state; compute t0 per env from the previous done/reset flag; mean = where(t0[:,None,None], 0, shift(prev_mean)). Split keys for: the H π samples of the prior trajectories; per-iteration Gaussian noise, terminal-π ε and Q-pair permutation; the final categorical draw; and the exploration noise. Use lax.top_k and lax.fori_loop/scan (all shapes static).
    • Seed phase: random actions while step ≤ seed_steps. The first planned call is usually t0 = False (stale warm start, 3.22).

    3.B Open questions (planning)¶

    • σ warm start: the paper warm-starts (μ, σ); the code warm-starts only μ. Recommendation: the code.
    • Executed action: the paper uses a_t ~ N(μ*, σ*); the code uses a score-sampled elite plus σ*_0 noise. Which takes precedence under "as close to the papers as possible"?
    • Eq. 6 terminal action: planner Gaussian (paper, internally inconsistent) or π(z_H) (code)? Confirm the code.
    • Eval protocol: the trainers use eval_mode=True (still stochastic); evaluate.py is noisy. Which one produced the paper's numbers is unknown. Which should Ajax use?
    • Vectorised envs: per-env t0 and prev_mean generalise the code, but neither the paper nor the code specifies them. Confirm the design.
    • Stale warm start after seeding: reproduce exactly, or treat "no previous plan" as t0? The effect is negligible.
    • App J uncertainty regulariser: in scope (multi-task offline)? It is off by default everywhere, and the branch formula differs from Eq. 9.
    • Episodic termination masking in planning: include it as an Extension (ST only)?
    • Separate planning vs training horizon: keep one shared H (the reference) or expose two?

    4.C Reference pseudocode: online loop (HEAD)¶

    step = 0; done = True; eval_next = False                       # [PE: eval_next = True]
while step <= steps:                                            # steps+1 iterations (default 10_000_000)
    if step % eval_freq == 0: eval_next = True                  # eval_freq = 50_000
    if done:
        if eval_next: eval(); eval_next = False                 # at the NEXT episode boundary; includes step 0
        if step > 0:
            if info['terminated'] and not episodic: raise ValueError
            log(episode_reward = sum(r over tds[1:]), episode_success = info['success'] (last step))
            buffer.add(cat(tds))                                # whole finished episode, T+1 rows
        obs = env.reset(); tds = [row(obs, NaN action, NaN reward, NaN terminated)]
    action = agent.act(obs, t0 = (len(tds) == 1)) if step > seed_steps else env.rand_act()
    obs, reward, done, info = env.step(action)
    tds.append(row(obs, action, reward, info['terminated']))
    if step >= seed_steps:
        n = seed_steps if step == seed_steps else 1             # one-off pretraining burst
        for _ in range(n): agent.update(buffer)
    step += 1
save()                                                          # in-progress episode is discarded

    4.A Implementation subtleties (training loop, replay, envs, MT)¶

    • Slices never cross episodes. Row 0 placeholders are never consumed (losses use rows 1..H). In JAX, store zeros, not NaN.
    • Insert data per completed episode, or sample only fully written windows. The burst at step == S must see exactly the completed seed episodes (5 × 500 transitions on DMC).
    • Random actions run for steps 0..S inclusive. Updates start at step == S with S back-to-back updates, then 1 per agent step.
    • Use an episode ring buffer [N_eps, T+1, ·] with N_eps = 1e6 // T (2000 for DMC) plus randint(episode) and randint(start ∈ [0, T−H]). This is the original b67b21c design and is jit-friendly.
    • The time limit is not terminal. Bootstrap from the final stored obs. terminated is 0 everywhere at PE semantics.
    • DMC: action_scale to [−1, 1], 2 sim steps per agent step with summed reward, flattened obs dict in key order as f32, no obs/reward normalisation, task_kwargs={'random': seed}.
    • Eval: 10 episodes at step 0 and every 50k agent steps, with eval_mode=True. eval_mode removes only the final noise.
    • Compare against the paper and results CSVs at env steps (= 2 × agent steps on DMC).
    • Represent MT machinery as data (a mask table, a discount table and an embedding table indexed by task id), not as agent kwargs, which fits the Ajax Extension rule.
    • MT: offline only, batch 1024, uniform over pooled episodes, no per-task balancing, no planning during training.
    • Neither Adam state nor RunningScale is checkpointed in the reference. Decide explicitly whether Ajax checkpoints them (better for resume, but differs from the reference).
