## Conventions

- **Dimensions.** d = model dimension, which is also the MLP width ("units") and the RSSM "hidden" width. D = 8d is the deterministic state width, g = 8 is the number of GRU blocks, S = 32 is the number of categorical latents and C = d/16 is the number of classes per latent. B = 16 is the batch size, T = 64 the number of trained steps per sequence, K the number of imagination starts per row (K = T) and H = 15 the imagination horizon. N = B·K = 1024 is the number of imagined trajectories.
- **Recommended Ajax configuration.** It uses **d = 256 (12M preset)**: D = 2048, C = 16, feature width 10d = 2560. See the Hyperparameter defaults and Open questions sections.
- **Notation.** `sg` = stop_gradient. symlog(x) = sign(x)·log(1 + abs(x)) and symexp(x) = sign(x)·(exp(abs(x)) − 1). Norms are written ‖·‖. Table cells avoid the pipe character, so absolute values are written abs(·).
- **Code references** are relative to the repo root at e3f0224 unless prefixed with a commit, e.g. `2411f7d:dreamerv3/nets.py:321`.
- **"Paper vs code" labels.** `agree`; `conflict` (paper and code differ); `code_only` (the paper is silent); `partial` (some sub-points agree, others are code_only or conflict).
- **Version note.** Gives differences at 2411f7d (paper era) and, where useful, v1 (8fa35f8). "Same" means algorithmically identical.
- **Where the paper and HEAD conflict,** the "Spec (exact)" cell gives HEAD and flags the conflict. The recommended Ajax default is in the final table, and the choice is listed under Open questions.

## Merge decisions and re-checks (traceability)

1. **All verifier corrections are applied,** and the verifiers' missing items are integrated:
   - sliding windows that cross episodes;
   - asynchronous write-back and parameter lag;
   - integer observations in the paper-era code;
   - weight-layout differences;
   - straight-through routing;
   - report windows;
   - eviction retry;
   - DMC preset history;
   - LR warmup labelled code-only;
   - RMSNorm precision history.
2. **Re-checked in the source and decided:**
   - **replay_context = 0.** The world-model spec said the official code "reuses the last carry of the previous unrelated batch, not a clean zero start". The training spec said it is a zero-state start. **The source shows a zero start.** `Replay.sample` always calls `_annotate_batch(..., is_first=True)`, which sets `is_first[:, 0] = True` (embodied/core/replay.py:126, :284-286). `RSSM._observe` then masks deter, stoch and prevact to 0 wherever is_first holds (dreamerv3/rssm.py:75-80). The old carry is passed in but zeroed immediately, so the world-model spec's note is wrong. This item is corrected.
   - **Asynchronous outs and params.** The delayed write-back (`pending_outs`) and the acting-parameter lag of about two driver iterations (`pending_sync` holds the pre-update non-donated `allo`, swapped only after the next policy call) are confirmed at embodied/jax/agent.py:237-247, :264-289.
   - **The first training batch is prefetched before the 1024-item gate.** Confirmed: train.py:64 builds the stream at setup, Prefetch starts its worker in `__iter__` (streams.py:44-48, :70-77), and `Replay.sample` waits only for `len(sampler) >= 1` (replay.py:121-124).
   - **No 1/2 factor in the symlog MSE in either code version.** At 2411f7d `TransformedMseDist.log_prob` = −Σ(pred − symlog(y))², and at HEAD `outs.MSE.loss` = (pred − sg(symlog(y)))². The conflict with paper Eq. 8 holds for both versions.
   - **Gradient-routing label.** The paper's ablation (Ablations text p.10, Fig. 6b p.9, Fig. 18 caption: "additional reward and value gradients further improve performance") says that **value** gradients shape the representation by default. In the code, imagination features are stop-gradiented, so the replay critic (`repval_grad=True`) is the only path for value gradients into the world model. The training verifier's "agree (implicit)" therefore supersedes the world-model verifier's "code_only" for repval.
   - **dyn-loss gradient reach (new correction found in the merge).** The world-model spec said "dyn trains only the prior net". In the code, prior = _prior(feat['deter']) uses a deter that is **not** stop-gradiented (rssm.py:123), so dyn also trains the core and everything upstream of h_t. This matches paper p.4: "The dynamics loss trains the sequence model". Corrected in 2.14 and in the routing matrix (4.2).
   - **Removed note: "AGC slows zero-initialised tensors".** A constant per-tensor clip factor cancels in g / sqrt(EMA(g²)) when eps = 1e-20. At the first RMS step u = sign(g).
   - **LaProp beta2.** The paper (p.18) says beta2 = 0.99 and describes it as "its default parameters". Both code versions use 0.999. The defaults of the LaProp reference itself were **not verified** here (no literature fetch), so this stays open.

### Algorithm D: two-hot loss and prediction (raw-space interpolation)

```python
def twohot_loss(logits, y, bins):                      # logits [..., n] f32, y [...] f32 raw
    n = len(bins)
    below = clip(sum(bins <= y[..., None], -1) - 1, 0, n - 1)
    above = clip(n - sum(bins > y[..., None], -1), 0, n - 1)
    equal = below == above
    d_below = where(equal, 1, abs(bins[below] - y))
    d_above = where(equal, 1, abs(bins[above] - y))
    w_below = d_above / (d_below + d_above)
    w_above = d_below / (d_below + d_above)
    target = w_below[..., None] * one_hot(below, n) + w_above[..., None] * one_hot(above, n)
    return -sum(target * (logits - logsumexp(logits, -1, keepdims=True)), -1)

def twohot_pred(logits, bins):                         # odd n, m = (n - 1) // 2
    p = softmax(logits)
    m = (len(bins) - 1) // 2
    pb = p * bins
    return pb[..., m] + sum(pb[..., :m][..., ::-1] + pb[..., m + 1:], -1)
```

### Algorithm A: block-GRU core (`RSSM._core`, dynlayers = 1)

```python
def core(deter, stoch, action):     # deter [B, D] bf16, stoch [B, S, C] bf16 one-hot, action [B, A] bf16
    D, Hd, g = 8 * d, d, 8          # Hd = rssm.hidden
    z = stoch.reshape(B, S * C)
    a = action / sg(maximum(1, abs(action)))
    x0 = silu(rms(Linear(Hd)(deter)))          # 'dynin0'  (full deter: the only cross-block mixing)
    x1 = silu(rms(Linear(Hd)(z)))              # 'dynin1'
    x2 = silu(rms(Linear(Hd)(a)))              # 'dynin2'
    x = concat([x0, x1, x2], -1)               # [B, 3Hd]
    x = repeat(x[:, None, :], g, axis=1)       # [B, g, 3Hd]: same embedding for every block
    x = concat([deter.reshape(B, g, D // g), x], -1).reshape(B, g * (D // g + 3 * Hd))
    x = silu(rms(BlockLinear(D, g)(x)))        # 'dynhid0'; RMSNorm over the FULL D vector
    x = BlockLinear(3 * D, g)(x)               # 'dyngru'; no norm, no activation
    r, c, u = split(x.reshape(B, g, 3 * D // g), 3, axis=-1)   # per-block [r | c | u]
    r, c, u = (y.reshape(B, D) for y in (r, c, u))
    r = sigmoid(r)
    c = tanh(r * c)                            # reset gate scales the whole candidate pre-activation
    u = sigmoid(u - 1)                         # u weights the candidate; ~0.27 at init
    return u * c + (1 - u) * deter
```

### Algorithm B: one observe step (`RSSM._observe`), used both when training and when acting

```python
def observe_step(carry, token_t, prevact_t, is_first_t):
    deter, stoch, prevact_t = where(is_first_t, 0, (carry.deter, carry.stoch, prevact_t))
    act = DictConcat(act_space)(prevact_t)     # one-hot for discrete, identity for continuous
    act = where(is_first_t, 0, act)            # mask again: one_hot(0) != 0
    deter = core(deter, stoch, act)            # h_t
    x = concat([deter, token_t], -1)
    x = silu(rms(Linear(d)(x)))                # 'obs0'
    logit = Linear(S * C, outscale=1.0)(x).reshape(S, C)   # 'obslogit', raw
    stoch = bf16(OneHot(logit, unimix=0.01).sample())      # straight-through sample
    return {deter, stoch}, entry={deter, stoch}, feat={deter, stoch, logit}
```

### Algorithm C: one imagine step (`RSSM.imagine`, single=True)

```python
def imagine_step(carry, policy):
    a = policy(sg(carry))                      # pi(. | feat2tensor(sg(carry))).sample()
    deter = core(carry.deter, carry.stoch, DictConcat(act_space)(a))
    x = deter
    for i in range(2):
        x = silu(rms(Linear(d)(x)))            # 'prior0', 'prior1'
    logit = Linear(S * C, outscale=1.0)(x).reshape(S, C)   # 'priorlogit'
    stoch = bf16(OneHot(logit, unimix=0.01).sample())
    return {deter, stoch}, (feat={deter, stoch, logit}, action=a)
```

### Algorithm E: world-model part of the loss (`Agent.loss`, first half)

```python
tokens = enc(obs)                                          # [B, T, d]
carry, entries, feat = rssm.observe(carry0, tokens, prevact, obs.is_first)   # scan, Algorithm B
prior = rssm.prior(feat.deter)                             # [B, T, S, C], parallel
dyn = max(KL(OneHot(sg(feat.logit)) || OneHot(prior)), 1.0)       # summed over S
rep = max(KL(OneHot(feat.logit) || OneHot(sg(prior))), 1.0)
recons = dec(concat(stoch_flat, deter))                    # one dist per obs key
losses[key] = recons[key].loss(sg(obs[key]))  for each vector key   # [B, T] each
x = feat2tensor(feat)                                      # concat(deter, stoch_flat), NOT sg
losses.rew = rewhead(x).loss(obs.reward)                   # two-hot NLL, raw reward
losses.con = conhead(x).loss(f32(~obs.is_terminal) * (1 - 1/333))
losses.dyn, losses.rep = dyn, rep                          # all [B, T]
```

```python
def lambda_return(last, term, rew, boot, disc, lam):     # all [N, L] f32; the code's unused 'val' arg dropped
```

### Algorithm F: imagination actor-critic loss (`imag_loss`)

```python
# inputs on (N=B*K, H+1): act (sg), r_hat = rew.pred(), c_hat = con.prob(1), pi, v, v_slow (all on sg feats)
```

### Algorithm I: one optimizer update (shared by all modules)

```python
def opt_update(params, grads, state):                 # all f32
    k = state.count                                   # 0, 1, 2, ...
    g = {name: gi / max(1.0, norm(gi) / (0.3 * max(1e-3, norm(params[name]))))
         for name, gi in grads.items()}               # AGC per tensor
    state.t_rms += 1
    state.nu = 0.999 * state.nu + 0.001 * g**2
    u = g / (sqrt(state.nu / (1 - 0.999**state.t_rms)) + 1e-20)
    state.t_mom += 1
    state.mu = 0.9 * state.mu + 0.1 * u
    m = state.mu / (1 - 0.9**state.t_mom)
    lr = 4e-5 * min(k / 1000, 1.0)                    # first update: lr = 0
    state.count += 1
    return params - lr * m, state
# then: slowval = 0.02 * val + 0.98 * slowval
```

## Implementation subtleties

### Shared building blocks
- **BlockLinear init uses fan_in = the full input width I**, not the per-block width I/g, because compute_fans multiplies the per-block fan by g. A per-block fan-in makes the GRU weights sqrt(8) ≈ 2.83× too large at init.
- **Every hidden Linear keeps its bias**, even when RMSNorm follows. RMSNorm: eps **1e-4**, statistics in f32, learnable scale only (no shift), output cast back to the activation dtype.
- **`outscale` applies only to the final head Linear**; hidden layers always use 1.0. Policy 0.01 (mean and std Linears), reward 0.0, value 0.0, continue 1.0, RSSM logits 1.0, vector decoder 1.0 (HEAD) or 0.1 (2411f7d). Biases are always zero-initialised.
- **Two-hot:** 255 bins built from a mirrored half for exact antisymmetry. Interpolation is linear in **raw** space between symexp-spaced bins, and targets are **not** symlogged. The expectation **must** use the symmetric pairwise sum, or the reward and value predictions are not exactly 0 at init. Targets must be f32.
- **Unimix (1%) is re-applied every time a categorical is built from logits**, including inside both KL terms after the sg and when sampling. The straight-through estimator uses the **mixed** probabilities: sample = sg(onehot) + p_mix − sg(p_mix). Store raw logits.
- **DictConcat availability masking is all-or-nothing per key and per sample.** Keys are sorted alphabetically. Discrete keys are one-hot encoded and never symlogged.
- **bf16 compute:** Linear outputs, the RSSM carry and the GRU maths are bf16. Norm statistics, distributions, losses, returns and normalisers are f32. An all-f32 Ajax implementation changes numerics only. Note that if Ajax computes in f32, storing replay latents as bf16 is **no longer lossless**.

### World model
- **Core:** the RMSNorm after `dynhid0` runs over the **full D vector**, not per block, and `dyngru` has no norm and no activation. GRU convention: deter' = u·cand + (1 − u)·deter, with u = sigmoid(u_pre − 1) and cand = tanh(sigmoid(r_pre)·cand_pre). The per-block gate layout is [r, c, u] within each block's 3D/g chunk; this matters only for official-weight compatibility.
- **is_first:** zero deter, stoch **and** the previous action **before** the core, and zero the action again **after** one-hot encoding. h at an episode start is core(0, 0, 0). There is no learned initial state in the revised recipe. World-model losses at is_first steps are **not** masked.
- **KL:** free bits clamp max(Σ_latents KL, 1.0) per (b, t), not per latent, and both dyn and rep are clamped. Both are KL(post ‖ prior); the sg goes on post for dyn and on prior for rep. The prior is computed from the **same** h_t that conditioned the posterior, in parallel after the scan, and h_t is **not** stop-gradiented, so dyn also trains the core and everything upstream (merge correction, 2.14).
- **Decoder:** the input order is concat(stoch_flat, deter), while reward, continue, actor and critic use concat(deter, stoch_flat). The loss per key is the **sum** of squared errors over the feature dims against symlog(target), with **no ½**. Each obs key is its own loss term (scale 1), mean-reduced over (B, T).
- **Encoder:** symlog only continuous keys. The tokens are the output of the 3rd Linear → RMSNorm → SiLU block, with no extra projection.
- **Action input to the dynamics** is a / sg(max(1, abs(a))). The replay stores the **unclipped** policy sample; env clipping happens in a wrapper.
- **Stoch is sampled, not the mode,** when acting, training and imagining.
- **Continue target** = 0.997·(1 − is_terminal), a soft label. Truncations (is_last without is_terminal) are **not** zero targets. Never use is_last for this target.
- **Reward target** = raw reward of the step that **entered** x_t (0 at is_first), not squashed.
- Unused rssm.py class defaults (gelu, deter 4096, hidden 2048, classes 32) must not leak in. Use silu and the size-preset values.

### Actor-critic
- **Targets and advantages bootstrap from the ONLINE critic** (slowtar = False overrides the function default True). The slow critic is only a regulariser: two-hot cross-entropy toward its **scalar mean**, weight 1.0, in both the imagination and replay critic losses.
- **λ-return at step t uses r̂, ĉ and v of the NEXT state s_{t+1}**, and r̂_0 is unused. Paper Eq. 5 literally indexes v_t; follow the code. lambda_return's `val` argument is never used.
- **The continuation weight w_t = Π_{i≤t} ĉ_i includes ĉ_0** of the start state. Slice weight[:, :−1] to align it with R_0..R_{H−1}. With contdisc the imagination recursion uses disc = 1. The replay recursion always uses γ = 1 − 1/333 with hard flags.
- **Return normaliser:** update the EMAs of P5 and P95 **first**, then compute S = max(1, hi − lo) for the same batch. lo and hi start at 0 with no debias. Percentiles use linear interpolation over the flattened (B·K·H) = 15360 imagined returns, with no mask and no weights. Divide the advantage by S and do **not** subtract the offset.
- **Reinforce for both action types:** log_prob of sg(sampled action). Continuous: Normal(tanh(μ), 0.9·sigmoid(s + 2) + 0.1), unsquashed samples and log-probs, no tanh-Jacobian term, entropy of the unsquashed Normal.
- **Imagined features are stop-gradiented** (start feat via ac_grads = False, imagined feats always), so the actor and imagination critic never update the world model. The **replay critic (repval) is not stop-gradiented** and trains enc/dyn with scale 0.3. Its mask is ~is_last at the trained state, with no continuation product. Episode boundaries are cut by cont = λ(1 − is_last_{t+1}) and live = γ(1 − is_terminal_{t+1}).
- **Batch-major flattening** of imagination starts (b major, t minor) is required for boot = R_imag[:, 0].reshape(B, K) to line up with the replay rows.
- **Reductions are means, not sums.** Policy and value: mean over H, then over B·K. repval: mean over B·(T − 1). Weighted-out and masked entries still count in the denominator. The final states (imagination index H, replay index T − 1) receive no loss.
- **Normaliser EMA updates happen inside the loss forward pass** and must be skipped in evaluation and report passes.
- **The policy samples stochastically in every mode**; there is no deterministic eval action in the reference.

### Optimizer and loss assembly
- **Optimizer order:** AGC per **tensor** (0.3·max(1e-3, ‖p‖)) on the raw gradients, then RMS (β₂ 0.999, eps 1e-20 **after** the sqrt, bias-corrected), then momentum on the **normalised** update (β₁ 0.9, bias-corrected, its own step counter), then −lr. One optimizer covers all modules; the slow-critic EMA runs after the step.
- **The LR warms up linearly from 0 over 1000 updates**, so the first update has lr = 0 (a no-op on the params, but the moments accumulate). This is code-only; the paper says "no annealing".
- The AGC cap on zero-initialised tensors (gradient norm ≤ 3e-4 while ‖p‖ = 0) does **not** slow them: a constant clip factor cancels in the RMS normalisation.
- Total loss = Σ scale·mean(term). Each vector obs key is its own rec term with weight 1. The loss must be an f32 scalar.

### Replay, replay context and loop
- **Replay windows:** an item at every start index (stride 1), length 65 = 64 trained steps + 1 context step. Windows cross episode and chunk boundaries. Do not restrict them to within-episode windows; the RSSM handles boundaries through is_first masking.
- **Batch annotation:** is_first[:, 0] = True, and is_last = is_last OR (next step is_first), with the last column excluded. The repval mask relies on this.
- **Context alignment:** the carry comes from the latent stored at index 0. The first trained obs is index 1. prevact for obs index t is the action stored at index t − 1 (data[act][:, 0:64]). Step 0 contributes no loss and is not overwritten by the write-back.
- **Stored per step:** obs_t; a_t, the action chosen **after** seeing obs_t (zero if is_last_t); h_t and z_t, the posterior **after** filtering obs_t. After every update, write back the training-pass posteriors (pre-update params) for indices 1..64.
- **Online queue:** per worker, push the item whose insertion happens at step n with n % 65 == 0 (starts 1, 66, 131, …). Train sampling pops it FIFO before uniform sampling; report sampling never pops.
- **The train-ratio clock counts agent transitions over all envs** (not env frames). Updates per agent step = RR/(16·64). Evaluate after every transition. The first eligible call does exactly one update. Training starts once ≥ 1024 items exist (2048 transitions with 16 envs). There is no random prefill.
- **Capacity never binds for DMC proprio:** 250K agent transitions ≪ 5e6 items, so FIFO eviction and the eviction retry never trigger there. A preallocated per-env ring of about 15.7K steps × 16 envs holds the entire run.
- **Memory for stored latents at 12M:** D + 32·C = 2560 floats per step (10 KB in f32). Lossless compact storage is stoch as uint8 class indices [32] (C = 16 < 256) plus deter in bf16 (lossless only when compute is bf16), about 4.1 KB per step, or about 1 GB for 250K steps.
- **Functional, on-device replay design for Ajax** (pure-JAX):
  - Per-env ring buffers [N_env, L_cap] with flags.
  - Valid starts are positions with 64 later steps in the same env stream.
  - Draw a uniform start index, gather 65 steps, and scatter the latent write-back at (env, start + 1 .. start + 64).
  - Emulate the online queue with a per-env pointer to the next unconsumed non-overlapping window (starts 1, 66, …), consumed before uniform draws.
- **Engineering staleness in the reference** (acting params about two driver iterations stale, one-batch prefetch, outs and write-back delayed by one train call, replay RNG fixed at seed 0) is not algorithmic. A synchronous Ajax loop is a faithful simplification; document it as a deviation.
- **Scores:** the reference reports training-episode returns of the stochastic policy. Paper Table 11's "Task mean" and "Task median" rows are swapped. Use mean ≈ 754 and median ≈ 871 at 500K env steps as the DMC-proprio sanity target, and mean ≈ 675 / median ≈ 790 at 250K env steps from the bundled curves.

## Open questions

Each question gives the recommended default in the final table in **bold**. The user's call is needed where marked.

1. **DMC-proprio protocol (user call).** The paper (Table 2) and 2411f7d use size12m, replay ratio 512, action repeat 2, 16 envs and 500K env steps. 2411f7d actually ran 3e5 agent steps = 600K env steps. HEAD (since f8817c4, Dec 2024) uses size1m, ratio 1024, repeat 1 and 1.1M env steps. This choice fixes every network width. Reproducing Table 11 needs the paper / 2411f7d setting. **Recommended: paper (12M / 512 / repeat 2 / 500K).**
2. **LaProp β₂ (user call).** The paper text says 0.99 ("its default parameters"); both code versions use 0.999, which produced the published curves. The LaProp reference's own defaults were not verified here (no literature fetch). **Recommended: 0.999, with 0.99 as a config option.**
3. **Symlog MSE ½ factor.** Paper Eq. 8 has ½; both code versions have none, so the code's reconstruction gradient is 2× the paper formula's. **Recommended: code (no ½).**
4. **Continue head target.** The paper uses a binary c_t with γ applied in the return; both code versions use the soft label 0.997·(1 − terminal) with γ folded in (contdisc = True). The returns are equivalent in expectation. **Recommended: code (contdisc = True).**
5. **Discrete actor unimix.** The paper (p.18, Table 4) and 2411f7d use 1%; HEAD's 'categorical' head drops it. This does not affect DMC, only discrete-action tasks. **Recommended: 1% (paper), as a head option.**
6. **Start-state continuation and reward in imagination.** HEAD uses the predicted ĉ_0 (≈ 0.997) in the weight. 2411f7d used the replay flag 1 − is_terminal (hard, without the 0.997 factor) and the replayed reward. The effect is a constant factor of about 0.997 on all actor-critic weights, plus different handling of terminal start states. The paper is silent. **Recommended: HEAD.**
7. **Vector decoder output outscale.** HEAD uses 1.0; 2411f7d (paper era) effectively used 0.1, a 10× init difference. The paper is silent. **Recommended: HEAD 1.0**, unless strict paper-era fidelity is preferred.
8. **Table 3 12M recurrent units.** The paper prints 1024, which contradicts its own 8d rule; both code versions use 2048. **Recommended: 2048** (treat as a typo).
9. **Replay context in Ajax (user call).** The replay context needs a replay that stores per-step latents (2560 floats per step at 12M) and supports write-back by step id. If Ajax's on-device replay cannot provide this, the deviation must be chosen. The clean fallback is the official replay_context = 0 behaviour, which is a **zero-state start** (is_first forced at index 0; see 5.11), not a reuse of stale state. Burn-in is another option. **Recommended: implement it (it is part of the paper).**
10. **Compute dtype (user call).** The reference uses bf16 compute with f32 params, norms, distributions and losses. Should Ajax replicate bf16 (GPU-oriented) or default to f32 for CPU benchmarks and reproducibility? **Recommended: a dtype option; f32 default for CPU tests, bf16 on GPU.**
11. **Asynchrony.** Should Ajax reproduce the reference's acting-param lag (about two driver iterations), one-batch prefetch, one-call-delayed write-back and early first batch? The paper does not specify these. **Recommended: synchronous, documented as a deviation.**
12. **Replay sampler seed.** The reference fixes it to 0, independent of config.seed. **Recommended: derive it from config.seed (documented deviation).**
13. **What Table 11 scores measure.** The paper does not say whether they are training-episode returns of the stochastic policy (what the default train script logs) or separate evaluation episodes, and the code has no deterministic eval mode. **Recommended: log training-episode returns as the primary metric, plus optional sampled-policy eval episodes.**
14. **Replay windows crossing episode boundaries.** The code does this; the paper is silent. **Recommended: follow the code.**
15. **`elements.when.Ratio` at HEAD** comes from the external `elements` package, which is not available locally. Its semantics are taken from the 2411f7d code it was moved from, so a later change in that package cannot be ruled out. Low risk.
16. **Online queue in a functional replay.** The paper lists it as a component. A per-env "next non-overlapping window" pointer reproduces it. Its effect is small (about 0.2% of rows at RR 512 after the start-up batches). **Recommended: implement it, behind a flag.**
